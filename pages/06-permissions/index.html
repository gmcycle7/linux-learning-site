Chapter 6: Permissions & Ownership

Linux is a multi-user operating system. That means many people (or programs) can use the same machine at the same time. Permissions are the mechanism that controls who can do what to which files. Understanding permissions is essential for keeping your files safe, your system secure, and your scripts running correctly.

In this chapter you will learn how to read permission strings, change them with chmod, transfer ownership with chown and chgrp, control default permissions with umask, and use sudo responsibly.

1. Understanding Permissions

Every file and directory in Linux has three sets of permissions that control access for three categories of users:

  • User (u) — the owner of the file. Usually the person who created it.
  • Group (g) — a set of users who share a common group membership. Every file belongs to exactly one group.
  • Others (o) — everyone else on the system who is not the owner and not in the file's group.

You can see permissions by running ls -l:

$ ls -l
-rwxr-xr--  1 alice  developers  4096  Mar 15 10:30  deploy.sh
drwxr-x---  3 alice  developers  4096  Mar 14 09:15  configs/
-rw-r--r--  1 bob    staff       2048  Mar 13 14:22  readme.txt
lrwxrwxrwx  1 alice  developers    12  Mar 12 08:00  latest -> deploy.sh

Each column in that output means something specific. Here is a detailed breakdown:

-rwxr-xr-- 1 alice developers 4096 Mar 15 10:30 deploy.sh |__________| | |____ |________ |____ |___________| |________| | | | | | | | permissions | owner group size last modified filename | link count

Breaking Down the Permission String

The permission string is 10 characters long. The first character indicates the file type, and the remaining nine characters are three groups of three, each representing read, write, and execute for user, group, and others.

Concept: Anatomy of the Permission String
- r w x r - x r - - | |___| |___| |___| | | | | | user group others | file type: - = regular file d = directory l = symbolic link c = character device b = block device Example: -rwxr-xr-- ^ ^^^ ^^^ ^^^ | ||| ||| ||| | ||| ||| ||+-- others: no execute | ||| ||| |+--- others: no write | ||| ||| +---- others: read | ||| ||+------ group: execute | ||| |+------- group: no write | ||| +-------- group: read | ||+---------- user: execute | |+----------- user: write | +------------ user: read +-------------- regular file
Mental Model: Permissions as a Lock System

Think of every file as a room with three different locks on the door:

  • Read (r) is like a window — you can look inside and see the contents, but you cannot change anything.
  • Write (w) is like a key to the desk — you can modify, add, or delete the contents inside.
  • Execute (x) is like a key to the engine — you can run the file as a program or (for directories) walk into the room.

Three copies of these locks exist: one for the owner, one for the group, and one for everyone else. Each copy can be independently locked or unlocked.

How to Check Permissions

Use ls -l for files in a directory. Use ls -la to include hidden files. Use ls -ld directory_name to see the permissions on the directory itself (not its contents). Use stat filename for even more detail including the numeric (octal) mode.

$ stat deploy.sh
  File: deploy.sh
  Size: 4096       Blocks: 8          IO Block: 4096   regular file
Device: 801h/2049d Inode: 524292      Links: 1
Access: (0754/-rwxr-xr--)  Uid: ( 1000/   alice)   Gid: ( 1001/developers)
Access: 2025-03-15 10:30:00.000000000 +0000
Modify: 2025-03-15 10:30:00.000000000 +0000
Change: 2025-03-15 10:30:00.000000000 +0000

2. rwx — What Read, Write, and Execute Mean

The meaning of r, w, and x is straightforward for regular files, but behaves differently for directories. This is one of the most commonly misunderstood areas of Linux permissions.

Permission On a File On a Directory
r (read) View the contents of the file (e.g., cat, less) List the names of files inside the directory (e.g., ls)
w (write) Modify or overwrite the file's contents Create, rename, or delete files inside the directory
x (execute) Run the file as a program or script Enter the directory (cd) and access files within it
Important: Directory Permissions Are Different

A directory with r but no x lets you see the names of files inside, but you cannot cd into it or read any file contents. A directory with x but no r lets you cd into it and access files by name, but you cannot list the directory contents with ls. You almost always want both r and x together on directories.

Common Permission Combinations Explained

String Meaning for Files Meaning for Directories
r-- Read-only Can list names, but cannot enter or modify
rw- Read and write (but cannot execute) Can list and create/delete files, but cannot enter
r-x Read and execute (common for scripts) Can list and enter, but cannot create/delete files
rwx Full access Full access: list, enter, create, delete
--x Execute only (rare for files) Can enter but cannot list contents
--- No access at all No access at all

3. Numeric (Octal) vs Symbolic Notation

Linux permissions can be expressed in two ways: symbolic (letters like rwx) and numeric/octal (numbers like 755). Both describe exactly the same thing, just in different formats.

Numeric (Octal) System

Each permission has a numeric value:

  • r (read) = 4
  • w (write) = 2
  • x (execute) = 1
  • - (none) = 0

You add these values together for each category (user, group, others). The result is a three-digit number.

Conversion Table

Symbolic Binary Octal Meaning
---0000No permissions
--x0011Execute only
-w-0102Write only
-wx0113Write and execute
r--1004Read only
r-x1015Read and execute
rw-1106Read and write
rwx1117Read, write, and execute

Common Octal Permission Values

Octal Symbolic Typical Use
755rwxr-xr-xExecutable files, directories (owner: full, everyone: read+execute)
644rw-r--r--Regular files (owner: read+write, everyone: read-only)
700rwx------Private executables/directories (owner-only)
600rw-------Private files like SSH keys, config files with passwords
777rwxrwxrwxDANGEROUS: everyone can do everything (almost never correct)
666rw-rw-rw-DANGEROUS: everyone can read and write
750rwxr-x---Group-shared executables/directories
640rw-r-----Group-readable files
444r--r--r--Read-only for everyone
400r--------Owner read-only (e.g., sensitive credentials)
Quick Conversion Trick

To convert a symbolic permission to octal, look at each group of three characters separately and add the values:

rwxr-xr-- rwx = 4+2+1 = 7 r-x = 4+0+1 = 5 r-- = 4+0+0 = 4 Result: 754

To go the other way, break each digit into its components: 6 = 4+2 = rw-, 5 = 4+1 = r-x, 1 = 1 = --x. So 651 = rw-r-x--x.

4. chmod — Change Permissions

The chmod command changes the permissions on a file or directory. You can use either symbolic or numeric notation.

Syntax

$ chmod [options] mode file...

Symbolic Mode

Symbolic mode uses letters and operators to modify permissions selectively:

Who Operator Permission
u = user (owner)
g = group
o = others
a = all (u+g+o)		 + = add
- = remove
= = set exactly		 r = read
w = write
x = execute

Examples: Symbolic Mode

# Add execute permission for the owner
$ chmod u+x script.sh
# Before: -rw-r--r--  ->  After: -rwxr--r--

# Remove write permission from group and others
$ chmod go-w shared.txt
# Before: -rw-rw-rw-  ->  After: -rw-r--r--

# Set group permissions to read-only (exactly)
$ chmod g=r config.yml
# Before: -rw-rwxr--  ->  After: -rw-r--r--

# Add read permission for everyone
$ chmod a+r report.pdf
# Before: -rw-------  ->  After: -rw-r--r--

# Add execute for owner and group
$ chmod ug+x build.sh
# Before: -rw-rw-r--  ->  After: -rwxrwxr--

# Remove all permissions for others
$ chmod o= private.key
# Before: -rw-r--r--  ->  After: -rw-r-----

# Multiple operations in one command (comma-separated)
$ chmod u+x,g=rx,o-w deploy.sh
# Adds execute for user, sets group to r-x, removes write from others

Examples: Numeric Mode

# Standard permissions for a script (owner: all, group: read+exec, others: read+exec)
$ chmod 755 deploy.sh
# Result: -rwxr-xr-x

# Standard permissions for a regular file
$ chmod 644 readme.txt
# Result: -rw-r--r--

# Private file, owner only
$ chmod 600 ~/.ssh/id_rsa
# Result: -rw-------

# Private directory, owner only
$ chmod 700 ~/private/
# Result: drwx------

# Group-shared directory
$ chmod 750 /var/www/project/
# Result: drwxr-x---

Recursive Permissions with -R

# Change permissions recursively for an entire directory tree
$ chmod -R 755 /var/www/html/

# Add group read permission to all files in a directory tree
$ chmod -R g+r project/
Tip: Different Permissions for Files vs Directories

Using chmod -R 755 makes everything executable, which you usually do not want for regular files. A better approach is to set directories and files separately:

# Set all directories to 755
$ find /var/www/html -type d -exec chmod 755 {} \;

# Set all files to 644
$ find /var/www/html -type f -exec chmod 644 {} \;

More chmod Examples

# Make a file read-only for everyone
$ chmod 444 important.conf
# Result: -r--r--r--

# Remove all permissions for group and others
$ chmod go= secrets.env
# Before: -rw-r--r--  ->  After: -rw-------

# Copy permissions from user to group
$ chmod g=u report.txt
# Before: -rwxr--r--  ->  After: -rwxrwxr--

# Give everyone full permissions (almost always wrong!)
$ chmod 777 some_file
# Result: -rwxrwxrwx   (DO NOT DO THIS casually)

# Make script executable by owner only
$ chmod 700 backup.sh
# Result: -rwx------
Do NOT chmod 777 Everything

When you run into a "Permission denied" error, the temptation is to throw chmod 777 at it. Do not do this. Setting 777 means every user on the system can read, write, and execute that file. This is a massive security hole. Instead, figure out why you do not have permission and fix the actual problem.

  • Are you the wrong user? Use sudo or chown.
  • Is the group wrong? Use chgrp.
  • Do you just need execute? Use chmod u+x.
  • Is the parent directory blocking access? Check directory permissions.

chmod 777 is a sign that you do not understand the problem. Take time to understand it instead.

5. chown — Change Owner

The chown command changes the owner and/or the group of a file. You typically need sudo to change file ownership (only root can give away files to other users).

Syntax

$ chown [options] user[:group] file...

Examples

# Change owner to alice
$ sudo chown alice report.txt
# Owner is now alice, group is unchanged

# Change owner to alice and group to developers
$ sudo chown alice:developers project/
# Owner: alice, Group: developers

# Change only the group (note the colon before group name)
$ sudo chown :staff shared.txt
# Owner unchanged, Group: staff

# Recursive: change owner/group for an entire directory tree
$ sudo chown -R www-data:www-data /var/www/html/
# All files and subdirectories now owned by www-data

# Change owner to bob, keep the current group
$ sudo chown bob server.conf

# Use numeric UID and GID
$ sudo chown 1000:1001 data.csv

# Change ownership of a symbolic link itself (not the target)
$ sudo chown -h alice symlink_file

# Change owner and group from a reference file
$ sudo chown --reference=template.txt newfile.txt
# newfile.txt now has the same owner and group as template.txt
Why chown requires sudo

Ordinary users cannot give their files to someone else — this is a security measure. If any user could change ownership, they could create malicious files and make it look like root created them. Only the superuser (root) can change file ownership. You can, however, change a file's group to any group you belong to.

Practical Use Cases for chown

# Fix web server permissions after deploying code
$ sudo chown -R www-data:www-data /var/www/mysite/

# Take ownership of a file someone shared with you
$ sudo chown $(whoami) downloaded_tool

# Set up a shared directory for a team
$ sudo mkdir /opt/teamproject
$ sudo chown root:devteam /opt/teamproject
$ sudo chmod 775 /opt/teamproject

6. chgrp — Change Group

The chgrp command changes only the group of a file. It is essentially a convenience shortcut — chown :group file does the same thing. You can change a file's group to any group you belong to without sudo.

Syntax

$ chgrp [options] group file...

Examples

# Change group to developers
$ chgrp developers project.py
# Group is now developers

# Recursive group change
$ chgrp -R marketing /shared/campaigns/
# All files and subdirectories now in marketing group

# Change group using a reference file
$ chgrp --reference=template.conf newapp.conf
# newapp.conf now has the same group as template.conf

# Change group on multiple files at once
$ chgrp staff report1.txt report2.txt report3.txt

# Verbose output to see what changed
$ chgrp -v webteam index.html
changed group of 'index.html' from staff to webteam
Tip: Check Your Groups

To see which groups you belong to, run groups or id. You can only chgrp to a group you are a member of (unless you use sudo).

$ groups
alice sudo developers docker

$ id
uid=1000(alice) gid=1000(alice) groups=1000(alice),27(sudo),1001(developers),998(docker)

7. umask — Default Permission Mask

When you create a new file or directory, it does not get 777 permissions by default. Linux applies a umask (user file-creation mask) that removes certain permissions automatically. The umask is subtractive — it defines which permissions to take away from the maximum.

How umask Works

The maximum default permissions are:

  • Files: 666 (rw-rw-rw-) — files are never created executable by default
  • Directories: 777 (rwxrwxrwx)

The umask is subtracted from these maximums:

Concept: umask Calculation
umask = 022 For a new FILE: Base permissions: 666 (rw-rw-rw-) Subtract umask: - 022 ───────────────────────── Result: 644 (rw-r--r--) For a new DIRECTORY: Base permissions: 777 (rwxrwxrwx) Subtract umask: - 022 ───────────────────────── Result: 755 (rwxr-xr-x)

Note: The subtraction is not standard arithmetic — it is a bitwise AND NOT operation. In practice, for the common umask values (022, 077, 002), simple subtraction gives the same result. But technically umask 033 applied to a file with base 666 gives 644, not 633, because the execute bit was never set for files.

Checking and Setting umask

# Check current umask
$ umask
0022

# Check umask in symbolic format
$ umask -S
u=rwx,g=rx,o=rx

# Set umask to 022 (the most common default)
$ umask 022

# Set a restrictive umask (only owner gets permissions)
$ umask 077

Common umask Values

umask New File New Directory Use Case
022 644 (rw-r--r--) 755 (rwxr-xr-x) Most common default. Others can read but not write.
002 664 (rw-rw-r--) 775 (rwxrwxr-x) Group-friendly. Group members can write too.
077 600 (rw-------) 700 (rwx------) Maximum privacy. Only the owner has access.
027 640 (rw-r-----) 750 (rwxr-x---) Group can read, others get nothing.

Testing umask

# Set a restrictive umask
$ umask 077

# Create a file and a directory
$ touch secret.txt
$ mkdir secret_dir

# Check the results
$ ls -l secret.txt
-rw------- 1 alice alice 0 Mar 15 11:00 secret.txt

$ ls -ld secret_dir
drwx------ 2 alice alice 4096 Mar 15 11:00 secret_dir
Making umask Permanent

The umask command only affects the current shell session. To make it permanent, add the umask command to your shell profile file (~/.bashrc, ~/.bash_profile, or ~/.profile). System-wide defaults are typically set in /etc/profile or /etc/login.defs.

8. The Executable Bit

In Linux, a file does not become a program just because it has a .sh extension. Files are only executable if the execute bit is set in their permissions. This is fundamentally different from Windows, where the file extension (like .exe) determines whether a file is a program.

Making a Script Executable

# Create a simple script
$ cat hello.sh
#!/bin/bash
echo "Hello, world!"

# Try to run it — permission denied!
$ ./hello.sh
bash: ./hello.sh: Permission denied

# Check permissions — no execute bit
$ ls -l hello.sh
-rw-r--r-- 1 alice alice 33 Mar 15 12:00 hello.sh

# Add the execute bit
$ chmod +x hello.sh

# Check again — execute bit is set
$ ls -l hello.sh
-rwxr-xr-x 1 alice alice 33 Mar 15 12:00 hello.sh

# Now it runs!
$ ./hello.sh
Hello, world!

The Shebang Line

The first line of an executable script should be a shebang (also called hashbang): #! followed by the path to the interpreter. This tells the system which program to use to run the script.

# Bash script
#!/bin/bash

# Python script
#!/usr/bin/env python3

# Perl script
#!/usr/bin/perl

# Node.js script
#!/usr/bin/env node
Tip: Use env for Portability

Instead of hardcoding the interpreter path (like #!/usr/bin/python3), use #!/usr/bin/env python3. The env command searches your PATH for the interpreter, making the script portable across systems where the interpreter may be installed in different locations.

Workaround: Running Without Execute Permission

Even without the execute bit, you can still run a script by calling the interpreter directly:

# These work even without the execute bit
$ bash hello.sh
Hello, world!

$ python3 myscript.py
$ node app.js

However, setting the execute bit is the proper way to make a script runnable with ./script.sh syntax.

9. sudo — Superuser Do

sudo allows a permitted user to run a command as the superuser (root) or another user. It is how you perform administrative tasks without logging in as root.

Basic Usage

# Install a package (requires root privileges)
$ sudo apt install nginx
[sudo] password for alice:

# Edit a system configuration file
$ sudo nano /etc/hosts

# Restart a service
$ sudo systemctl restart nginx

# View a file owned by root
$ sudo cat /etc/shadow

sudo vs su

Command What It Does When to Use
sudo command Runs a single command as root Most of the time — safer, logged, temporary
sudo -i Opens an interactive root shell (login shell) When you need to run many root commands
sudo -s Opens a root shell (non-login) Quick root shell with your current environment
su - Switches to root user (needs root's password) Rarely — requires knowing root password
su - bob Switches to user bob (needs bob's password) Testing as another user
sudo -u bob command Runs a command as user bob Running a command as a specific user

The sudoers File

Who can use sudo is controlled by the /etc/sudoers file. Never edit this file directly — always use visudo, which checks for syntax errors before saving.

# Open the sudoers file safely
$ sudo visudo

# Common entries in /etc/sudoers:
root    ALL=(ALL:ALL) ALL           # root can do everything
%sudo   ALL=(ALL:ALL) ALL           # members of sudo group can do everything
alice   ALL=(ALL) NOPASSWD: ALL     # alice can sudo without a password (be careful!)

Useful sudo Tricks

# Repeat the last command with sudo (when you forgot to add it)
$ apt update
E: Could not open lock file - open (13: Permission denied)
$ sudo !!
sudo apt update
[sudo] password for alice:

# Check if you can use sudo
$ sudo -v

# See what commands you are allowed to run
$ sudo -l
User alice may run the following commands:
    (ALL : ALL) ALL

# Edit a file with your normal editor, saving as root
$ sudoedit /etc/nginx/nginx.conf

# Write to a file as root (common redirect trick)
$ echo "new line" | sudo tee -a /etc/hosts
Warning: sudo Is Not the Answer to Every "Permission Denied"

When you see "Permission denied," your first instinct should NOT be to add sudo. Ask yourself these questions first:

  • Am I in the right directory? Maybe you are trying to access a path that does not exist.
  • Do I own this file? Maybe you should use chown to take ownership instead.
  • Is the execute bit missing? Maybe you just need chmod +x.
  • Am I in the right group? Maybe adding yourself to the correct group is the proper fix.
  • Is this a file I should have access to? If not, there is probably a good reason it is restricted.

Using sudo when you should not can create files owned by root in your home directory, break application configurations, or worse — cause security problems. sudo is powerful. Use it intentionally, not reflexively.

DANGER: Commands You Should Never Run Carelessly with sudo

These commands can destroy your system. Understand them before you type them:

  • sudo rm -rf / — Deletes your entire filesystem. Unrecoverable.
  • sudo chmod -R 777 / — Removes all permission security from your entire system.
  • sudo chown -R user:user / — Changes ownership of system files, breaking everything.
  • sudo dd if=/dev/zero of=/dev/sda — Overwrites your hard drive with zeros.

Always double-check your commands before pressing Enter, especially when using sudo with recursive flags (-R, -r) or destructive commands (rm, dd, mkfs).

Wrong vs Correct Permission Examples

Wrong
# "I got Permission Denied, so I'll just..."
$ sudo chmod 777 /var/www/html/
$ sudo chmod -R 777 ~/project/

This opens your files to every user on the system. It is lazy and insecure.

Correct
# Fix the actual ownership problem
$ sudo chown -R www-data:www-data /var/www/html/
$ sudo chmod -R 755 /var/www/html/

Set the correct owner and give appropriate permissions (755 for dirs, 644 for files).

Wrong
# SSH key with too-open permissions
$ chmod 644 ~/.ssh/id_rsa

SSH will refuse to use a private key that others can read. You will get: "Permissions 0644 are too open."

Correct
# SSH keys must be private
$ chmod 600 ~/.ssh/id_rsa
$ chmod 644 ~/.ssh/id_rsa.pub

Private key: 600 (owner read/write). Public key: 644 (everyone can read).

Wrong
# Running everything as root
$ sudo pip install flask
$ sudo npm install -g express

Installing packages with sudo can break system Python/Node and create permission conflicts.

Correct
# Use virtual environments / user installs
$ python3 -m venv venv
$ pip install flask
$ npm install express

Use virtual environments for Python and local installs for Node. No sudo needed.

Quizzes

Quiz 1: What does the permission string -rwxr-x--- mean in octal notation, and who can execute the file?
Correct answer: b) 750 — The owner and group members can execute.
Breakdown: rwx = 4+2+1 = 7 (user), r-x = 4+0+1 = 5 (group), --- = 0 (others). The owner has full permissions (rwx). Group members have read and execute (r-x). Others have no access. Both the owner and group members can execute the file.
Quiz 2: You run umask 027 and then create a new file with touch notes.txt. What permissions will the file have?
Correct answer: a) -rw-r----- (640)
Files start with a base of 666. Subtract the umask 027: 666 - 027 = 640. That is rw-r-----. The owner can read and write. The group can only read. Others have no access. Remember, files never get the execute bit from default creation — only directories do.

Key Takeaways
  • Every file has an owner, a group, and permissions for user/group/others.
  • r=4, w=2, x=1. Add them up for octal notation.
  • Use chmod to change permissions, chown to change ownership.
  • umask controls the default permissions for new files.
  • Use sudo intentionally, not as a reflex for every permission error.
  • Never chmod 777 unless you truly understand and accept the consequences.
  • SSH keys require strict permissions: 600 for private, 644 for public.
