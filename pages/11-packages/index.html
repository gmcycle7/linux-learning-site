Chapter 11: Package Management

Every Linux distribution needs a way to install, update, and remove software. That is the job of a package manager. This chapter covers all the major package managers you will encounter across different Linux distributions.

1. What is a Package Manager?

Mental Model: Packages, Repositories, and Dependencies

Think of a package manager like an app store for your terminal.

  • Package — A bundle containing a program's files, metadata, and instructions for where to put them. Similar to an installer on Windows or a .dmg on macOS.
  • Repository (repo) — A remote server that stores thousands of packages. Your package manager downloads from these repos. Think of it as the shelves in the app store.
  • Dependency — A package that another package requires to work. For example, a text editor might depend on a graphics library. The package manager handles these automatically.

When you run apt install firefox, the package manager checks the repository, finds Firefox and all its dependencies, downloads them, and installs everything in the right locations.

Different distributions use different package managers:

Distribution FamilyHigh-Level ToolLow-Level ToolPackage Format
Debian, Ubuntu, Mintapt / apt-getdpkg.deb
RHEL, CentOS 7yumrpm.rpm
Fedora, RHEL 8+, CentOS 8+dnfrpm.rpm
Arch, Manjaropacmanpacman.pkg.tar.zst

High-level tools resolve dependencies automatically and download from repos. Low-level tools install individual package files but do not handle dependencies on their own.

2. apt (Debian / Ubuntu)

apt is the modern, user-friendly command-line tool for Debian-based systems. It combines the most commonly used features of apt-get and apt-cache into one command with cleaner output and progress bars.

Always update before installing

Run sudo apt update before installing anything. This refreshes your local list of available packages so you get the latest versions.

Update the package list

$ sudo apt update
Hit:1 http://archive.ubuntu.com/ubuntu jammy InRelease
Get:2 http://security.ubuntu.com/ubuntu jammy-security InRelease [110 kB]
Reading package lists... Done
Building dependency tree... Done
15 packages can be upgraded.

Upgrade installed packages

$ sudo apt upgrade                   # upgrade all packages
$ sudo apt full-upgrade               # upgrade, removing obsolete packages if needed

Install a package

$ sudo apt install nginx              # install nginx web server
$ sudo apt install vim curl git       # install multiple packages at once
$ sudo apt install -y nodejs          # skip confirmation prompt with -y

Remove a package

$ sudo apt remove nginx               # remove package, keep config files
$ sudo apt purge nginx                # remove package AND its config files
$ sudo apt autoremove                 # remove unused dependencies

Search and get information

$ apt search "web server"             # search for packages by keyword
$ apt show nginx                      # detailed info about a package
$ apt list --installed                # list all installed packages
$ apt list --upgradable               # list packages with updates available

Practical examples

# Full update workflow
$ sudo apt update && sudo apt upgrade -y

# Install a package and check it was installed
$ sudo apt install -y tree
$ apt list --installed | grep tree
tree/jammy,now 2.0.2-1 amd64 [installed]

# Clean up cached package files to free disk space
$ sudo apt clean                      # remove all cached .deb files
$ sudo apt autoclean                  # remove only outdated cached .deb files

3. apt-get (Legacy Tool)

apt-get is the older command that apt was built to replace for interactive use. It still works and you will see it in many tutorials, scripts, and Dockerfiles.

When to use which?

Featureaptapt-get
Progress barYesNo
Color outputYesNo
Combines apt-get + apt-cacheYesNo (separate commands)
Stable CLI for scriptsNo (output may change)Yes (stable, predictable)
Use in Dockerfiles / scriptsNot recommendedRecommended
Interactive terminal useRecommendedWorks fine

Common apt-get commands

$ sudo apt-get update                 # refresh package list
$ sudo apt-get upgrade                # upgrade all packages
$ sudo apt-get dist-upgrade           # upgrade with dependency changes
$ sudo apt-get install vim             # install a package
$ sudo apt-get remove vim              # remove a package
$ sudo apt-get purge vim               # remove package + config
$ sudo apt-get autoremove              # clean unused dependencies

# apt-cache is the companion for searches
$ apt-cache search "text editor"      # search packages
$ apt-cache show vim                   # show package details
$ apt-cache policy vim                 # show version and repo info
Rule of thumb

Use apt when typing commands yourself. Use apt-get inside shell scripts, cron jobs, and Dockerfiles where stable output matters.

4. dpkg (Debian Package Tool)

dpkg is the low-level tool that works directly with .deb files. It does not resolve dependencies. Use it when you have downloaded a .deb file manually (for example, Google Chrome or VS Code).

Install a local .deb file

$ sudo dpkg -i google-chrome-stable_current_amd64.deb
# If dependencies are missing, fix them with:
$ sudo apt install -f               # -f = fix broken dependencies

Remove a package

$ sudo dpkg -r google-chrome-stable  # remove, keep config files
$ sudo dpkg -P google-chrome-stable  # purge (remove everything)

Query installed packages

$ dpkg -l                            # list ALL installed packages
$ dpkg -l | grep nginx               # check if nginx is installed
$ dpkg -L nginx                      # list all files installed by nginx
$ dpkg -s nginx                      # show status and details of nginx
$ dpkg -S /usr/bin/vim               # which package owns this file?

Practical examples

# Download and install VS Code
$ wget -O vscode.deb "https://code.visualstudio.com/sha/download?build=stable&os=linux-deb-x64"
$ sudo dpkg -i vscode.deb
$ sudo apt install -f                # fix any missing dependencies

# Check what version of a package is installed
$ dpkg -s bash | grep Version
Version: 5.1-6ubuntu1

# Count how many packages are installed
$ dpkg -l | grep "^ii" | wc -l
534

5. yum (RHEL / CentOS 7)

yum (Yellowdog Updater, Modified) is the traditional package manager for Red Hat-based systems. It is the default on RHEL 7 and CentOS 7.

Update and upgrade

$ sudo yum check-update              # check for available updates
$ sudo yum update                    # update all packages
$ sudo yum update nginx               # update a specific package

Install and remove

$ sudo yum install httpd              # install Apache web server
$ sudo yum install -y vim curl        # install multiple, skip prompt
$ sudo yum remove httpd               # remove a package
$ sudo yum autoremove                 # remove unused dependencies

Search and info

$ yum search "web server"             # search for packages
$ yum info httpd                      # detailed package information
$ yum list installed                  # list all installed packages
$ yum list available                  # list all available packages

Practical examples

# Install a package group (e.g., Development Tools)
$ sudo yum groupinstall "Development Tools"

# See which package provides a file
$ yum provides /usr/bin/dig
bind-utils-9.11.4-26.P2.el7.x86_64 : Utilities for querying DNS name servers

# View yum history (see past transactions)
$ sudo yum history
$ sudo yum history info 15            # details of transaction #15

# Clean cached data
$ sudo yum clean all

6. dnf (Fedora / RHEL 8+)

dnf (Dandified Yum) is the successor to yum. It is faster, uses less memory, handles dependencies better, and is the default on Fedora and RHEL/CentOS 8 and later. The command syntax is almost identical to yum.

dnf replaces yum

On RHEL 8+ and Fedora, yum is actually a symlink to dnf. Running yum install really runs dnf install behind the scenes. However, you should use dnf directly on these systems.

Core commands

$ sudo dnf check-update              # check for updates
$ sudo dnf update                    # update all packages (same as upgrade)
$ sudo dnf upgrade                   # same as update
$ sudo dnf install nginx              # install a package
$ sudo dnf install -y vim curl git    # install multiple, skip prompt
$ sudo dnf remove nginx               # remove a package
$ sudo dnf autoremove                 # remove unneeded dependencies

Search, info, and listing

$ dnf search "text editor"            # search for packages
$ dnf info nginx                      # show package details
$ dnf list installed                  # list installed packages
$ dnf list available                  # list available packages
$ dnf provides /usr/bin/dig           # which package provides this file?

Groups and history

$ dnf group list                      # list available package groups
$ sudo dnf group install "Development Tools"
$ dnf history                         # view transaction history
$ sudo dnf history undo 12            # undo transaction #12
$ sudo dnf clean all                  # clean cached data

7. rpm (RPM Package Manager)

rpm is the low-level tool for .rpm files on Red Hat-based systems. Like dpkg for Debian, it does not resolve dependencies. Use it to install locally downloaded .rpm files or to query installed packages.

Install, upgrade, and remove

$ sudo rpm -ivh package.rpm           # install (-i=install, -v=verbose, -h=progress)
$ sudo rpm -Uvh package.rpm           # upgrade (or install if not present)
$ sudo rpm -e package-name            # erase (remove) a package

Query packages

$ rpm -qa                             # list ALL installed packages
$ rpm -qa | grep nginx                # check if nginx is installed
$ rpm -qi nginx                       # detailed info about an installed package
$ rpm -ql nginx                       # list all files from an installed package
$ rpm -qf /usr/bin/vim                # which package owns this file?

Query an .rpm file (before installing)

$ rpm -qip package.rpm                # show info from the .rpm file
$ rpm -qlp package.rpm                # list files the .rpm would install
$ rpm -qRp package.rpm                # list dependencies of the .rpm file

Verify installed packages

$ rpm -V nginx                        # verify integrity of installed files
$ rpm -Va                             # verify ALL installed packages (slow)

8. pacman (Arch Linux)

pacman is the package manager for Arch Linux and its derivatives (Manjaro, EndeavourOS). It uses a different flag style than the other package managers.

Sync (install) and update

$ sudo pacman -Syu                    # sync repos + full system upgrade (do this first!)
$ sudo pacman -Sy                     # sync repos only (refresh package database)
$ sudo pacman -S nginx                # install a package
$ sudo pacman -S --noconfirm vim      # install without confirmation
$ sudo pacman -S vim curl git         # install multiple packages

Remove packages

$ sudo pacman -R nginx                # remove a package
$ sudo pacman -Rs nginx               # remove + unneeded dependencies
$ sudo pacman -Rns nginx              # remove + dependencies + config files

Search and query

$ pacman -Ss "web server"             # search remote repos
$ pacman -Si nginx                    # info about a remote package
$ pacman -Qs nginx                    # search installed packages
$ pacman -Qi nginx                    # info about an installed package
$ pacman -Ql nginx                    # list files installed by a package
$ pacman -Qo /usr/bin/vim             # which package owns this file?

Maintenance

$ pacman -Qdt                         # list orphaned packages (unneeded deps)
$ sudo pacman -Rns $(pacman -Qdtq)    # remove all orphaned packages
$ sudo pacman -Sc                     # clean old cached packages
$ sudo pacman -Scc                    # clean ALL cached packages
Pacman flag cheat sheet

-S = Sync (install/update from repos), -R = Remove, -Q = Query (installed packages), -U = Upgrade (from local file). Lowercase letters after modify the action: s=search, i=info, l=list, u=update, y=refresh db.

Low-Level vs High-Level Package Tools

Mental Model: Two Layers of Package Management

Think of package management as having two layers:

  • Low-level tools (dpkg, rpm) — work with individual package files. They install and remove single packages but do NOT download from the internet or handle dependencies.
  • High-level tools (apt, yum, dnf, pacman) — work with repositories. They resolve dependencies, download packages, and call the low-level tool to do the actual installation.

When you run apt install nginx, apt figures out the dependencies, downloads all needed .deb files, and then calls dpkg to install each one.

ScenarioUse High-LevelUse Low-Level
Install software from reposYes (apt install)No
Install a downloaded .deb/.rpm filePossible (apt install ./file.deb)Yes (dpkg -i)
Query which package owns a filePossibleYes (dpkg -S, rpm -qf)
List all files in an installed packageNoYes (dpkg -L, rpm -ql)
Upgrade the entire systemYes (apt upgrade)No

Common Package Management Workflows

Full system update (Debian/Ubuntu)

$ sudo apt update                    # refresh package list
$ sudo apt upgrade -y                # upgrade all packages
$ sudo apt autoremove -y              # remove orphaned dependencies
$ sudo apt clean                      # free disk space from cache

Full system update (Arch)

$ sudo pacman -Syu                    # sync + full upgrade in one command
$ sudo pacman -Rns $(pacman -Qdtq)    # remove orphans (if any)
$ sudo pacman -Sc                     # clean cache

Find what package provides a command

# Debian/Ubuntu
$ dpkg -S $(which dig)
dnsutils: /usr/bin/dig

# Red Hat / Fedora
$ dnf provides /usr/bin/dig
bind-utils-9.16.23-1.el9.x86_64 : Utilities for querying DNS

# Arch
$ pacman -Qo /usr/bin/dig
/usr/bin/dig is owned by bind 9.18.20-1

Downgrade a package (Debian/Ubuntu)

# List available versions
$ apt list -a nginx
nginx/jammy-updates 1.18.0-6ubuntu14.4 amd64
nginx/jammy 1.18.0-6ubuntu14 amd64

# Install a specific version
$ sudo apt install nginx=1.18.0-6ubuntu14

How to Safely Install and Remove Packages

Before installing

  1. Update your package list first. On Debian/Ubuntu: sudo apt update. On Arch: sudo pacman -Sy.
  2. Search before installing to make sure you have the right package name: apt search nginx.
  3. Check package details with apt show or dnf info to confirm it is what you expect.
  4. Review what will be installed. The package manager shows you a list of packages and dependencies before confirming. Read it.

Before removing

  1. Check dependencies. Removing a package may also remove packages that depend on it. Read the confirmation carefully.
  2. Use remove before purge. Start with remove to keep config files. Only use purge if you want a clean slate.
  3. Clean up afterward. Run autoremove to clear orphaned dependencies.
Warning: Do not mix package managers

Never install a .rpm file on a Debian system or a .deb file on a Red Hat system. Do not try to use apt on Arch or pacman on Ubuntu. Each distribution has its own package format, and mixing them will break your system. If you need software that is not in your distro's repos, look for a Snap, Flatpak, AppImage, or build from source.

Caution: Be careful with sudo and package removal

Running sudo apt remove on critical system packages (like systemd, libc6, or bash) can make your system unbootable. Always read what the package manager says it will remove before typing y.

Knowledge Check

1. You downloaded a .deb file from a website. Which command installs it?
Answer: b) sudo dpkg -i file.deb installs a local .deb file. After installing, run sudo apt install -f to fix any missing dependencies. Note that apt install ./file.deb (with the path) also works on newer systems and handles dependencies automatically.
2. What is the equivalent of apt install nginx on Arch Linux?
Answer: c) sudo pacman -S nginx installs a package from the repos. -S stands for Sync. -R removes, -Ss searches, and -Q queries installed packages.

Troubleshooting Package Issues

Package managers usually work smoothly, but sometimes things go wrong. Here are the most common problems and how to fix them.

"dpkg was interrupted" Error

This happens when a previous dpkg or apt operation was interrupted (e.g., you pressed Ctrl+C during an install, or the system lost power).

$ sudo apt install vim
E: dpkg was interrupted, you must manually run 'sudo dpkg --configure -a' to correct the problem.
# Fix: reconfigure any partially installed packages
$ sudo dpkg --configure -a
# Then try your command again
$ sudo apt install vim
If --configure -a does not work

In rare cases you may need to force-remove the problematic package first:

$ sudo dpkg --remove --force-remove-reinstreq package-name
$ sudo apt install -f

Broken Dependencies

This typically happens after installing a .deb file manually with dpkg -i when its dependencies are not installed.

$ sudo dpkg -i some-app.deb
dpkg: dependency problems prevent configuration of some-app:
 some-app depends on libfoo (>= 2.0); however:
  Package libfoo is not installed.

# Fix: let apt resolve the missing dependencies
$ sudo apt --fix-broken install
# or equivalently:
$ sudo apt install -f
# apt will download and install the missing dependencies automatically

Locked apt (Another Process Using apt)

Only one package manager process can run at a time. If you see a lock error, another process (perhaps an automatic update) is already running.

$ sudo apt update
E: Could not get lock /var/lib/dpkg/lock-frontend - open (11: Resource temporarily unavailable)
E: Unable to acquire the dpkg frontend lock (/var/lib/dpkg/lock-frontend), is another process using it?
# Step 1: Check if another apt/dpkg process is running
$ ps aux | grep -E 'apt|dpkg'
root      1234  ...  apt upgrade -y
root      1235  ...  dpkg --configure -a

# Step 2: Wait for it to finish. If it's a legitimate process, be patient.
# Unattended upgrades often run in the background after boot.

# Step 3: If the process is truly stuck or crashed, kill it:
$ sudo kill 1234
# Then clean up the lock files:
$ sudo rm /var/lib/dpkg/lock-frontend
$ sudo rm /var/lib/apt/lists/lock
$ sudo dpkg --configure -a
Do NOT blindly delete lock files

Only remove lock files if you are certain the other process is dead. Killing an active dpkg process can leave your system in a broken state. Always check with ps first, and try waiting before resorting to killing processes.

Package Held Back

Sometimes apt upgrade reports packages are "kept back." This means the upgrade would require installing new packages or removing existing ones, which apt upgrade refuses to do.

$ sudo apt upgrade
The following packages have been kept back:
  linux-generic linux-headers-generic linux-image-generic

# Fix option 1: Use full-upgrade (allows installing/removing packages)
$ sudo apt full-upgrade

# Fix option 2: Install the held package explicitly
$ sudo apt install linux-generic

A package can also be manually held to prevent upgrades:

# Hold a package (prevent it from being upgraded)
$ sudo apt-mark hold nginx
nginx set on hold.

# See which packages are held
$ apt-mark showhold
nginx

# Unhold a package (allow upgrades again)
$ sudo apt-mark unhold nginx
Canceled hold on nginx.

Removing PPAs

PPAs (Personal Package Archives) are third-party repositories on Ubuntu. If a PPA causes problems or is no longer maintained, you should remove it.

# List all PPAs currently configured
$ grep -r "^deb " /etc/apt/sources.list.d/
/etc/apt/sources.list.d/some-ppa.list:deb https://ppa.launchpadcontent.net/user/ppa/ubuntu jammy main

# Remove a PPA
$ sudo add-apt-repository --remove ppa:user/ppa-name
$ sudo apt update

# Or manually delete the source file
$ sudo rm /etc/apt/sources.list.d/some-ppa.list
$ sudo apt update

# To also downgrade packages from the removed PPA to official versions:
$ sudo apt install ppa-purge
$ sudo ppa-purge ppa:user/ppa-name

Snap and Flatpak

Traditional package managers (apt, dnf, pacman) install software that integrates deeply with your system. Snap and Flatpak take a different approach: they bundle applications with their dependencies into self-contained packages that run in a sandbox. This means fewer dependency conflicts and easier cross-distribution compatibility.

What are Snap and Flatpak?
  • Snap — Developed by Canonical (the company behind Ubuntu). Snaps are self-contained packages that include the application and all its dependencies. They auto-update in the background. Snap is pre-installed on Ubuntu.
  • Flatpak — A community-driven project supported by Red Hat and others. Flatpaks are sandboxed applications that run isolated from the rest of the system. Flatpak uses Flathub as its primary app store.

Both solve the same problem: "I want to install this app on any Linux distro without worrying about dependencies." They just do it differently.

Snap Commands

# Install a snap
$ sudo snap install vlc
vlc 3.0.20 from VideoLAN installed

# Remove a snap
$ sudo snap remove vlc

# List installed snaps
$ snap list
Name     Version    Rev    Tracking       Publisher   Notes
core22   20240111   1122   latest/stable  canonical   base
firefox  124.0      3771   latest/stable  mozilla     -
vlc      3.0.20     3721   latest/stable  videolan    -

# Search for a snap
$ snap find "media player"

# Show info about a snap
$ snap info vlc

Flatpak Commands

# Install Flatpak (if not already installed)
$ sudo apt install flatpak
# Add the Flathub repository (main source of Flatpak apps)
$ flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo

# Install a Flatpak app
$ flatpak install flathub org.videolan.VLC

# Remove a Flatpak app
$ flatpak uninstall org.videolan.VLC

# List installed Flatpak apps
$ flatpak list
Name         Application ID               Version   Branch   Origin
VLC          org.videolan.VLC             3.0.20    stable   flathub
GIMP         org.gimp.GIMP               2.10.36   stable   flathub

# Search for a Flatpak app
$ flatpak search "media player"

# Run a Flatpak app
$ flatpak run org.videolan.VLC

Snap vs Flatpak vs apt Comparison

Feature apt (traditional) Snap Flatpak
Managed by Distribution maintainers Canonical (Ubuntu) Community / Red Hat
Sandboxed No Yes (AppArmor) Yes (Bubblewrap)
Auto-updates Manual or via unattended-upgrades Yes (automatic) Manual (or via GNOME Software)
Startup speed Fast (native) Slower (decompresses at launch) Moderate
Disk usage Small (shared libraries) Larger (bundled dependencies) Larger (bundled dependencies)
App store Distribution repos Snap Store Flathub
CLI and server apps Yes Yes Desktop apps only (mainly)
Cross-distro No (Debian-family only) Yes (any distro with snapd) Yes (any distro with Flatpak)
Best for System packages, servers, scripts Ubuntu desktop apps, CLI tools Desktop apps across any distro
When to use which?
  • Use apt/dnf/pacman for system tools, libraries, server software, and anything in your distro's repos.
  • Use Snap when you are on Ubuntu and the app is available as a snap, especially for desktop apps.
  • Use Flatpak for desktop apps when you want the latest version or the app is not in your distro's repos. Flathub often has newer versions than distribution repos.

How to Find the Right Package

One of the most common challenges is figuring out which package to install. You know the command you want to run or the functionality you need, but not the package name. Here are several strategies.

Strategy 1: apt search

Search for packages by keyword in their name or description:

$ apt search "image editor"
gimp/jammy 2.10.30-1build1 amd64
  GNU Image Manipulation Program

kolourpaint/jammy 4:21.12.3-0ubuntu1 amd64
  simple image editor and drawing application

$ apt search json | head -20
# Search for anything related to JSON

$ apt search --names-only python3
# Search only in package names, not descriptions

Strategy 2: apt-cache

apt-cache provides more detailed search and query capabilities:

# Search with keywords
$ apt-cache search "pdf viewer"

# Show detailed info about a package
$ apt-cache show nginx
Package: nginx
Version: 1.18.0-6ubuntu14.4
Description-en: small, powerful, scalable web/proxy server
 ...

# Show which repo provides a package and what version
$ apt-cache policy nginx
nginx:
  Installed: 1.18.0-6ubuntu14.4
  Candidate: 1.18.0-6ubuntu14.4
  Version table:
 *** 1.18.0-6ubuntu14.4 500
        500 http://archive.ubuntu.com/ubuntu jammy-updates/main amd64 Packages

# Show a package's dependencies
$ apt-cache depends nginx

# Show which packages depend on a given package
$ apt-cache rdepends libssl3

Strategy 3: apt-file (Find Which Package Provides a File)

apt-file searches all packages (even uninstalled ones) for a specific file. This is extremely useful when you need a command or library that is not installed.

# Install and set up apt-file
$ sudo apt install apt-file
$ sudo apt-file update             # download the file database (takes a moment)

# Find which package provides a specific file
$ apt-file search /usr/bin/convert
imagemagick-6.q16: /usr/bin/convert

# Find which package provides a command you want to run
$ apt-file search bin/dig
bind9-dnsutils: /usr/bin/dig

# Search for a header file (useful for compiling software)
$ apt-file search openssl/ssl.h
libssl-dev: /usr/include/openssl/ssl.h

# List all files that a package would install
$ apt-file list nginx | head -10

Strategy 4: "command-not-found" Hints

On Ubuntu, if you type a command that is not installed, the system often tells you which package provides it:

$ dig example.com
Command 'dig' not found, but can be installed with:
  sudo apt install bind9-dnsutils

$ ifconfig
Command 'ifconfig' not found, but can be installed with:
  sudo apt install net-tools

Strategy 5: dpkg -S (Find Which Installed Package Owns a File)

If the file already exists on your system, use dpkg -S to find which package installed it:

$ dpkg -S /usr/bin/vim
vim: /usr/bin/vim

$ dpkg -S $(which python3)
python3-minimal: /usr/bin/python3

# Find all packages that installed files in a directory
$ dpkg -S /etc/nginx/
nginx-common: /etc/nginx
nginx-common: /etc/nginx/nginx.conf
nginx-common: /etc/nginx/mime.types

Summary: Finding the Right Package

Situation Tool Example
I know a keyword about the software apt search apt search "web server"
I want to run a command but it is not installed apt-file search apt-file search bin/dig
I have a file and want to know which package owns it dpkg -S dpkg -S /usr/bin/wget
I want version and repository details apt-cache policy apt-cache policy nginx
I need a header file or library for compiling apt-file search apt-file search openssl/ssl.h
I just type the command and hope command-not-found Type the command; Ubuntu suggests the package

Exercise 3: Fix Broken Packages

Simulate and fix package problems (Debian/Ubuntu):

  1. Run sudo dpkg --configure -a to check if any packages need reconfiguring.
  2. Run sudo apt --fix-broken install to fix any broken dependencies.
  3. Check for held packages with apt-mark showhold.
  4. Hold the vim package, verify it shows as held, then unhold it.
  5. List all configured APT sources (check /etc/apt/sources.list and /etc/apt/sources.list.d/).
Show Solution 
$ sudo dpkg --configure -a
# If nothing is broken, this produces no output.

$ sudo apt --fix-broken install
# Resolves any unmet dependencies.

$ apt-mark showhold
# Lists held packages (probably empty).

$ sudo apt-mark hold vim
vim set on hold.
$ apt-mark showhold
vim
$ sudo apt-mark unhold vim
Canceled hold on vim.

$ cat /etc/apt/sources.list
$ ls /etc/apt/sources.list.d/
# Shows all configured repositories and PPAs.
Exercise 4: Find the Right Package

Use the search tools to answer these questions (Debian/Ubuntu):

  1. Which package provides the dig command?
  2. Which package provides the ifconfig command?
  3. Search for packages related to "markdown." How many results are there?
  4. What version of openssh-server is available in your repos?
  5. Which installed package owns the file /usr/bin/less?
Show Solution 
# 1. Which package provides dig?
$ apt-file search bin/dig | grep "/dig$"
bind9-dnsutils: /usr/bin/dig
# Or, if dig is not installed, just type "dig" and Ubuntu will suggest the package.

# 2. Which package provides ifconfig?
$ apt-file search bin/ifconfig
net-tools: /sbin/ifconfig

# 3. Search for markdown-related packages
$ apt search markdown | wc -l

# 4. Check available version of openssh-server
$ apt-cache policy openssh-server

# 5. Which package owns /usr/bin/less?
$ dpkg -S /usr/bin/less
less: /usr/bin/less
Exercise 5: Snap and Flatpak Exploration

Try working with alternative package formats:

  1. Check if snap is installed: snap version.
  2. List currently installed snaps with snap list.
  3. Search for a snap: snap find "text editor".
  4. Check if flatpak is installed: flatpak --version. If not, install it with sudo apt install flatpak.
  5. List installed Flatpak apps (if any): flatpak list.
  6. Compare: check if VLC is available via apt search vlc, snap find vlc, and flatpak search vlc. Which versions are offered?
Show Solution 
$ snap version
snap    2.61
snapd   2.61
series  16
ubuntu  22.04

$ snap list
# Shows all installed snaps

$ snap find "text editor"
# Shows available text editor snaps

$ flatpak --version
# If "command not found":
$ sudo apt install flatpak
$ flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo

$ flatpak list
# Shows installed Flatpak apps (may be empty)

# Compare VLC availability across all three
$ apt show vlc 2>/dev/null | grep Version
$ snap info vlc 2>/dev/null | grep "latest/stable"
$ flatpak search vlc 2>/dev/null
