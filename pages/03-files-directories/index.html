Chapter 3: File and Directory Commands

In this chapter you will learn how to create, copy, move, rename, and delete files and directories from the command line. These commands form the backbone of everyday Linux work. You will also learn about links, file type identification, and how to inspect detailed file metadata.

Prerequisites

Before starting this chapter, make sure you are comfortable with pwd, ls, and cd from Chapter 2: Terminal Basics. You should know how to navigate the filesystem and list directory contents.

Mental Model: How Files Work in Linux

Before you start creating and deleting files, it helps to understand what a "file" actually is under the hood in Linux.

Everything is a file

In Linux, almost everything is represented as a file: regular documents, directories, hardware devices (/dev/sda), network sockets, and even running processes (/proc). This unified design means the same commands work on many different kinds of objects.

Inodes — the real identity of a file

Every file on disk has a unique number called an inode (index node). The inode stores all the metadata about the file: its size, owner, permissions, timestamps, and the locations of the actual data blocks on disk. Crucially, the inode does not store the filename.

Directories are just lists

A directory is a special file that contains a table mapping names to inode numbers. When you "create a file" named report.txt, you are really adding an entry in the parent directory that says "the name report.txt points to inode 284710."

  Directory: /home/user/
  +-----------------+----------+
  | Name            | Inode #  |
  +-----------------+----------+
  | .               | 131073   |   (this directory itself)
  | ..              | 2        |   (parent directory)
  | report.txt      | 284710   |
  | notes.txt       | 284711   |
  | projects/       | 284720   |   (another directory)
  +-----------------+----------+

  Inode 284710:
  +-----------------------------+
  | size: 2048 bytes            |
  | owner: user                 |
  | permissions: rw-r--r--      |
  | data blocks: 50123, 50124  |
  +-----------------------------+

Why this matters

  • Renaming a file is instant — you only change the name in the directory table, not the data.
  • Hard links are additional directory entries pointing to the same inode, so the same data can have multiple names.
  • Deleting a file removes the directory entry. The actual data is only freed when no directory entries (links) point to the inode anymore.
  • Moving a file within the same filesystem is just updating directory entries — no data is copied.

1. touch — Create Files and Update Timestamps

The touch command creates empty files or updates the access and modification timestamps of existing files. It is the quickest way to create a new empty file from the command line.

Syntax

touch [OPTIONS] FILE...

Common Flags

FlagDescription
-aChange only the access time
-mChange only the modification time
-t STAMPSet time to a specific value (format: [[CC]YY]MMDDhhmm[.ss])
-d STRINGSet time using a human-readable date string
-r REFUse the timestamp of another file as reference
-cDo not create the file if it does not exist

Examples

$ touch newfile.txt
$ ls -l newfile.txt
-rw-r--r-- 1 user user 0 Mar 31 10:00 newfile.txt

Creates an empty file. If the file already exists, its timestamp is updated to the current time.

$ touch file1.txt file2.txt file3.txt
$ ls
file1.txt  file2.txt  file3.txt

Create multiple files at once.

$ touch notes_{monday,tuesday,wednesday}.txt
$ ls
notes_monday.txt  notes_tuesday.txt  notes_wednesday.txt

Using brace expansion to create several files with a pattern.

$ touch -t 202301150830.00 oldfile.txt
$ ls -l oldfile.txt
-rw-r--r-- 1 user user 0 Jan 15  2023 oldfile.txt

Set a specific timestamp. Format: YYYYMMDDhhmm.ss

$ touch -d "2024-06-15 14:30" meeting.txt
$ ls -l meeting.txt
-rw-r--r-- 1 user user 0 Jun 15  2024 meeting.txt

Set timestamp using a human-readable date string.

$ touch -r file1.txt file2.txt
$ stat file1.txt file2.txt | grep Modify
Modify: 2026-03-31 10:00:00.000000000 +0000
Modify: 2026-03-31 10:00:00.000000000 +0000

Copy the timestamp from file1.txt to file2.txt.

$ touch -a config.cfg

Update only the access time, leaving the modification time unchanged.

$ touch -c nonexistent.txt
$ ls nonexistent.txt
ls: cannot access 'nonexistent.txt': No such file or directory

With -c, the file is not created if it does not exist. Useful in scripts where you only want to update timestamps.

Tip

A common pattern is touch logfile.log to ensure a log file exists before a program tries to write to it. This prevents "file not found" errors.

Common Mistakes

  • Forgetting that touch on an existing file does not erase its contents — it only updates the timestamp.
  • Using touch when you meant to use > file.txt (which does truncate the file to zero bytes).

Related commands: stat, date, ls -l

2. mkdir — Create Directories

The mkdir command creates new directories. It is one of the first commands any Linux user learns.

Syntax

mkdir [OPTIONS] DIRECTORY...

Common Flags

FlagDescription
-pCreate parent directories as needed (no error if they exist)
-vVerbose — print a message for each created directory
-m MODESet permissions (mode) when creating the directory

Examples

$ mkdir projects
$ ls -ld projects
drwxr-xr-x 2 user user 4096 Mar 31 10:05 projects

Create a single directory.

$ mkdir docs images scripts
$ ls
docs  images  scripts

Create multiple directories at once.

$ mkdir project/src/main
mkdir: cannot create directory 'project/src/main': No such file or directory

$ mkdir -p project/src/main
$ tree project
project
└── src
    └── main

Without -p, mkdir fails if parent directories do not exist. The -p flag creates the entire path.

$ mkdir -pv app/{bin,lib,config,logs}
mkdir: created directory 'app'
mkdir: created directory 'app/bin'
mkdir: created directory 'app/lib'
mkdir: created directory 'app/config'
mkdir: created directory 'app/logs'

Combine -p and brace expansion to create an entire project structure in one command.

$ mkdir -pv website/{css,js,images,pages/{about,contact,blog}}
mkdir: created directory 'website'
mkdir: created directory 'website/css'
mkdir: created directory 'website/js'
mkdir: created directory 'website/images'
mkdir: created directory 'website/pages'
mkdir: created directory 'website/pages/about'
mkdir: created directory 'website/pages/contact'
mkdir: created directory 'website/pages/blog'

Nested brace expansion for complex structures.

$ mkdir -m 700 private_data
$ ls -ld private_data
drwx------ 2 user user 4096 Mar 31 10:10 private_data

Create a directory with specific permissions. 700 means only the owner can read, write, or enter it.

$ mkdir -pv backup/$(date +%Y/%m/%d)
mkdir: created directory 'backup'
mkdir: created directory 'backup/2026'
mkdir: created directory 'backup/2026/03'
mkdir: created directory 'backup/2026/03/31'

Use command substitution to create date-based directory structures.

$ mkdir "my folder"
$ ls
my folder

Directories with spaces require quotes. Prefer hyphens or underscores instead: my-folder.

Tip

Always use mkdir -p in scripts. It will not fail if the directory already exists, making your scripts more robust.

Common Mistakes

  • Forgetting -p when creating nested paths.
  • Not quoting directory names that contain spaces.

Related commands: rmdir, tree, ls

3. rmdir — Remove Empty Directories

rmdir removes directories, but only if they are empty. This makes it a safe command — you cannot accidentally delete a directory full of files.

Syntax

rmdir [OPTIONS] DIRECTORY...

Common Flags

FlagDescription
-pRemove the directory and its empty parent directories
-vVerbose — print a message for each removed directory
--ignore-fail-on-non-emptySuppress error messages for non-empty directories

Examples

$ mkdir test_dir
$ rmdir test_dir
$ ls test_dir
ls: cannot access 'test_dir': No such file or directory

Remove an empty directory.

$ mkdir -p a/b/c
$ rmdir a
rmdir: failed to remove 'a': Directory not empty

rmdir refuses to remove a directory that contains other files or directories.

$ rmdir -p a/b/c
$ ls a
ls: cannot access 'a': No such file or directory

With -p, rmdir removes c, then b, then a — but only because each becomes empty after its child is removed.

$ rmdir -v empty1 empty2 empty3
rmdir: removing directory, 'empty1'
rmdir: removing directory, 'empty2'
rmdir: removing directory, 'empty3'

Verbose removal of multiple empty directories.

$ mkdir -p temp/data
$ touch temp/data/file.txt
$ rmdir -p temp/data
rmdir: failed to remove 'temp/data': Directory not empty

If any directory in the chain is not empty, rmdir stops and reports an error.

$ rmdir nonempty_dir --ignore-fail-on-non-empty

Silently skip non-empty directories. Useful in scripts where you want to clean up only empty directories.

$ rmdir dir1 dir2 dir3
rmdir: failed to remove 'dir2': Directory not empty

When removing multiple directories, rmdir reports errors individually but continues with the rest.

$ find . -type d -empty -exec rmdir -v {} +
rmdir: removing directory, './old_cache'
rmdir: removing directory, './tmp_build'

Find and remove all empty directories in the current tree. A useful cleanup pattern.

rmdir vs rm -r

rmdir is safe because it only removes empty directories. If you need to remove a directory and everything inside it, you need rm -r — but that is a much more dangerous command. See the rm section below.

Related commands: mkdir, rm -r, find -empty

4. cp — Copy Files and Directories

The cp command copies files and directories. It is one of the most used commands in day-to-day Linux work.

Syntax

cp [OPTIONS] SOURCE DEST
cp [OPTIONS] SOURCE... DIRECTORY

Common Flags

FlagDescription
-r / -RRecursive — copy directories and their contents
-iInteractive — prompt before overwriting
-vVerbose — show each file as it is copied
-uUpdate — only copy if the source is newer than the destination
-aArchive — preserve permissions, timestamps, ownership, and links (same as -dR --preserve=all)
-nNo clobber — do not overwrite existing files
-pPreserve permissions, ownership, and timestamps
-lCreate hard links instead of copying
-sCreate symbolic links instead of copying
--backupCreate a backup of each existing destination file

Examples

$ cp original.txt copy.txt
$ ls
copy.txt  original.txt

Copy a single file. The copy is independent of the original.

$ cp file1.txt file2.txt file3.txt backup/
$ ls backup/
file1.txt  file2.txt  file3.txt

Copy multiple files into a directory. The destination must already exist and be a directory.

$ cp report.txt docs/
$ ls docs/
report.txt

Copy a file into an existing directory, keeping the same filename.

$ cp -r project/ project_backup/
$ ls project_backup/
src  docs  README.md

Copy an entire directory tree. Without -r, cp refuses to copy directories.

$ cp -i important.txt backup/important.txt
cp: overwrite 'backup/important.txt'? y

Interactive mode asks before overwriting. Very useful for important files.

$ cp -v *.log /var/log/archive/
'access.log' -> '/var/log/archive/access.log'
'error.log' -> '/var/log/archive/error.log'
'debug.log' -> '/var/log/archive/debug.log'

Verbose mode shows what is being copied. Great for monitoring large copy operations.

$ cp -u *.txt backup/

Only copy files that are newer than what is already in backup/. Useful for incremental backups.

$ cp -a /home/user/project /media/usb/project_backup

Archive mode: preserves everything (permissions, ownership, timestamps, symlinks). The gold standard for backups.

$ cp -rn source_dir/ dest_dir/

Copy a directory recursively but never overwrite existing files in the destination.

$ cp --backup=numbered config.cfg config.cfg
$ ls
config.cfg  config.cfg.~1~

Create a numbered backup before overwriting.

$ cp -rv project/{src,docs} release/
'project/src' -> 'release/src'
'project/src/main.c' -> 'release/src/main.c'
'project/docs' -> 'release/docs'
'project/docs/manual.txt' -> 'release/docs/manual.txt'

Copy selected subdirectories using brace expansion.

$ cp -s /usr/local/bin/myapp ~/bin/myapp
$ ls -l ~/bin/myapp
lrwxrwxrwx 1 user user 22 Mar 31 10:20 /home/user/bin/myapp -> /usr/local/bin/myapp

Create a symbolic link instead of a physical copy.

Warning: cp overwrites silently

By default, cp silently overwrites existing files at the destination. Use -i (interactive) or -n (no clobber) to protect against accidental data loss. Many system administrators add alias cp='cp -i' to their shell profile.

Common Mistakes

  • Forgetting -r when copying directories — cp will skip them and print an error.
  • Copying into a non-existent directory path — cp will treat the path as a filename instead.
  • Not using -a for backups and losing file permissions or ownership.

Related commands: mv, rsync, scp, install

5. mv — Move and Rename Files

mv moves files and directories to a new location. When used on the same filesystem, it simply updates directory entries without copying data, making it nearly instant regardless of file size. It also serves as the standard way to rename files and directories.

Syntax

mv [OPTIONS] SOURCE DEST
mv [OPTIONS] SOURCE... DIRECTORY

Common Flags

FlagDescription
-iInteractive — prompt before overwriting
-vVerbose — show each file being moved
-nNo clobber — do not overwrite existing files
-uUpdate — move only if the source is newer
-fForce — do not prompt before overwriting (default behavior)
--backupCreate a backup of each existing destination file

Examples

$ mv oldname.txt newname.txt
$ ls
newname.txt

Rename a file. This is the standard way to rename in Linux.

$ mv old_directory/ new_directory/
$ ls
new_directory

Rename a directory. Unlike cp, mv does not need -r for directories.

$ mv report.txt docs/
$ ls docs/
report.txt

Move a file into a directory.

$ mv file1.txt file2.txt file3.txt archive/
$ ls archive/
file1.txt  file2.txt  file3.txt

Move multiple files into a directory at once.

$ mv *.jpg images/

Move all JPEG files into an images directory using a glob pattern.

$ mv -i data.csv backup/data.csv
mv: overwrite 'backup/data.csv'? n

Interactive mode gives you a chance to cancel before overwriting.

$ mv -v project/ /opt/
renamed 'project/' -> '/opt/project'

Verbose output shows the action taken.

$ mv -n incoming.txt archive/incoming.txt

No clobber: if archive/incoming.txt already exists, do nothing.

$ mv report.txt docs/final_report.txt

Move and rename in one step.

$ mv --backup=numbered config.yaml config.yaml.bak
$ ls
config.yaml.bak  config.yaml.bak.~1~

Automatically create numbered backups of the destination file.

$ for f in *.JPEG; do mv "$f" "${f%.JPEG}.jpg"; done

Batch rename: convert all .JPEG extensions to .jpg using a shell loop.

Tip: Safe aliases

Add alias mv='mv -i' to your ~/.bashrc to always be prompted before overwriting. You can override the alias temporarily with \mv or command mv when you explicitly want force behavior.

Common Mistakes

  • Moving a file into a directory that does not exist — mv will rename the file to that path instead of reporting an error in some cases.
  • Forgetting that mv across filesystems (e.g., from /home to /tmp on a different partition) performs a copy-then-delete, which is slower and may fail if disk space is low.

Related commands: cp, rename, install

6. rm — Remove Files and Directories

DANGER: rm is permanent

Linux has no recycle bin on the command line. When you rm a file, it is gone. There is no undo. There is no confirmation by default. Double-check your command before pressing Enter, especially when using -r and -f flags together.

The rm command removes (deletes) files and directories. It is powerful and dangerous. Use it with care.

Syntax

rm [OPTIONS] FILE...

Common Flags

FlagDescription
-r / -RRecursive — remove directories and all their contents
-fForce — never prompt, ignore nonexistent files
-iInteractive — prompt before every removal
-IPrompt once before removing more than three files or recursing
-vVerbose — print each file as it is removed
-dRemove empty directories (like rmdir)
--preserve-rootDo not remove / (this is the default on modern systems)

Examples

$ rm unwanted.txt
$ ls unwanted.txt
ls: cannot access 'unwanted.txt': No such file or directory

Remove a single file. Gone instantly, no confirmation.

$ rm file1.txt file2.txt file3.txt

Remove multiple files at once.

$ rm *.tmp

Remove all files matching a pattern. Always double-check your glob with ls *.tmp first.

$ rm -i important_data.csv
rm: remove regular file 'important_data.csv'? y

Interactive mode asks for confirmation. Use this for important files.

$ rm -r old_project/

Recursively remove a directory and everything inside it.

$ rm -rv build/
removed 'build/output/main.o'
removed 'build/output/utils.o'
removed directory 'build/output'
removed 'build/Makefile'
removed directory 'build/'

Verbose recursive removal shows every file and directory being deleted.

$ rm -rf temp_dir/

Force recursive removal. No prompts, no errors for missing files. Use only when you are absolutely certain.

$ rm -I *.log
rm: remove 47 arguments? y

-I prompts once when removing many files. A good middle ground between -i (too many prompts) and no flag (too dangerous).

$ rm -- -weird-filename.txt

Use -- to remove files whose names start with a dash. Without it, rm would interpret -weird-filename.txt as flags.

$ rm -f nonexistent.txt

-f suppresses the "No such file or directory" error. Useful in scripts for idempotent cleanup.

NEVER run: rm -rf /

The command rm -rf / attempts to delete every single file on the entire system. Modern Linux distributions have a safeguard (--preserve-root) that blocks this exact command, but variations like rm -rf /* or rm -rf $VAR/ (when $VAR is empty) can still destroy your system. Never use rm -rf with variables that could expand to / or empty strings.

NEVER run: rm -rf $VARIABLE/ when the variable might be empty

If you write a script like rm -rf $DIR/ and $DIR is unset or empty, the command becomes rm -rf /. Always validate variables and use ${DIR:?Variable not set} to abort instead of deleting everything.

Wrong
$ rm -rf $DEPLOY_DIR/
# If DEPLOY_DIR is empty, this becomes: rm -rf /
# YOUR ENTIRE SYSTEM IS NOW BEING DELETED
$ rm -rf /home/user/*
# One typo (extra space) and you delete everything:
# rm -rf /home/user/ *    (deletes home AND everything in cwd)
$ rm -rf temp *
# Missing the / between temp and *
# Deletes "temp" AND everything in the current directory
Right
$ rm -rf "${DEPLOY_DIR:?Error: variable not set}/"
# Aborts with an error if DEPLOY_DIR is empty
$ # First, verify what will be deleted:
$ ls /home/user/*
$ # Then delete:
$ rm -ri /home/user/*
rm: remove regular file '/home/user/old.txt'? y
$ rm -rf temp/
# Use a trailing slash for clarity
# Or better: rm -rv temp/ to see what is deleted

Safe Usage Tips for rm

  • Use ls first — run your glob with ls before rm: ls *.tmp then rm *.tmp.
  • Use -i or -I — especially when using wildcards or the -r flag.
  • Use -v — verbose output lets you see what is happening and cancel if something looks wrong.
  • Alias rm — add alias rm='rm -I' to your ~/.bashrc for a safety net.
  • Avoid -rf with variables — always validate variables in scripts before using them with rm.
  • Consider trash-cli — install a trash utility to move files to a recycle bin instead of deleting them permanently.

Related commands: rmdir, find -delete, shred, trash-put

7. ln — Create Links

The ln command creates links between files. Links allow a file to be accessed by multiple names or from multiple locations without duplicating data.

Syntax

ln [OPTIONS] TARGET LINK_NAME

Common Flags

FlagDescription
-sCreate a symbolic (soft) link instead of a hard link
-fForce — remove existing destination files
-vVerbose — print the name of each link created
-nTreat a symlink to a directory as a file (do not follow it)
-rCreate relative symbolic links
Hard Links vs Symbolic (Soft) Links

There are two types of links in Linux, and understanding the difference requires knowing about inodes (see the mental model at the top of this chapter).

Hard Links

A hard link is an additional directory entry pointing to the same inode. The original file and the hard link are completely equal — there is no "original" and "link," just two names for the same data.

Symbolic (Soft) Links

A symbolic link (symlink) is a special file that contains a text path pointing to another file. It is like a shortcut. If the target is deleted, the symlink becomes a "dangling" link that points to nothing.

  HARD LINK                           SYMBOLIC LINK
  ─────────                           ─────────────

  Directory entries:                  Directory entries:
  ┌────────────────┐                  ┌────────────────┐
  │ report.txt ────┤──┐               │ data.txt ──────┤──> Inode 500
  └────────────────┘  │               └────────────────┘    (actual data)
  ┌────────────────┐  │               ┌────────────────┐
  │ report_v2.txt ─┤──┘──> Inode 100  │ latest.txt ────┤──> Inode 501
  └────────────────┘      (data on    └────────────────┘    (contains the
                           disk)                             text path:
                                                             "data.txt")
  Both names point to the            latest.txt -> data.txt
  SAME inode and data.               If data.txt is deleted,
  Delete one, the other              latest.txt becomes a
  still works perfectly.             broken (dangling) link.

  Hard link count: 2                 Hard link count: 1 each
  Same filesystem only               Can cross filesystems
  Cannot link to directories          Can link to directories
  Cannot tell which came first       ls -l shows the -> target

Examples

$ echo "Hello" > original.txt
$ ln original.txt hardlink.txt
$ ls -li original.txt hardlink.txt
284710 -rw-r--r-- 2 user user 6 Mar 31 10:30 hardlink.txt
284710 -rw-r--r-- 2 user user 6 Mar 31 10:30 original.txt

Create a hard link. Notice: same inode number (284710), and the link count is 2.

$ ln -s /var/log/syslog ~/logs/syslog
$ ls -l ~/logs/syslog
lrwxrwxrwx 1 user user 15 Mar 31 10:32 /home/user/logs/syslog -> /var/log/syslog

Create a symbolic link. The l at the start of permissions indicates a symlink.

$ ln -s /opt/myapp/bin/app /usr/local/bin/app

A common pattern: create a symlink in a directory on the PATH so you can run a program from anywhere.

$ rm original.txt
$ cat hardlink.txt
Hello

After deleting the original, the hard link still works because it points to the same inode. The data is only freed when all links are removed.

$ ln -s target.txt symlink.txt
$ rm target.txt
$ cat symlink.txt
cat: symlink.txt: No such file or directory
$ ls -l symlink.txt
lrwxrwxrwx 1 user user 10 Mar 31 10:35 symlink.txt -> target.txt

A broken (dangling) symlink. The link still exists but points to nothing.

$ ln -sf new_target.txt existing_link.txt

Force-update a symlink to point to a new target.

$ ln -s /opt/app/v2 /opt/app/current
$ ls -l /opt/app/current
lrwxrwxrwx 1 root root 12 Mar 31 10:38 /opt/app/current -> /opt/app/v2

Common deployment pattern: a "current" symlink points to the active version. Switch versions by changing the symlink.

$ ln -sv config.prod.yaml config.yaml
'config.yaml' -> 'config.prod.yaml'

Verbose mode confirms the link creation.

$ find . -xtype l
./broken_link1
./broken_link2

Find all broken symbolic links in the current directory tree.

$ stat hardlink.txt
  File: hardlink.txt
  Size: 6          Blocks: 8          IO Block: 4096   regular file
Device: 801h/2049d  Inode: 284710      Links: 2

Use stat to see the inode number and link count of a file.

When to use which type of link

Use symbolic links in most cases — they are more flexible (cross filesystems, link to directories) and easier to understand (you can see the target with ls -l).

Use hard links when you need the data to survive deletion of the "original" name, or when you want to save disk space by having multiple names for the same data without the overhead of a symlink.

Related commands: readlink, stat, ls -l, find -type l

8. file — Identify File Types

The file command examines files and tells you what type they are. Unlike Windows, Linux does not rely on file extensions to determine types — file inspects the actual contents (magic bytes) of the file.

Syntax

file [OPTIONS] FILE...

Common Flags

FlagDescription
-bBrief — do not prepend the filename in output
-iOutput MIME type instead of human-readable description
-LFollow symbolic links
-zLook inside compressed files
-f LISTRead filenames from a list file

Examples

$ file document.pdf
document.pdf: PDF document, version 1.4

Identifies a PDF file by its content, not its extension.

$ file photo.jpg
photo.jpg: JPEG image data, JFIF standard 1.01, resolution (DPI), density 72x72, segment length 16
$ file script.sh
script.sh: Bourne-Again shell script, ASCII text executable

Identifies the type of script by reading the shebang line (#!/bin/bash).

$ file /usr/bin/ls
/usr/bin/ls: ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked

Identifies a compiled binary executable.

$ file mystery_file
mystery_file: gzip compressed data, was "backup.tar", last modified: Sun Mar 29 08:00:00 2026

Even without an extension, file identifies the content correctly.

$ file -b notes.txt
ASCII text

Brief mode omits the filename from the output.

$ file -i data.json
data.json: application/json; charset=utf-8

MIME type output, useful for scripting and web applications.

$ file /dev/sda
/dev/sda: block special (8/0)

Identifies device files too.

$ file -i *
image.png:    image/png; charset=binary
README.md:    text/plain; charset=utf-8
data.csv:     text/plain; charset=us-ascii
app:          application/x-executable; charset=binary

Check MIME types of all files in a directory.

$ mv photo.jpg photo.txt
$ file photo.txt
photo.txt: JPEG image data, JFIF standard 1.01

Renaming the extension does not fool file — it reads the actual content.

Tip

Use file when you find a mysterious file with no extension, or when you suspect a file has the wrong extension. It is also helpful for verifying that downloads are what they claim to be.

Related commands: stat, mimetype, xdg-mime

9. stat — Detailed File Information

The stat command displays detailed metadata about a file or filesystem. It shows everything that ls -l shows and much more: inode number, exact timestamps (with nanoseconds), block count, device IDs, and more.

Syntax

stat [OPTIONS] FILE...

Common Flags

FlagDescription
-fDisplay filesystem status instead of file status
-LFollow symbolic links
-c FORMATUse a custom output format string
--printf=FORMATLike -c but interprets backslash escapes

Examples

$ stat report.txt
  File: report.txt
  Size: 2048        Blocks: 8          IO Block: 4096   regular file
Device: 801h/2049d  Inode: 284710      Links: 1
Access: (0644/-rw-r--r--)  Uid: ( 1000/    user)   Gid: ( 1000/    user)
Access: 2026-03-31 09:00:00.123456789 +0000
Modify: 2026-03-30 14:30:22.987654321 +0000
Change: 2026-03-30 14:30:22.987654321 +0000
 Birth: 2026-03-28 08:15:00.000000000 +0000

Full file status. Shows the inode number, link count, three timestamps (Access, Modify, Change), and the birth (creation) time.

$ stat -c "%n: %s bytes, inode %i, %h links" report.txt
report.txt: 2048 bytes, inode 284710, 1 links

Custom format output. Useful format specifiers: %n (name), %s (size), %i (inode), %h (link count), %U (owner), %a (octal permissions).

$ stat -c "%a %U %G %n" *
644 user user report.txt
755 user user script.sh
700 user user private/

Show octal permissions, owner, group, and name for all files.

$ stat -c "%y" report.txt
2026-03-30 14:30:22.987654321 +0000

Show only the modification time with nanosecond precision.

$ stat -f /
  File: "/"
    ID: abcdef12345678 Namelen: 255     Type: ext2/ext3
Block size: 4096       Fundamental block size: 4096
Blocks: Total: 25600000   Free: 12800000   Available: 11520000
Inodes: Total: 6553600    Free: 5242880

Filesystem status. Shows total and available disk space at the block level.

$ stat -c "%F" /dev/sda /tmp report.txt /dev/null
block special file
directory
regular file
character special file

The %F format shows the file type in words.

$ stat -L symlink.txt

Follow a symbolic link and show the status of the target file instead of the link itself.

$ stat --printf="Owner: %U\nSize: %s\nModified: %y\n" data.csv
Owner: user
Size: 4096
Modified: 2026-03-31 08:00:00.000000000 +0000

Using --printf with newline escapes for readable output.

Three timestamps explained
  • Access (atime): Last time the file contents were read.
  • Modify (mtime): Last time the file contents were changed.
  • Change (ctime): Last time the file metadata (permissions, ownership, etc.) was changed. This is NOT the creation time.
  • Birth: The actual creation time (not available on all filesystems).

Related commands: ls -l, file, df, du

11. basename and dirname — Extract Path Components

basename extracts the filename from a path. dirname extracts the directory part. These are essential for shell scripting when you need to work with parts of file paths.

Syntax

basename PATH [SUFFIX]
dirname PATH

Common Flags

FlagCommandDescription
-abasenameSupport multiple arguments
-s SUFFIXbasenameRemove a trailing suffix (extension)
-zbothSeparate output with NUL instead of newline

Examples

$ basename /home/user/documents/report.txt
report.txt

Extract just the filename from a full path.

$ dirname /home/user/documents/report.txt
/home/user/documents

Extract just the directory path.

$ basename /home/user/documents/report.txt .txt
report

Remove a suffix (extension) from the filename.

$ basename -s .tar.gz backup-2026-03-31.tar.gz
backup-2026-03-31

The -s flag explicitly specifies the suffix to remove.

$ basename -a /path/to/file1.txt /path/to/file2.txt /path/to/file3.txt
file1.txt
file2.txt
file3.txt

Process multiple paths at once.

$ dirname /var/log/syslog
/var/log
$ dirname /home/user/
/home

Trailing slashes are handled correctly.

$ dirname filename.txt
.

When there is no directory component, dirname returns . (current directory).

Practical scripting examples

$ # Get the name of the current directory
$ basename $(pwd)
projects
$ # Convert file extensions in a script
$ file="photo.jpeg"
$ echo "$(basename "$file" .jpeg).png"
photo.png
$ # Create an output file in the same directory as the input
$ input="/data/raw/measurements.csv"
$ output="$(dirname "$input")/$(basename "$input" .csv)_processed.csv"
$ echo "$output"
/data/raw/measurements_processed.csv
$ # Process all .log files: create .bak copies in the same directories
$ for f in /var/log/*.log; do
>   cp "$f" "$(dirname "$f")/$(basename "$f" .log).bak"
> done
Tip: Shell parameter expansion alternative

In Bash, you can also use parameter expansion: ${path##*/} works like basename and ${path%/*} works like dirname. These are faster in scripts because they do not fork a new process, but they are less readable.

Related commands: realpath, readlink, pwd

Exercise 4: Understanding Links

Perform the following and explain the output at each step:

  1. Create a file: echo "important data" > original.txt
  2. Create a hard link: ln original.txt hardlink.txt
  3. Create a soft link: ln -s original.txt softlink.txt
  4. Run ls -li and note the inode numbers and link counts
  5. Delete original.txt
  6. Try cat hardlink.txt and cat softlink.txt — which one still works and why?
Show solution 
$ echo "important data" > original.txt
$ ln original.txt hardlink.txt
$ ln -s original.txt softlink.txt
$ ls -li
284710 -rw-r--r-- 2 user user 15 Mar 31 11:10 hardlink.txt
284710 -rw-r--r-- 2 user user 15 Mar 31 11:10 original.txt
284720 lrwxrwxrwx 1 user user 12 Mar 31 11:10 softlink.txt -> original.txt
$ rm original.txt
$ cat hardlink.txt
important data
$ cat softlink.txt
cat: softlink.txt: No such file or directory

Explanation: The hard link shares the same inode (284710) as the original, so deleting one name does not affect the data — it is still reachable via the other name. The soft link stored the text path "original.txt", and since that name no longer exists, the soft link is broken.

Quizzes

Quiz 1: You want to copy a directory called photos/ and all its contents to /backup/photos/, preserving all permissions and timestamps. Which command is correct?

  1. cp photos/ /backup/photos/
  2. cp -r photos/ /backup/photos/
  3. cp -a photos/ /backup/photos/
  4. mv photos/ /backup/photos/

C is the best answer. cp -a copies recursively AND preserves permissions, timestamps, ownership, and symbolic links. Option A fails because cp refuses to copy directories without -r. Option B copies recursively but does not preserve all metadata. Option D would move (not copy) the directory, so the original would be gone.

Quiz 2: You create a file and a symbolic link:

echo "data" > file.txt
ln -s file.txt link.txt

Then you delete file.txt and run ls -l link.txt. What happens?

  1. link.txt is automatically deleted too
  2. link.txt still exists but points to nothing (dangling link)
  3. link.txt still works because it has a copy of the data
  4. An error occurs when creating the link

B is correct. A symbolic link is just a pointer that stores the path "file.txt". Deleting the target does not delete the link. The link becomes "dangling" — it points to a path that no longer exists. Running ls -l will still show the link, but attempting to read it with cat will give a "No such file or directory" error.

Quiz 3: What is the difference between rm file.txt and rmdir file.txt?

  1. They do the same thing
  2. rm deletes files; rmdir only deletes empty directories
  3. rmdir is safer because it moves files to the trash
  4. rm only works on directories; rmdir only works on files

B is correct. rm deletes files (and with -r, directories). rmdir only removes directories, and only if they are empty. Neither command moves anything to a trash bin — deletion is permanent in both cases.
