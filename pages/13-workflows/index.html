Chapter 13: Real-World Workflows

This chapter is where everything comes together. You have learned individual commands across the previous twelve chapters. Now we combine them into practical workflows that solve real problems you will face every day as a Linux user, developer, or system administrator.

Each workflow below follows the same pattern: the problem, step-by-step commands, expected output, and tips for getting the best results.

How to Use This Chapter

You do not need to memorize every workflow. Bookmark this page and come back whenever you face one of these situations. Over time, the patterns will become second nature.

1. Find Large Files

The problem: Your disk is running low on space and you need to find which files are eating up the most room. You want to locate the biggest offenders quickly so you can decide what to delete or move.

Approach 1: Using du + sort + head

The du command calculates disk usage. Combined with sort and head, you can list the top space consumers.

$ du -ah /home/user | sort -rh | head -20
4.2G    /home/user
1.8G    /home/user/Videos
900M    /home/user/Videos/tutorial.mp4
650M    /home/user/.cache
420M    /home/user/Downloads
380M    /home/user/Downloads/ubuntu.iso
210M    /home/user/.cache/mozilla
...

Explanation of the flags:

  • -a — show all files, not just directories
  • -h — human-readable sizes (K, M, G)
  • sort -rh — reverse sort by human-readable numbers (biggest first)
  • head -20 — show only the top 20 results

Approach 2: Using find with -size

If you want to find files above a specific threshold:

$ find /home/user -type f -size +100M
/home/user/Videos/tutorial.mp4
/home/user/Downloads/ubuntu.iso

To also see the sizes:

$ find /home/user -type f -size +100M -exec ls -lh {} \;
-rw-r--r-- 1 user user 900M Mar 15 10:30 /home/user/Videos/tutorial.mp4
-rw-r--r-- 1 user user 380M Mar 10 08:22 /home/user/Downloads/ubuntu.iso

Approach 3: Using find + sort for a Sorted List

$ find /home/user -type f -size +50M -printf '%s %p\n' | sort -rn | head -10
943718400 /home/user/Videos/tutorial.mp4
398458880 /home/user/Downloads/ubuntu.iso
...

The -printf '%s %p\n' prints size in bytes followed by the path, making it sortable numerically.

Approach 4: Using ncdu (Interactive)

$ ncdu /home/user

This opens an interactive, navigable view of disk usage. Press d to delete files directly, q to quit. Install it with sudo apt install ncdu if not available.

Tip

Start with du -sh /home/user/* to see which top-level directories are largest, then drill down into the big ones.

2. Search Logs for Errors

The problem: Something went wrong on your server or machine. You need to find error messages in system logs to diagnose the issue.

Step 1: Know Where Logs Live

Most system logs are in /var/log/:

$ ls /var/log/
auth.log  dpkg.log  kern.log  syslog  apache2/  nginx/  mysql/  ...

Step 2: Search with grep

$ grep -i "error" /var/log/syslog
Mar 15 10:30:22 server kernel: [ERROR] disk I/O timeout
Mar 15 10:30:25 server systemd: Unit failed: error code 1

Use -i for case-insensitive search since errors may appear as "Error", "ERROR", or "error".

Step 3: Search Multiple Patterns

$ grep -iE "error|fail|critical|panic" /var/log/syslog

The -E flag enables extended regex so you can use | for OR patterns.

Step 4: Use journalctl for systemd Logs

$ journalctl -p err -b
-- Logs begin at Mon 2025-03-10, end at Sat 2025-03-15 --
Mar 15 10:30:22 server kernel: disk I/O timeout
Mar 15 10:31:00 server nginx[1234]: bind() failed

Flags explained:

  • -p err — show only priority "error" and above (error, critical, alert, emergency)
  • -b — only current boot

Other useful journalctl commands:

$ journalctl -u nginx --since "1 hour ago"    # Logs from a specific service
$ journalctl -f                                # Follow logs in real time
$ journalctl --since "2025-03-15" --until "2025-03-16"

Step 5: Watch Logs in Real Time

$ tail -f /var/log/syslog
$ tail -f /var/log/syslog | grep --line-buffered "error"

The --line-buffered flag ensures grep outputs each matching line immediately rather than waiting for a buffer to fill.

Tip

Add context to your searches with grep -C 3 "error" /var/log/syslog to see 3 lines before and after each match. This helps you understand what happened leading up to the error.

3. Copy Files Safely

The problem: You need to copy files, but you do not want to accidentally overwrite existing files at the destination. A careless cp can silently destroy data.

Approach 1: Use cp -i (Interactive)

$ cp -i report.txt /backup/report.txt
cp: overwrite '/backup/report.txt'? n

The -i flag prompts you before overwriting any file. Always use this when copying to directories that might already contain files with the same names.

Approach 2: Use cp -n (No Clobber)

$ cp -n report.txt /backup/report.txt

The -n flag silently skips files that already exist at the destination. No prompt, no overwrite.

Approach 3: Use cp --backup

$ cp --backup=numbered report.txt /backup/report.txt

If /backup/report.txt already exists, this creates /backup/report.txt.~1~ as a backup before overwriting.

Approach 4: Use rsync --dry-run

$ rsync -av --dry-run /home/user/docs/ /backup/docs/
sending incremental file list
report.txt
notes.txt
images/screenshot.png

sent 180 bytes  received 45 bytes  450.00 bytes/sec
total size is 1,234,567  speedup is 5,486.52 (DRY RUN)

The --dry-run flag shows exactly what would happen without actually doing it. Once satisfied:

$ rsync -av /home/user/docs/ /backup/docs/

Approach 5: Verify Before Copying

Always check what exists at the destination first:

$ ls -la /backup/
$ diff report.txt /backup/report.txt    # See if files differ
Warning

A plain cp file.txt /destination/file.txt will silently overwrite the destination file with no way to undo. Always use -i or --dry-run with rsync when you are unsure.

4. Batch Rename Files

The problem: You have many files that need renaming, for example changing extensions, adding prefixes, or replacing spaces with underscores. Doing it one by one is tedious and error-prone.

Approach 1: Using mv in a for Loop

Rename all .txt files to .md:

$ for f in *.txt; do mv "$f" "${f%.txt}.md"; done

How it works:

  • for f in *.txt — loops over every .txt file in the current directory
  • ${f%.txt} — removes the .txt suffix from the filename
  • .md is appended as the new extension

Approach 2: Replace Spaces with Underscores

$ for f in *\ *; do mv "$f" "${f// /_}"; done

The ${f// /_} syntax replaces all spaces with underscores in the variable $f.

Approach 3: Add a Prefix to All Files

$ for f in *.jpg; do mv "$f" "photo_$f"; done
# beach.jpg -> photo_beach.jpg
# sunset.jpg -> photo_sunset.jpg

Approach 4: Add a Date Prefix

$ for f in *.log; do mv "$f" "$(date +%Y%m%d)_$f"; done
# app.log -> 20250315_app.log
# error.log -> 20250315_error.log

Approach 5: Using the rename Command

The rename command (Perl version) uses regular expressions:

$ rename 's/\.txt$/.md/' *.txt          # Change extension
$ rename 's/ /_/g' *                     # Replace spaces
$ rename 'y/A-Z/a-z/' *                  # Lowercase all filenames
$ rename 's/^/backup_/' *.sql             # Add prefix
Tip: Always Preview First

Use rename -n (dry run) to see what would be renamed without actually doing it:

$ rename -n 's/\.txt$/.md/' *.txt
file1.txt renamed as file1.md
file2.txt renamed as file2.md

Approach 6: Numbered Sequence

$ counter=1; for f in *.jpg; do mv "$f" "img_$(printf '%03d' $counter).jpg"; counter=$((counter+1)); done
# beach.jpg -> img_001.jpg
# sunset.jpg -> img_002.jpg
# mountain.jpg -> img_003.jpg

5. Monitor a Running Process

The problem: You started a long-running task (a build, a download, a server) and you want to monitor it — see how much CPU and memory it uses, or check if it is still alive.

Method 1: watch + ps

$ watch -n 2 'ps aux | grep python'

This refreshes every 2 seconds, showing all processes matching "python". Press Ctrl+C to stop.

Method 2: top -p (Monitor a Specific PID)

First find the PID:

$ pgrep -f "my_script.py"
12345
$ top -p 12345

This shows a live dashboard for only that process, displaying CPU usage, memory, and run time.

Method 3: ps with grep

$ ps aux | grep "[n]ginx"
root      1234  0.0  0.2  50000  4000 ?  Ss   10:30   0:00 nginx: master
www-data  1235  0.0  0.3  50500  6000 ?  S    10:30   0:05 nginx: worker

The [n]ginx trick prevents grep from matching its own process in the output.

Method 4: Check if a Process is Still Running

$ kill -0 12345 && echo "Running" || echo "Not running"
Running

The kill -0 sends signal 0 (no actual signal) — it just tests whether the process exists.

Method 5: Monitor with htop

$ htop -p 12345

Like top but with colors, mouse support, and easier navigation. Press F6 to sort, F9 to send signals.

Watching Resource Usage Over Time

For longer monitoring, you can log resource usage to a file:

$ while kill -0 12345 2>/dev/null; do
  ps -p 12345 -o %cpu,%mem,etime | tail -1 >> monitor.log
  sleep 5
done

6. Check Disk Usage

The problem: You need to know how much disk space is used, how much is free, and what is taking up the most space.

Step 1: Check Overall Disk Space with df

$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G   35G   13G  73% /
/dev/sda2       200G  120G   70G  63% /home
tmpfs           3.9G  1.2M  3.9G   1% /tmp

Key flags:

  • -h — human-readable sizes
  • -T — also shows filesystem type (ext4, xfs, etc.)

Step 2: Find What is Using Space with du

$ du -sh /home/user/*
1.8G    /home/user/Videos
650M    /home/user/.cache
420M    /home/user/Downloads
180M    /home/user/Documents
50M     /home/user/Pictures
$ du -sh /home/user/* | sort -rh
1.8G    /home/user/Videos
650M    /home/user/.cache
420M    /home/user/Downloads
...

Step 3: Drill Down with ncdu

$ ncdu /home/user

This opens an interactive disk usage browser. Navigate with arrow keys, press Enter to drill into directories, d to delete, q to quit.

Step 4: Find Large Files Specifically

$ find / -type f -size +500M 2>/dev/null
/var/log/large-application.log
/home/user/Videos/tutorial.mp4

The 2>/dev/null suppresses "permission denied" errors from directories you cannot read.

Step 5: Check Inode Usage

Sometimes you run out of inodes (too many small files) even if you have free space:

$ df -i
Filesystem      Inodes  IUsed   IFree IUse% Mounted on
/dev/sda1      3276800 250000 3026800    8% /
Quick Summary Command

A one-liner to see the biggest directories under your current path:

$ du -h --max-depth=1 | sort -rh | head -15

7. Download Files from the Terminal

The problem: You need to download a file from the internet — a software package, a dataset, an image — and you only have a terminal.

Method 1: wget

$ wget https://example.com/file.tar.gz
--2025-03-15 10:30:00--  https://example.com/file.tar.gz
Saving to: 'file.tar.gz'
file.tar.gz         100%[==================>]  25.3M  5.20MB/s  in 4.9s
2025-03-15 10:30:05 (5.20 MB/s) - 'file.tar.gz' saved [26,542,080]

Save with a custom filename:

$ wget -O myfile.tar.gz https://example.com/file.tar.gz

Resume a partially downloaded file:

$ wget -c https://example.com/large-file.iso

Download an entire directory listing:

$ wget -r -np -l 1 https://example.com/files/

Method 2: curl

$ curl -O https://example.com/file.tar.gz        # Save with original name
$ curl -o myfile.tar.gz https://example.com/file.tar.gz  # Custom name
$ curl -C - -O https://example.com/large.iso      # Resume download

Download Multiple Files

$ wget -i urls.txt      # Download all URLs listed in a file

Or with a loop:

$ for url in https://example.com/file{1..5}.txt; do wget "$url"; done

Download in the Background

$ wget -b https://example.com/huge-file.iso
Continuing in background, pid 12345.
Output will be written to 'wget-log'.
wget vs curl Quick Reference

wget is ideal for downloading files (especially recursively). curl is better for APIs and supports more protocols. Both can resume downloads. See Chapter 15 for a detailed comparison.

8. SSH into a Remote Server

The problem: You need to connect to a remote machine to administer it, deploy code, or troubleshoot. SSH (Secure Shell) is the standard tool for this.

Step 1: Generate SSH Keys (One-Time Setup)

$ ssh-keygen -t ed25519 -C "your_email@example.com"
Generating public/private ed25519 key pair.
Enter file in which to save the key (/home/user/.ssh/id_ed25519):
Enter passphrase (empty for no passphrase):
Your identification has been saved in /home/user/.ssh/id_ed25519
Your public key has been saved in /home/user/.ssh/id_ed25519.pub
Tip

Always set a passphrase for your SSH key. It adds a layer of security so that even if someone steals your private key file, they cannot use it without the passphrase.

Step 2: Copy Your Public Key to the Server

$ ssh-copy-id user@192.168.1.100
/usr/bin/ssh-copy-id: INFO: attempting to log in with the new key(s)
Number of key(s) added: 1
Now try logging into the machine.

This copies your public key to ~/.ssh/authorized_keys on the remote server.

Step 3: Connect

$ ssh user@192.168.1.100
Welcome to Ubuntu 22.04.3 LTS
Last login: Sat Mar 15 09:00:00 2025 from 192.168.1.50
user@server:~$

Step 4: Connect on a Non-Standard Port

$ ssh -p 2222 user@192.168.1.100

Step 5: Run a Command Without Interactive Login

$ ssh user@192.168.1.100 "df -h"
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G   35G   13G  73% /

Step 6: Set Up an SSH Config File

Create or edit ~/.ssh/config:

Host myserver
    HostName 192.168.1.100
    User admin
    Port 2222
    IdentityFile ~/.ssh/id_ed25519

Now you can connect with just:

$ ssh myserver
Security Reminder

Never share your private key (id_ed25519). Only share the public key (id_ed25519.pub). Set permissions correctly: chmod 700 ~/.ssh and chmod 600 ~/.ssh/id_ed25519.

9. Transfer Files Securely

The problem: You need to move files between your local machine and a remote server, or between two servers, securely.

Method 1: scp (Secure Copy)

Copy a local file to a remote server:

$ scp report.txt user@server:/home/user/documents/
report.txt                           100%   25KB  2.5MB/s   00:00

Copy a remote file to your local machine:

$ scp user@server:/var/log/app.log ./local-copy.log

Copy an entire directory:

$ scp -r /home/user/project/ user@server:/home/user/backup/

Method 2: rsync (Recommended)

rsync is smarter than scp — it only copies files that have changed, can resume interrupted transfers, and shows progress.

Sync a local directory to a remote server:

$ rsync -avz /home/user/project/ user@server:/home/user/project/
sending incremental file list
./
src/main.py
src/utils.py
README.md

sent 15,234 bytes  received 345 bytes  10,386.00 bytes/sec
total size is 125,000  speedup is 8.02

Flags explained:

  • -a — archive mode (preserves permissions, timestamps, symlinks, etc.)
  • -v — verbose output
  • -z — compress data during transfer

Sync from remote to local:

$ rsync -avz user@server:/home/user/project/ /home/user/local-copy/

Dry run first to see what would be transferred:

$ rsync -avz --dry-run /home/user/project/ user@server:/backup/

Exclude certain files:

$ rsync -avz --exclude='.git' --exclude='node_modules' /project/ user@server:/project/
Trailing Slash Matters with rsync

rsync src/ dest/ copies the contents of src into dest. rsync src dest/ (no trailing slash on src) copies the src directory itself into dest, creating dest/src/. This is a common gotcha.

10. Find Text Inside Many Files

The problem: You know a string appears somewhere in your project files, but you do not know which file. You need to search the contents of many files at once.

Method 1: grep -r (Recursive)

$ grep -r "TODO" /home/user/project/
/home/user/project/src/main.py:# TODO: refactor this function
/home/user/project/src/utils.py:# TODO: add error handling
/home/user/project/README.md:- TODO: write installation docs

With line numbers and color:

$ grep -rn --color "TODO" /home/user/project/

Limit to specific file types:

$ grep -rn --include="*.py" "import os" /home/user/project/

Exclude directories:

$ grep -rn --exclude-dir=".git" --exclude-dir="node_modules" "config" /project/

Method 2: find + grep

$ find /project -name "*.py" -exec grep -l "import os" {} \;
/project/src/main.py
/project/src/utils.py

The -l flag shows only filenames, not the matching lines.

Method 3: ripgrep (rg) for Speed

If you install ripgrep, it is significantly faster than grep for large codebases:

$ rg "TODO" /home/user/project/
src/main.py
3:# TODO: refactor this function

src/utils.py
15:# TODO: add error handling

rg automatically ignores .git, node_modules, and files listed in .gitignore. Install with sudo apt install ripgrep.

Tip

When searching a large codebase, always exclude version control and dependency directories. This dramatically reduces search time and noise.

11. Combine grep + find + xargs

The problem: You need to perform complex searches or operations on files that match certain criteria. The combination of find, grep, and xargs is one of the most powerful patterns in Linux.

The Power Trio

find selects files by name, size, date, or type. grep searches within file contents. xargs takes input from a pipe and passes it as arguments to another command. Together, they can do almost anything.

Example 1: Find Python Files Containing "TODO"

$ find /project -name "*.py" | xargs grep -l "TODO"
/project/src/main.py
/project/tests/test_utils.py

Example 2: Count Lines of Code in All JavaScript Files

$ find /project -name "*.js" -not -path "*/node_modules/*" | xargs wc -l
   120 /project/src/app.js
    85 /project/src/utils.js
    45 /project/src/config.js
   250 total

Example 3: Delete All .tmp Files Older Than 7 Days

$ find /tmp -name "*.tmp" -mtime +7 -print | xargs rm -v
removed '/tmp/session_abc123.tmp'
removed '/tmp/upload_def456.tmp'
Handle Filenames with Spaces

If filenames contain spaces, use null-terminated strings to avoid breaking:

$ find /project -name "*.txt" -print0 | xargs -0 grep "pattern"

The -print0 and -0 flags use null bytes instead of newlines as delimiters.

Example 4: Replace Text in All Config Files

$ find /etc/myapp -name "*.conf" | xargs sed -i 's/old_server/new_server/g'

Example 5: Find Files Modified Today and Archive Them

$ find /project -type f -mtime 0 -print0 | xargs -0 tar -czf today-changes.tar.gz

Example 6: Find and Chmod Specific Files

$ find /project -name "*.sh" | xargs chmod +x

Example 7: List Files Larger Than 10MB and Show Their Sizes

$ find / -type f -size +10M -print0 2>/dev/null | xargs -0 ls -lh | sort -k5 -rh | head -20

Example 8: Search and Replace Across an Entire Project

$ grep -rl "old_function" /project/src/ | xargs sed -i 's/old_function/new_function/g'

This first finds all files containing "old_function" (using grep -rl), then replaces the text in each of those files.

Example 9: Find Empty Files and Directories

$ find /project -empty -type f    # Empty files
$ find /project -empty -type d    # Empty directories

Example 10: Parallel Execution with xargs

$ find /images -name "*.png" -print0 | xargs -0 -P 4 -I {} convert {} -resize 50% {}

The -P 4 flag runs up to 4 processes in parallel, speeding up the operation significantly.

12. Use Pipes Effectively

The problem: You want to chain commands together so the output of one becomes the input of the next. Pipes (|) are the fundamental building blocks of Linux command-line power.

How Pipes Work

The pipe character | takes the standard output (stdout) of the command on the left and feeds it as standard input (stdin) to the command on the right. You can chain as many pipes as you need.

Pipe Chain 1: Find the Most Common Error

$ grep "ERROR" /var/log/app.log | awk '{print $5}' | sort | uniq -c | sort -rn | head -5
    142 ConnectionTimeout
     87 FileNotFound
     34 PermissionDenied
     12 OutOfMemory
      5 DiskFull

Pipe Chain 2: List Users Currently Logged In (Unique)

$ who | awk '{print $1}' | sort -u
admin
deploy
root

Pipe Chain 3: Show the 10 Largest Installed Packages

$ dpkg-query -W -f='${Installed-Size}\t${Package}\n' | sort -rn | head -10
512000  linux-firmware
125000  chromium-browser
 98000  libreoffice-core
...

Pipe Chain 4: Count Files by Extension

$ find /project -type f | sed 's/.*\.//' | sort | uniq -c | sort -rn | head -10
    234 py
    156 js
     89 html
     67 css
     45 json
     23 md

Pipe Chain 5: Find Processes Using the Most Memory

$ ps aux --sort=-%mem | head -11
USER       PID %CPU %MEM    VSZ   RSS TTY   STAT START   TIME COMMAND
mysql     1234  2.3 15.2 2048000 312000 ?   Sl   10:00  0:45 /usr/sbin/mysqld
www-data  5678  1.1  8.5 1024000 174000 ?   Sl   10:00  0:20 apache2

Pipe Chain 6: Extract Unique IP Addresses from a Log

$ grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' /var/log/auth.log | sort -u
10.0.0.1
192.168.1.50
203.0.113.42

Pipe Chain 7: Show Directory Sizes Sorted

$ du -h --max-depth=1 /home/user | sort -rh
4.2G    /home/user
1.8G    /home/user/Videos
650M    /home/user/.cache
420M    /home/user/Downloads

Pipe Chain 8: Find Duplicate Lines in a File

$ sort data.txt | uniq -d
duplicate line 1
duplicate line 2

Pipe Chain 9: Monitor Network Connections

$ ss -tun | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn | head -10
     15 192.168.1.50
      8 10.0.0.1
      3 203.0.113.42

Pipe Chain 10: Generate a Simple Report

$ echo "=== Server Report ===" && date && echo "---" && uptime && echo "---" && df -h / | tail -1 && echo "---" && free -h | grep Mem
=== Server Report ===
Sat Mar 15 10:30:00 UTC 2025
---
 10:30:00 up 45 days,  3:22,  2 users,  load average: 0.15, 0.20, 0.18
---
/dev/sda1        50G   35G   13G  73% /
---
Mem:           7.8Gi  3.2Gi  2.1Gi  0.0Ki  2.5Gi  4.3Gi
Debugging Pipes

If a long pipe chain is not producing what you expect, build it up one stage at a time. Start with the first command, verify its output, then add the next pipe, and so on.

13. Backup a Folder

The problem: You want to create a backup of a directory — either a one-time snapshot or an incremental backup — with timestamps so you know when each backup was made.

Method 1: tar with Timestamp

$ tar -czf "backup_$(date +%Y%m%d_%H%M%S).tar.gz" /home/user/project/
tar: Removing leading '/' from member names

This creates a file like backup_20250315_103000.tar.gz. Each backup has a unique name based on the date and time.

To verify the backup contents:

$ tar -tzf backup_20250315_103000.tar.gz | head -10
home/user/project/
home/user/project/src/
home/user/project/src/main.py
home/user/project/README.md
...

Method 2: rsync (Incremental Backup)

$ rsync -av --delete /home/user/project/ /backup/project/
sending incremental file list
deleting old-file.txt
./
src/new-feature.py

sent 15,234 bytes  received 345 bytes  31,158.00 bytes/sec
total size is 125,000  speedup is 8.02

Flags:

  • -a — archive mode (preserves everything)
  • -v — verbose
  • --delete — remove files in the destination that no longer exist in the source (makes it a true mirror)

Method 3: cp -a (Simple Copy)

$ cp -a /home/user/project/ "/backup/project_$(date +%Y%m%d)/"

The -a flag preserves all attributes (permissions, timestamps, symlinks). This is a full copy every time, so it uses more space than rsync.

Method 4: Rotating Backups Script

#!/bin/bash
# backup.sh - Create timestamped backup, keep last 5

BACKUP_DIR="/backup"
SOURCE="/home/user/project"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
BACKUP_NAME="project_${TIMESTAMP}.tar.gz"

# Create backup
tar -czf "${BACKUP_DIR}/${BACKUP_NAME}" "$SOURCE"

# Remove old backups, keep last 5
cd "$BACKUP_DIR"
ls -t project_*.tar.gz | tail -n +6 | xargs rm -f

echo "Backup created: ${BACKUP_NAME}"
echo "Remaining backups:"
ls -lh project_*.tar.gz

Method 5: Rsync with Dated Snapshots

$ rsync -av /home/user/project/ "/backup/$(date +%Y%m%d)_project/"

This creates a full copy in a date-stamped folder each time you run it.

Best Practice

Always verify your backup after creating it. Try listing contents (tar -tzf) or restoring to a test location. A backup you cannot restore from is not a backup.

Automating Backups

Use cron to schedule regular backups. Edit your crontab with crontab -e and add:

# Run backup every day at 2:00 AM
0 2 * * * /home/user/scripts/backup.sh >> /var/log/backup.log 2>&1
