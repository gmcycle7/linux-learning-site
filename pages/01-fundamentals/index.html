Chapter 1: Linux Fundamentals

Welcome to the very first chapter of the Linux Learning Guide. Before you type a single command, it is essential to understand what Linux actually is, how it is structured, and why millions of developers, companies, and devices rely on it every day. This chapter builds the mental foundation you will use throughout every subsequent lesson.

No prior experience required. This chapter assumes you have never used Linux before. Every concept is explained from scratch with analogies, diagrams, and examples.

1.1 What is Linux?

Linux is an operating system — the foundational software that sits between you and your computer's hardware. Just as Windows runs your PC or macOS runs your Mac, Linux runs computers too. But Linux is fundamentally different in one crucial way: it is completely free and open source. Anyone in the world can view, modify, and distribute its source code.

Mental Model: The Restaurant Analogy

Think of your computer as a restaurant:

  • The hardware (CPU, RAM, disk) is the kitchen — where the real work happens.
  • The operating system (Linux) is the manager — it takes your orders, tells the kitchen what to cook, and brings the food back to you.
  • Applications (web browser, text editor) are the menu items — the things you actually want.
  • You are the customer — you give orders and receive results.

Without the manager (operating system), the kitchen has no idea what to cook and you cannot get your food. Linux is that manager.

Why Does Linux Matter?

Linux is not just "another operating system." It runs an extraordinary share of the world's computing infrastructure:

  • Servers: Over 90% of the world's top 500 supercomputers run Linux. Most web servers (including the ones that power Google, Amazon, Facebook, and Netflix) run Linux.
  • Mobile Phones: Android, the most popular mobile operating system on Earth, is built on the Linux kernel.
  • Cloud Computing: The vast majority of cloud instances on AWS, Google Cloud, and Azure run Linux.
  • IoT & Embedded Devices: Smart TVs, routers, refrigerators, cars, and even Mars rovers use Linux.
  • Development: Most software developers use Linux as their primary development environment, either directly or through tools like WSL (Windows Subsystem for Linux).
Career tip: Knowing Linux is one of the most valuable skills in tech. Nearly every DevOps, system administration, cloud engineering, and backend development role requires Linux knowledge.

A Brief History

In 1991, a Finnish university student named Linus Torvalds started building a free operating system kernel as a hobby project. He posted a now-famous message to a Usenet newsgroup:

"I'm doing a (free) operating system (just a hobby, won't be big and professional like GNU) for 386(486) AT clones."

That "hobby" became Linux, and it grew thanks to thousands of contributors worldwide. Combined with the GNU project (which provided essential tools like compilers, shells, and utilities), it became a fully functional operating system often referred to as GNU/Linux.

Open Source: What Does It Mean?

When software is open source, its source code is publicly available. Anyone can:

  1. Read the code to understand exactly what the software does.
  2. Modify it to fix bugs or add features.
  3. Distribute their modified version to others.
  4. Use it for any purpose, including commercial use, at no cost.

This is in contrast to proprietary (closed-source) software like Windows or macOS, where the source code is secret and controlled by a single company.

1.2 Linux Distributions

Unlike Windows, which comes in a single flavor from Microsoft, Linux comes in many different distributions (commonly called distros). A distribution is a complete operating system built around the Linux kernel, bundled with a package manager, desktop environment, and a curated set of software.

Mental Model: Ice Cream Flavors

Think of the Linux kernel as the base ice cream. A distribution is a flavor — vanilla, chocolate, strawberry — each made from the same base but with different toppings, sweetness levels, and target audiences. Ubuntu is like a crowd-pleasing vanilla: easy, popular, and widely available. Arch Linux is like an exotic, DIY flavor: you assemble it yourself and customize every ingredient.

Popular Distributions

Distribution Based On Difficulty Package Manager Best For
Ubuntu Debian Beginner apt Desktops, servers, learning Linux
Linux Mint Ubuntu Beginner apt Windows switchers, everyday desktop use
Debian — (independent) Intermediate apt Stability-focused servers, advanced desktops
Fedora — (independent) Intermediate dnf Developers who want cutting-edge software
CentOS / Rocky / Alma RHEL Intermediate dnf / yum Enterprise servers, production workloads
Arch Linux — (independent) Advanced pacman Power users who want full control
openSUSE — (independent) Intermediate zypper System administrators, enterprise environments
Kali Linux Debian Advanced apt Penetration testing, security research
Recommendation for beginners: Start with Ubuntu or Linux Mint. They have the largest communities, the most tutorials, and the friendliest installation process. You can always switch later once you are comfortable.

Distribution Families

Most distributions belong to one of three major families, which determines their package manager and general philosophy:

  • Debian family (uses apt / .deb packages): Debian, Ubuntu, Linux Mint, Pop!_OS, Kali Linux
  • Red Hat family (uses dnf or yum / .rpm packages): RHEL, CentOS, Rocky Linux, Fedora, AlmaLinux
  • Arch family (uses pacman): Arch Linux, Manjaro, EndeavourOS

Knowing which family your distro belongs to is important because commands for installing software, managing services, and configuring the system can differ between families.

1.3 Kernel vs Shell vs Terminal

Three terms that beginners often confuse are kernel, shell, and terminal. They are related but serve entirely different roles. Understanding the distinction will help you reason about everything that follows in this guide.

The Kernel

The kernel is the absolute core of the Linux operating system. It is the first program loaded when you boot your computer, and it remains running until you shut down. The kernel has four primary responsibilities:

  1. Process management: Deciding which programs get CPU time and when.
  2. Memory management: Allocating RAM to programs and reclaiming it when they finish.
  3. Device management: Communicating with hardware (disks, network cards, USB devices) through drivers.
  4. File system management: Organizing data on disks into files and directories.

You almost never interact with the kernel directly. Instead, you use programs (like the shell) that make requests to the kernel on your behalf through system calls.

# Check your kernel version
$ uname -r
5.15.0-91-generic

# See detailed kernel information
$ uname -a
Linux myhost 5.15.0-91-generic #101-Ubuntu SMP x86_64 GNU/Linux

The Shell

The shell is a program that reads the commands you type, interprets them, and executes them. It is your primary interface to the operating system. The shell is not the window you see on screen — it is the invisible interpreter running inside that window.

Common shells include:

  • bash (Bourne Again Shell) — the default on most Linux distributions. This is the shell we use throughout this guide.
  • zsh (Z Shell) — the default on macOS since Catalina. Popular for its advanced features and plugins (Oh My Zsh).
  • fish (Friendly Interactive Shell) — known for user-friendly features like auto-suggestions and syntax highlighting out of the box.
  • sh (Bourne Shell) — the original Unix shell. Very minimal.
  • dash — a lightweight POSIX shell often used for system scripts.
# Which shell are you currently using?
$ echo $SHELL
/bin/bash

# List all available shells on your system
$ cat /etc/shells
/bin/sh
/bin/bash
/usr/bin/bash
/bin/zsh
/usr/bin/zsh

The Terminal (Terminal Emulator)

The terminal emulator is the graphical window (application) that you open on your desktop to access the shell. It draws the text on your screen, handles your keyboard input, and sends it to the shell running inside it.

Popular terminal emulators include:

  • GNOME Terminal — default on Ubuntu and many GNOME-based distros.
  • Konsole — default on KDE-based distros.
  • xterm — one of the oldest terminal emulators.
  • Alacritty — a modern, GPU-accelerated terminal.
  • Windows Terminal — used with WSL on Windows.
  • iTerm2 — popular on macOS.
Key distinction: The terminal is the window. The shell is the program running inside the window. You can run different shells inside the same terminal, and you can run the same shell inside different terminals.

1.4 The Linux Filesystem Hierarchy

In Windows, you have drives like C:\, D:\, etc. Linux does things very differently. There is a single root directory called / (just a forward slash), and everything in the system lives under it — all files, all devices, all mounted drives. This unified structure is called the Filesystem Hierarchy Standard (FHS).

Mental Model: The Upside-Down Tree

Think of the Linux filesystem as an upside-down tree. The root (/) is at the top, and branches (directories) extend downward. Every file and folder on the entire system is a "leaf" or "branch" hanging from this single root.

                              /                         (root - the trunk)
            __________________|__________________
           |     |     |     |     |     |      |
         /bin  /etc  /home  /usr  /var  /tmp  /dev
                       |            |     |
                    /home/         /usr/ /var/
                    alice          |     |
                    bob          /usr/  /var/log
                                 bin    /var/www
                                 lib
                                 share

Key Directories Explained

Directory Name Purpose
/ Root The top-level directory. Everything on the system is under /. Do not confuse this with /root (the root user's home directory).
/home Home Contains personal directories for each user. For example, user "alice" has /home/alice. This is where your documents, downloads, and personal configuration files live.
/etc Et cetera / Configuration System-wide configuration files. Hostname settings, network configuration, user accounts, service configurations — all live here. Example: /etc/hostname, /etc/passwd.
/var Variable Data that changes frequently at runtime: log files (/var/log), mail spools, web server content (/var/www), database files, caches.
/usr Unix System Resources User-installed programs, libraries, and documentation. /usr/bin holds most user commands. /usr/lib holds libraries. /usr/share holds architecture-independent data.
/tmp Temporary Temporary files that may be deleted on reboot. Any user can write here. Programs use it for scratch space.
/bin Binaries Essential command binaries available to all users: ls, cp, mv, cat, bash. On modern systems, often a symlink to /usr/bin.
/sbin System Binaries Essential system administration commands: fdisk, iptables, reboot. Usually requires root privileges to use.
/opt Optional Third-party software that doesn't follow the standard directory layout. Commercial software, custom-compiled applications, and some large packages install here.
/dev Devices Special files that represent hardware devices. /dev/sda is your first hard disk. /dev/null is a "black hole" that discards anything written to it. In Linux, everything is a file, including devices.
/proc Process Information A virtual filesystem that provides information about running processes and the kernel. /proc/cpuinfo shows CPU details. /proc/meminfo shows memory usage. These files don't actually exist on disk.
/root Root Home The home directory of the root (superuser) account. Not to be confused with / (the root of the filesystem).
/boot Boot Files needed to start the system: the Linux kernel image, bootloader configuration (GRUB), and initial RAM disk.
/lib Libraries Shared libraries needed by programs in /bin and /sbin. On modern systems, often a symlink to /usr/lib.
/mnt Mount Temporary mount point for manually mounting filesystems (e.g., a USB drive).
/media Media Auto-mount point for removable media like USB drives and CDs.
Important: Never randomly modify files under /etc, /bin, /sbin, or /boot unless you understand exactly what you are doing. Incorrect changes to system configuration files can make your system unbootable.

1.5 Absolute vs Relative Paths

Every file and directory in Linux has an address called a path. There are two ways to specify a path:

Mental Model: Home Address vs Directions

An absolute path is like a full street address: "123 Main Street, Springfield, IL, USA." No matter where you are in the world, that address takes you to the same place.

A relative path is like giving directions from where you currently stand: "Go two blocks north, then turn left." The destination depends on where you start from.

Absolute Paths

An absolute path always starts with / (the root directory). It specifies the complete route from the very top of the filesystem to the target file or directory. Absolute paths are unambiguous — they work the same no matter where you currently are.

# Absolute paths always start with /
/home/alice/documents/report.txt
/etc/nginx/nginx.conf
/var/log/syslog
/usr/bin/python3
/tmp/scratch.txt

Relative Paths

A relative path does not start with /. It is interpreted relative to your current working directory (the directory you are currently "in"). Two special symbols are crucial:

  • . (single dot) — refers to the current directory.
  • .. (double dot) — refers to the parent directory (one level up).

Examples: Seeing Both in Action

# First, let's see where we are
$ pwd
/home/alice

# --- ABSOLUTE PATH EXAMPLES ---

# Go to an absolute path (works from anywhere)
$ cd /var/log

# List files using an absolute path
$ ls /home/alice/documents

# Copy a file using absolute paths
$ cp /home/alice/notes.txt /tmp/notes-backup.txt

# --- RELATIVE PATH EXAMPLES ---

# Assume we are in /home/alice
$ pwd
/home/alice

# Go into a subdirectory (relative)
$ cd documents
$ pwd
/home/alice/documents

# Go up one level (parent directory)
$ cd ..
$ pwd
/home/alice

# Go up two levels
$ cd ../..
$ pwd
/

# Reference a file in the current directory
$ cat ./notes.txt

# Reference a file in a sibling directory
# (If you are in /home/alice/documents, go up, then into pictures)
$ ls ../pictures

# Chain relative paths
$ cat ../bob/shared/readme.txt

Comparison Table

Current Directory Target Absolute Path Relative Path
/home/alice alice's documents folder /home/alice/documents documents or ./documents
/home/alice/documents alice's home directory /home/alice ..
/home/alice bob's home directory /home/bob ../bob
/var/log the syslog file /var/log/syslog syslog or ./syslog
/home/alice/documents the system log /var/log/syslog ../../../var/log/syslog
/usr/bin the /etc directory /etc ../../etc
/ the tmp directory /tmp tmp or ./tmp
/home/alice/pictures a file in documents /home/alice/documents/file.txt ../documents/file.txt
Common mistake: Typing cd home/alice when you mean cd /home/alice. Without the leading /, the shell looks for a directory named "home" inside your current directory, which probably does not exist. Always be conscious of whether you need an absolute or relative path.
When to use which? Use absolute paths in scripts and configuration files (so they work regardless of where the script is run). Use relative paths for quick navigation when you are working interactively in the terminal.

1.6 Hidden Files and Directories

In Linux, any file or directory whose name begins with a dot (.) is considered hidden. Hidden files are not shown by default when you list the contents of a directory with ls. They are commonly used for configuration files and application data that you don't need to see day-to-day.

# Normal ls does NOT show hidden files
$ ls
documents  downloads  pictures  videos

# Use -a (all) to see hidden files too
$ ls -a
.  ..  .bashrc  .profile  .ssh  .config  .local  documents  downloads  pictures  videos

# Use -la for a detailed list including hidden files
$ ls -la
total 48
drwxr-xr-x  8 alice alice 4096 Jan 15 10:30 .
drwxr-xr-x  4 root  root  4096 Jan 10 08:00 ..
-rw-r--r--  1 alice alice  220 Jan 10 08:00 .bash_logout
-rw-r--r--  1 alice alice 3771 Jan 10 08:00 .bashrc
drwx------  2 alice alice 4096 Jan 12 14:20 .ssh
drwxr-xr-x  3 alice alice 4096 Jan 13 09:15 .config
-rw-r--r--  1 alice alice  807 Jan 10 08:00 .profile
drwxr-xr-x  2 alice alice 4096 Jan 15 10:30 documents
drwxr-xr-x  2 alice alice 4096 Jan 14 16:00 downloads
drwxr-xr-x  2 alice alice 4096 Jan 13 12:00 pictures
drwxr-xr-x  2 alice alice 4096 Jan 11 20:00 videos

Common Hidden Files and Directories

File / Directory Purpose
.bashrc Bash shell configuration. Runs every time you open a new terminal. Used to set aliases, environment variables, and customize your prompt.
.bash_profile Runs once when you log in (login shells). Often sources .bashrc.
.bash_logout Runs when you log out of a login shell. Used for cleanup tasks.
.profile General login profile used by many shells, not just bash.
.bash_history A record of every command you have typed. Be careful — it may contain sensitive information.
.ssh/ Contains your SSH keys (id_rsa, id_ed25519), known hosts, and SSH configuration. Never share your private keys.
.config/ Application-specific configuration files (following the XDG Base Directory specification).
.local/ User-specific data files, including installed packages (.local/bin) and application data (.local/share).
.gitconfig Git version control configuration (username, email, aliases).
.vimrc Configuration file for the Vim text editor.
Tip: To create a hidden file or directory, simply start its name with a dot: touch .my-secret-file or mkdir .my-hidden-dir. To "unhide" it, rename it to remove the leading dot.
Security warning: Never share or commit your .ssh/ private keys, .bash_history, or any file containing passwords or API tokens. Hidden does not mean secure — it just means "not shown by default."

1.7 Environment Variables

Environment variables are named values stored in your shell session that programs can read to configure their behavior. They are one of the primary ways Linux passes configuration to programs. Think of them as global settings for your terminal session.

Mental Model: Name Tags

Imagine every environment variable is a name tag pinned to a bulletin board. The tag says something like HOME = /home/alice. Any program that needs to know where your home directory is can look at the bulletin board and read that tag. You can add new tags, change existing ones, or remove them.

Viewing Environment Variables

# Print a specific variable with echo and $
$ echo $HOME
/home/alice

$ echo $USER
alice

$ echo $SHELL
/bin/bash

$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

$ echo $PWD
/home/alice

$ echo $HOSTNAME
myserver

$ echo $LANG
en_US.UTF-8

$ echo $TERM
xterm-256color

# List ALL environment variables
$ env
HOME=/home/alice
USER=alice
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
LANG=en_US.UTF-8
TERM=xterm-256color
... (many more)

# Another way to see all variables (including shell variables)
$ printenv

Important Environment Variables

Variable Meaning Example Value
$HOME Your home directory /home/alice
$USER Your username alice
$SHELL Your default shell /bin/bash
$PATH Directories the shell searches for commands (colon-separated) /usr/local/bin:/usr/bin:/bin
$PWD Present working directory /home/alice/documents
$OLDPWD Previous working directory (used by cd -) /home/alice
$EDITOR Default text editor nano or vim
$LANG System locale (language/encoding) en_US.UTF-8
$HOSTNAME The machine's hostname webserver01
$TERM Terminal type xterm-256color

Setting Environment Variables

# Set a variable for the current session only
$ MY_NAME="Alice"
$ echo $MY_NAME
Alice

# Export it so child processes (programs you run) can see it
$ export MY_NAME="Alice"

# Set and export in one step
$ export PROJECT_DIR="/home/alice/projects/webapp"

# Unset (remove) a variable
$ unset MY_NAME
$ echo $MY_NAME
(empty - nothing printed)

The PATH Variable (Critical Concept)

The $PATH variable is arguably the most important environment variable. When you type a command like python3, the shell does not magically know where the program lives. Instead, it searches through each directory listed in $PATH (from left to right) until it finds a matching executable.

$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

# The shell searches these directories, in order:
# 1. /usr/local/sbin
# 2. /usr/local/bin
# 3. /usr/sbin
# 4. /usr/bin
# 5. /sbin
# 6. /bin

# Find which exact file runs when you type a command
$ which python3
/usr/bin/python3

$ which ls
/usr/bin/ls

# Add a new directory to PATH (e.g., your personal scripts folder)
$ export PATH="$HOME/bin:$PATH"
Making variables permanent: Variables set with export only last until you close the terminal. To make them permanent, add the export line to your ~/.bashrc file. We will cover this in detail in Chapter 12 (Shell & Scripting).

1.8 The Home Directory

Every user on a Linux system has a home directory: a personal space for storing files, configurations, and data. It is the directory you land in when you first open a terminal or log in via SSH.

Three Ways to Reference Home

Notation Type Example (for user alice)
~ Tilde shortcut (shell expansion) ~ expands to /home/alice
$HOME Environment variable $HOME evaluates to /home/alice
/home/alice Absolute path The literal full path 
# All three take you to the same place
$ cd ~
$ cd $HOME
$ cd /home/alice

# Just "cd" with no arguments also goes home!
$ cd
$ pwd
/home/alice

# Use ~ in paths
$ ls ~/documents
report.txt  notes.txt  budget.xlsx

# Copy a file to your home directory
$ cp /tmp/data.csv ~/

# Reference another user's home directory
$ ls ~bob
(shows bob's home directory, if you have permission)
Convention: Normal users have home directories under /home/username. The root user's home directory is /root (not /home/root). This is a deliberate design choice to keep the root account separate.

What Lives in Your Home Directory?

Your home directory typically contains:

  • Personal files: Documents, downloads, pictures, videos, music.
  • Configuration files: Hidden files like .bashrc, .gitconfig, .ssh/.
  • Application data: .config/, .local/, browser profiles, editor settings.
  • Project directories: Code repositories, scripts, work files.

Your home directory is your personal space. You have full read/write permissions here. Other users cannot access your files unless you explicitly grant them permission (covered in Chapter 6: Permissions).

1.9 Root User vs Normal User

Linux has a strict permission model based on users and groups. The most important distinction is between normal users and the root user (also called the superuser).

Mental Model: Tenant vs Building Manager

Imagine a large apartment building:

  • A normal user is like a tenant. You have full access to your own apartment (home directory), but you cannot enter other apartments, rewire the building's electricity, or change the locks on the front door.
  • The root user is like the building manager. They have a master key that opens every door. They can enter any apartment, modify any system, install or remove anything. With great power comes great responsibility — a careless manager could accidentally flood the entire building.

How to Tell Which User You Are

The shell prompt itself tells you whether you are a normal user or root:

# Normal user prompt ends with $
alice@myhost:~$

# Root user prompt ends with #
root@myhost:~#
# Check your username
$ whoami
alice

# Check your user ID (UID) — root is always 0
$ id
uid=1000(alice) gid=1000(alice) groups=1000(alice),27(sudo)

Comparison: Normal User vs Root

Aspect Normal User Root User
UID 1000+ (typically) 0
Prompt symbol $ #
Home directory /home/username /root
Can install system packages No (needs sudo) Yes
Can modify system files No (needs sudo) Yes
Can create/delete users No (needs sudo) Yes
Can access all files Only own files + permitted files Every file on the system
Risk level Low (mistakes affect only your files) High (mistakes can destroy the system)

Using sudo (Superuser Do)

Instead of logging in as root (which is dangerous), Linux provides the sudo command. It lets an authorized normal user execute a single command with root privileges. After the command finishes, you return to your normal user context.

# This will fail as a normal user — permission denied
$ apt update
E: Could not open lock file /var/lib/apt/lists/lock - open (13: Permission denied)

# Use sudo to run it with root privileges
$ sudo apt update
[sudo] password for alice:
Hit:1 http://archive.ubuntu.com/ubuntu jammy InRelease
...
Reading package lists... Done

# Install a package (requires root)
$ sudo apt install htop

# Edit a system configuration file
$ sudo nano /etc/hostname

# Restart a service
$ sudo systemctl restart nginx

# Check who can use sudo on this system
$ sudo cat /etc/sudoers
DANGER: Never run everything as root. Working as the root user full-time is like walking through a china shop with a sledgehammer. A simple typo can have catastrophic consequences:
  • rm -rf / — deletes everything on your system. Unrecoverable.
  • chmod -R 777 / — makes every file on the system readable, writable, and executable by everyone. A massive security breach.
  • chown -R alice / — changes ownership of every file to alice, breaking system services.

Always use sudo for individual commands instead of logging in as root. This limits the blast radius of mistakes.

The "sudo" habit: Before typing sudo, ask yourself: "Do I actually need root privileges for this?" If you are editing your own files, navigating directories, or running personal scripts, you do not need sudo. Only use it for system-level actions like installing packages, modifying system configs, or managing services.

Switching to Root (When Necessary)

# Open a root shell (use sparingly)
$ sudo -i
root@myhost:~#

# Or using su (switch user)
$ su -
Password:
root@myhost:~#

# Exit root shell and return to normal user
root@myhost:~# exit
$

Quizzes

Quiz 1: Core Concepts

  1. What is the Linux kernel responsible for?

    1. Displaying the graphical desktop
    2. Managing hardware, memory, processes, and file systems
    3. Running web browsers and applications
    4. Providing a text-based command interface
    Show answer

    b) The kernel manages hardware, memory, processes, and file systems. It is the core of the operating system that sits between software and hardware.

  2. Which of these is an absolute path?

    1. documents/report.txt
    2. ./report.txt
    3. /home/alice/documents/report.txt
    4. ../alice/report.txt
    Show answer

    c) An absolute path always starts with / (the root directory). The others are all relative paths.

  3. What does the $PATH environment variable control?

    1. The file path you are currently in
    2. The list of directories the shell searches for executable commands
    3. The route network packets take to reach a server
    4. The directory where downloaded files are saved
    Show answer

    b) $PATH is a colon-separated list of directories. When you type a command, the shell searches each directory in $PATH (left to right) to find the executable.

  4. What does .. refer to in a file path?

    1. The current directory
    2. The home directory
    3. The root directory
    4. The parent directory (one level up)
    Show answer

    d) Two dots (..) always refer to the parent directory. One dot (.) refers to the current directory.

  5. Why should you NOT work as the root user all the time?

    1. Root is slower than a normal user
    2. Root does not have access to graphical applications
    3. A single mistake as root can damage or destroy the entire system
    4. Root cannot use the bash shell
    Show answer

    c) Root has unrestricted access. A typo in a command (like rm -rf /) can irreversibly destroy all data. Use sudo for individual commands instead.

Quiz 2: Practical Scenarios

  1. You are in /home/alice/documents and want to access /home/bob/shared/notes.txt. Which relative path is correct?

    1. bob/shared/notes.txt
    2. ../bob/shared/notes.txt
    3. ../../bob/shared/notes.txt
    4. ~/bob/shared/notes.txt
    Show answer

    c) From /home/alice/documents, go up to /home/alice (..), up to /home (../..), then down into bob/shared/notes.txt. Full relative path: ../../bob/shared/notes.txt.

  2. Which command reveals hidden files in your home directory?

    1. ls ~
    2. ls -l ~
    3. ls -a ~
    4. ls --hidden ~
    Show answer

    c) The -a flag shows all files, including hidden ones (those starting with a dot). The -l flag shows a long listing but still hides dot-files by default. There is no --hidden flag for ls.

  3. You see $ at the end of your prompt. What does this tell you?

    1. You are logged in as root
    2. You are logged in as a normal (non-root) user
    3. The system is running in safe mode
    4. The shell is waiting for a password
    Show answer

    b) A $ prompt indicates a normal user. A # prompt indicates the root user.

  4. Where do system-wide configuration files typically live?

    1. /home
    2. /tmp
    3. /etc
    4. /bin
    Show answer

    c) /etc is the standard location for system-wide configuration files (hostname, network settings, user accounts, service configurations, etc.).

  5. You want to install the htop package but get "Permission denied." What should you do?

    1. Log out and log back in
    2. Prefix the command with sudo: sudo apt install htop
    3. Change directory to /root
    4. Delete the lock file manually
    Show answer

    b) Installing system packages requires root privileges. Use sudo to elevate for that single command: sudo apt install htop.
