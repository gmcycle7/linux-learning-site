Chapter 4: Viewing & Editing Files

Now that you know how to create, move, copy, and delete files, it is time to look inside them. This chapter covers every essential command for reading file contents, paging through long output, editing text, and transforming data on the command line. These are skills you will use every single day.

What you will learn

How to display files with cat, page through them with less and more, peek at the beginning or end with head and tail, edit with nano and vim, count with wc, and transform text with sort, uniq, cut, paste, and tr.

Mental Model: Text Streams

In Linux, almost everything is text. Configuration files, log files, command output — all plain text. Data flows through commands like water through pipes. A command reads text from standard input (stdin), processes it, and writes the result to standard output (stdout).

Think of each command as a station on an assembly line. cat pours the file onto the line, sort arranges it, uniq removes duplicates, cut trims columns, and wc counts the result. You chain these stations together with the pipe symbol (|) to build powerful data pipelines — all without writing a single script.

file on disk  -->  cat  -->  sort  -->  uniq  -->  wc -l  -->  answer on screen

Keep this mental model in mind as you learn each command below. Every one of them reads a stream in and pushes a stream out.

1. cat — Display and Concatenate Files

cat (short for concatenate) is the simplest way to dump the contents of a file to the terminal. It reads one or more files and prints them sequentially to standard output. For short files it is perfect; for long files you will want less instead.

Syntax

cat [OPTIONS] [FILE...]

Common Flags

FlagDescription
-nNumber all output lines
-bNumber non-blank lines only
-sSqueeze multiple blank lines into one
-AShow all non-printing characters (equivalent to -vET)
-EDisplay $ at end of each line
-TShow tabs as ^I
-vShow non-printing characters using caret notation

Examples

$ cat greeting.txt
Hello, world!
Welcome to Linux.
$ cat -n greeting.txt
     1	Hello, world!
     2	Welcome to Linux.
$ cat file1.txt file2.txt
Contents of file1
Contents of file2
$ cat file1.txt file2.txt > combined.txt
$ cat combined.txt
Contents of file1
Contents of file2
$ cat -b notes.txt
     1	First line

     2	Third line (blank line above is not numbered)
$ cat -s messy.txt
Line one

Line four (three blanks squeezed to one)
$ cat -A config.txt
name=Alice$
path=/home/alice^I/docs$
$ cat -T Makefile
target:
^Igcc -o app main.c
$ cat <<EOF > newfile.txt
> Line one
> Line two
> EOF
$ cat newfile.txt
Line one
Line two
$ cat /dev/null > logfile.txt   # truncate a file to zero bytes

Common Mistakes

Wrong
$ cat hugefile.log          # floods terminal with 100,000 lines
Right
$ less hugefile.log          # page through it instead
Tip

Use cat for short files (under ~50 lines) or when piping into another command. For anything longer, reach for less.

2. less — Page Through Files

less is the go-to pager on Linux. It lets you scroll forward and backward through a file without loading the entire thing into memory. The name is a joke — "less is more" — because it replaced the older more command with far more features.

Syntax

less [OPTIONS] FILE

Common Flags

FlagDescription
-NShow line numbers
-SChop (don't wrap) long lines
-iCase-insensitive search
-FQuit if file fits on one screen
-RDisplay raw ANSI color codes
-XDon't clear screen on exit
+FFollow mode (like tail -f; press Ctrl+C to stop)
-p PATTERNStart at first match of PATTERN

Navigation Keys Inside less

KeyAction
Space or fForward one screen
bBackward one screen
dForward half screen
uBackward half screen
gGo to beginning of file
GGo to end of file
/patternSearch forward for pattern
?patternSearch backward for pattern
nNext search match
NPrevious search match
qQuit
&patternShow only lines matching pattern
vOpen current file in editor

Examples

$ less /var/log/syslog
$ less -N /etc/passwd          # with line numbers
$ less -S /var/log/access.log  # long lines chopped, scroll right with arrow
$ less -i /etc/hosts           # case-insensitive searching
$ dmesg | less                  # pipe command output into less
$ less +F /var/log/syslog      # follow mode, like tail -f
$ less -p "error" /var/log/syslog   # jump straight to first "error"
$ less -R colored_output.txt   # preserve ANSI colors
$ less file1.txt file2.txt     # view multiple files; :n next, :p previous
$ less -NRS /var/log/auth.log  # numbers + raw colors + chopped lines
Tip

Inside less, type &ERROR and press Enter to filter and show only lines containing "ERROR". Press & and Enter with no pattern to remove the filter.

3. more — The Older Pager

more is the original Unix pager. It can only scroll forward (not backward), has no search, and fewer features than less. It still ships with every Linux system and you may encounter it in minimal environments or old scripts.

Syntax

more [OPTIONS] FILE

Common Flags

FlagDescription
-dDisplay help prompt instead of ringing bell
-fCount logical lines (ignore line wrapping)
-sSqueeze multiple blank lines
+NUMStart display at line NUM
-NUMSet screen size to NUM lines

Examples

$ more /etc/services
$ more +100 /etc/services      # start at line 100
$ ls -la /usr/bin | more        # page through long listing
$ more -d /etc/passwd           # shows "[Press space to continue, 'q' to quit.]"
$ more -s log_with_blanks.txt   # squeeze blank lines
$ more -20 /etc/hosts           # show 20 lines at a time
$ cat README.md | more           # pipe into more
$ more file1.txt file2.txt      # view multiple files sequentially
Why less is better

less can scroll backward, search with /, does not load the whole file into memory, and supports many more keybindings. Unless you are on a minimal rescue system that only has more, always prefer less.

cat vs less vs head vs tail — Comparison

Feature cat less head tail
Shows entire fileYesYes (paged)NoNo
Scroll backwardNoYesN/AN/A
Search within fileNoYes (/)NoNo
Best for short filesYesOverkillFirst few linesLast few lines
Best for long filesNoYesPreview onlyPreview only
Follow live updatesNoYes (+F)NoYes (-f)
Good for pipingYesYesYesYes
Line numbers-n-N-n (count)-n (count)

4. head — View the First N Lines

head prints the first part of a file. By default it shows the first 10 lines, but you can change that with -n. It is perfect for quickly checking what a file looks like, inspecting CSV headers, or peeking at log files.

Syntax

head [OPTIONS] [FILE...]

Common Flags

FlagDescription
-n NUMPrint the first NUM lines (default 10)
-n -NUMPrint all lines except the last NUM lines
-c NUMPrint the first NUM bytes
-qNever print headers when given multiple files
-vAlways print headers

Examples

$ head /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
sync:x:4:65534:sync:/bin:/bin/sync
games:x:5:60:games:/usr/games:/usr/sbin/nologin
man:x:6:12:man:/var/cache/man:/usr/sbin/nologin
lp:x:7:7:lp:/var/spool/lpd:/usr/sbin/nologin
mail:x:8:8:mail:/var/mail:/usr/sbin/nologin
news:x:9:9:news:/var/spool/news:/usr/sbin/nologin
$ head -n 3 /etc/passwd
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
$ head -3 /etc/passwd          # shorthand, same as -n 3
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
$ head -c 20 /etc/passwd       # first 20 bytes
root:x:0:0:root:/ro
$ head -n 1 data.csv           # see just the header row
name,age,city,email
$ head -n -2 numbers.txt       # all lines except the last 2
one
two
three
$ head -v file1.txt file2.txt  # headers shown for each file
==> file1.txt <==
alpha
bravo

==> file2.txt <==
charlie
delta
$ ls -lt /var/log | head -5    # 5 most recently modified log files
total 5260
-rw-r----- 1 syslog adm  102400 Mar 31 08:12 auth.log
-rw-r----- 1 syslog adm   84321 Mar 31 08:10 syslog
-rw-r----- 1 syslog adm   55012 Mar 31 07:55 kern.log
-rw-r--r-- 1 root   root  31452 Mar 31 06:30 dpkg.log
Tip

Combine head and tail to extract a range. For example, lines 5-10: head -n 10 file | tail -n 6.

5. tail — View the Last N Lines

tail prints the last part of a file. By default it shows the last 10 lines. Its killer feature is -f (follow), which keeps watching the file and prints new lines as they appear — essential for monitoring log files in real time.

Syntax

tail [OPTIONS] [FILE...]

Common Flags

FlagDescription
-n NUMPrint the last NUM lines (default 10)
-n +NUMPrint starting from line NUM (skip first NUM-1 lines)
-c NUMPrint the last NUM bytes
-fFollow: keep watching for new lines (Ctrl+C to stop)
-FFollow and retry if file is rotated/replaced
--pid=PIDStop following after process PID dies
-qNever print headers

Examples

$ tail /var/log/syslog          # last 10 lines
$ tail -n 5 /var/log/syslog     # last 5 lines
Mar 31 08:10:01 server CRON[4521]: (root) CMD (test -x /usr/sbin/anacron)
Mar 31 08:10:12 server systemd[1]: Started Session 42 of user alice.
Mar 31 08:10:15 server sshd[4530]: Accepted publickey for alice
Mar 31 08:10:15 server sshd[4530]: pam_unix(sshd:session): session opened
Mar 31 08:10:16 server systemd-logind[812]: New session 42 of user alice.
$ tail -n +5 data.txt           # everything from line 5 onward
line 5
line 6
line 7
...
$ tail -f /var/log/auth.log     # follow live, Ctrl+C to stop
Mar 31 08:12:33 server sshd[4600]: Failed password for root from 192.168.1.50
Mar 31 08:12:35 server sshd[4600]: Failed password for root from 192.168.1.50
(new lines appear here in real time...)
$ tail -F /var/log/nginx/access.log   # follow even if file is rotated
$ tail -c 100 /var/log/syslog   # last 100 bytes
$ tail -f /var/log/syslog --pid=1234  # stop following when PID 1234 exits
$ tail -f log1.txt log2.txt     # follow two files at once
==> log1.txt <==
new line in log1

==> log2.txt <==
new line in log2
$ dmesg | tail -20               # last 20 kernel messages
$ head -n 20 file.txt | tail -n 5    # extract lines 16-20
line 16
line 17
line 18
line 19
line 20
Safe usage

tail -f will run forever until you press Ctrl+C. Don't forget to stop it when you're done, or it will hold your terminal hostage. Use --pid if you're watching a log tied to a specific process.

6. nano — Beginner-Friendly Text Editor

nano is the easiest terminal text editor. It shows a helpful shortcut bar at the bottom of the screen, works the way you expect (type to insert, arrow keys to move), and requires no mode-switching. If you are new to Linux, start with nano.

Syntax

nano [OPTIONS] [FILE]

Common Flags

FlagDescription
-BCreate backup of file before saving
-iAuto-indent new lines
-lShow line numbers
-mEnable mouse support
-cConstantly show cursor position
+LINEOpen file at a specific line number
-wDon't wrap long lines (important for config files)
-EConvert tabs to spaces

Keyboard Shortcuts

In nano's shortcut bar, ^ means Ctrl and M- means Alt.

ShortcutAction
Ctrl+OSave (Write Out) the file
Ctrl+XExit nano (prompts to save if unsaved changes)
Ctrl+KCut (delete) current line
Ctrl+UPaste (Uncut) previously cut text
Ctrl+WSearch for text
Ctrl+\Search and replace
Ctrl+GShow help
Ctrl+CShow current line/column/character position
Ctrl+_Go to a specific line number
Alt+UUndo
Alt+ERedo
Ctrl+AGo to beginning of line
Ctrl+EGo to end of line
Alt+AStart marking text (selection)
Alt+6Copy marked text

Examples

$ nano notes.txt                # open or create notes.txt
$ nano -l script.sh             # open with line numbers shown
$ nano +50 config.conf          # open at line 50
$ nano -B /etc/hosts            # auto-backup before saving
$ nano -w /etc/fstab            # no line wrapping (essential for config files)
$ nano -i -E script.py          # auto-indent + tabs to spaces
$ nano -m README.md             # mouse support enabled
$ sudo nano /etc/ssh/sshd_config   # edit system config (needs sudo)
Nano workflow

1. Open: nano myfile.txt. 2. Type your text. 3. Save: Ctrl+O, then Enter. 4. Exit: Ctrl+X. That's it.

Common Mistakes

Wrong
$ nano /etc/nginx/nginx.conf    # permission denied!
Right
$ sudo nano /etc/nginx/nginx.conf   # system files need sudo

7. vim — The Powerful Modal Editor

vim (Vi IMproved) is the most widely installed editor on Linux servers. It is modal, meaning keys do different things depending on which mode you are in. This makes it confusing at first but extremely fast once you learn it. This section covers the absolute basics to get you started.

Syntax

vim [OPTIONS] [FILE]
Vim Modes

    +----------------+       i, a, o       +----------------+
    |                | -------------------> |                |
    |  NORMAL MODE   |                      |  INSERT MODE   |
    |  (navigation,  | <------------------- |  (typing text) |
    |   commands)    |        Esc           |                |
    +----------------+                      +----------------+
           |
           |  : (colon)
           v
    +----------------+
    |  COMMAND MODE  |
    |  (:w :q :wq    |
    |   :q! etc.)    |
    +----------------+
  • Normal mode (default): Keys move the cursor, delete text, copy/paste. You do NOT type text here.
  • Insert mode: Keys insert text into the file (like a normal editor). Press i to enter, Esc to leave.
  • Command mode: Type commands after : at the bottom of the screen. Press Enter to execute.

Essential Vim Keys

KeyModeAction
iNormal → InsertInsert text before cursor
aNormal → InsertInsert text after cursor
oNormal → InsertOpen new line below and insert
EscInsert → NormalReturn to Normal mode
:wCommandSave the file
:qCommandQuit (fails if unsaved changes)
:wqCommandSave and quit
:q!CommandQuit without saving (force)
ddNormalDelete (cut) current line
yyNormalYank (copy) current line
pNormalPaste after cursor
uNormalUndo
Ctrl+RNormalRedo
/patternNormalSearch forward for pattern
nNormalNext search match
NNormalPrevious search match
h j k lNormalMove left, down, up, right
ggNormalGo to first line
GNormalGo to last line
:set numberCommandShow line numbers

Examples

$ vim myfile.txt                # open file in vim
$ vim +10 myfile.txt            # open at line 10
$ vim -R /etc/passwd            # open in read-only mode
$ vim +/error logfile.txt       # open and jump to first "error"
$ vim -O file1.txt file2.txt    # open two files side by side
$ vim -o file1.txt file2.txt    # open two files stacked
$ sudo vim /etc/fstab           # edit system files
$ vim -d file1.txt file2.txt    # diff mode, show differences

Survival Guide: Your First Vim Session

  1. Open: vim myfile.txt
  2. Press i to enter Insert mode
  3. Type your text
  4. Press Esc to go back to Normal mode
  5. Type :wq and press Enter to save and quit
Stuck in vim?

Press Esc a few times to make sure you are in Normal mode, then type :q! and press Enter to quit without saving. This is the single most common question from beginners.

Common Mistakes

Wrong
# Trying to type text in Normal mode
# (you'll trigger random commands instead!)
Right
# Press i first to enter Insert mode
# THEN type your text
# Press Esc when done typing

8. wc — Word, Line, and Character Count

wc (word count) counts lines, words, and characters in files. It is a small command but incredibly useful — especially when piped with other commands to count results.

Syntax

wc [OPTIONS] [FILE...]

Common Flags

FlagDescription
-lCount lines only
-wCount words only
-cCount bytes only
-mCount characters only (differs from -c for multi-byte encodings like UTF-8)
-LPrint the length of the longest line

Examples

$ wc story.txt
  42  318 1876 story.txt
# 42 lines, 318 words, 1876 bytes
$ wc -l story.txt
42 story.txt
$ wc -w story.txt
318 story.txt
$ wc -c story.txt
1876 story.txt
$ wc -m utf8file.txt
1650 utf8file.txt
$ wc -L story.txt
78 story.txt
# longest line is 78 characters
$ wc -l file1.txt file2.txt file3.txt
  10 file1.txt
  25 file2.txt
  42 file3.txt
  77 total
$ cat /etc/passwd | wc -l       # count users on the system
35
$ ls /usr/bin | wc -l           # how many programs in /usr/bin?
1847
$ grep "ERROR" app.log | wc -l  # count error lines
14
$ find . -name "*.py" | wc -l   # count Python files
23
Tip

wc -l is one of the most common pipe endings. Whenever you need to count results from another command, pipe it into wc -l.

9. sort — Sort Lines of Text

sort reads lines from a file (or stdin) and outputs them in sorted order. By default it sorts alphabetically (lexicographically). You can sort numerically, in reverse, by a specific column, and more.

Syntax

sort [OPTIONS] [FILE...]

Common Flags

FlagDescription
-nSort numerically (not alphabetically)
-rReverse the sort order
-k NUMSort by column NUM (fields separated by whitespace)
-t CHARUse CHAR as the field delimiter
-uRemove duplicate lines (unique output)
-fCase-insensitive sort
-hSort human-readable numbers (1K, 2M, 3G)
-o FILEWrite output to FILE (can be the same as input)
-cCheck if input is already sorted (no output if yes)
-sStable sort (preserve original order of equal elements)

Examples

$ cat fruits.txt
banana
apple
cherry
apple
date
banana

$ sort fruits.txt
apple
apple
banana
banana
cherry
date
$ sort -r fruits.txt
date
cherry
banana
banana
apple
apple
$ sort -u fruits.txt            # sorted and unique
apple
banana
cherry
date
$ cat numbers.txt
10
2
33
5
1
100

$ sort numbers.txt              # alphabetic: 1, 10, 100, 2, 33, 5
1
10
100
2
33
5

$ sort -n numbers.txt           # numeric: correct order
1
2
5
10
33
100
$ sort -nr numbers.txt          # numeric descending
100
33
10
5
2
1
$ cat scores.txt
Alice 95
Bob 87
Carol 92
Dave 87
Eve 99

$ sort -k2 -n scores.txt        # sort by second column, numeric
Bob 87
Dave 87
Carol 92
Alice 95
Eve 99
$ sort -t: -k3 -n /etc/passwd   # sort passwd by UID (field 3, colon-delimited)
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
...
$ du -sh /var/log/* | sort -h   # sort by human-readable size
4.0K    /var/log/alternatives.log
12K     /var/log/bootstrap.log
1.2M    /var/log/dpkg.log
5.6M    /var/log/syslog
22M     /var/log/journal
$ sort -f mixed_case.txt        # case-insensitive
Alice
alice
Bob
bob
$ sort -o sorted.txt unsorted.txt   # save to file
$ sort -o data.txt data.txt          # sort a file in place (safe!)

Common Mistakes

Wrong
$ sort numbers.txt      # treats "10" as less than "2" (alphabetic)
1
10
100
2
33
5
Right
$ sort -n numbers.txt   # use -n for numeric data
1
2
5
10
33

10. uniq — Remove Duplicate Lines

uniq filters out adjacent duplicate lines. This is a crucial detail: it only removes duplicates that are next to each other, so you almost always need to sort the input first.

Syntax

uniq [OPTIONS] [INPUT [OUTPUT]]

Common Flags

FlagDescription
-cPrefix each line with the count of occurrences
-dOnly print duplicate lines (lines that appear more than once)
-uOnly print unique lines (lines that appear exactly once)
-iCase-insensitive comparison
-f NUMSkip the first NUM fields before comparing
-s NUMSkip the first NUM characters before comparing
-w NUMCompare only the first NUM characters

Examples

$ cat colors.txt
red
blue
red
green
blue
blue

$ uniq colors.txt               # WRONG: only removes ADJACENT duplicates
red
blue
red
green
blue

$ sort colors.txt | uniq         # RIGHT: sort first, then remove duplicates
blue
green
red
$ sort colors.txt | uniq -c      # count occurrences
      3 blue
      1 green
      2 red
$ sort colors.txt | uniq -c | sort -rn   # most common first
      3 blue
      2 red
      1 green
$ sort colors.txt | uniq -d      # only show duplicated lines
blue
red
$ sort colors.txt | uniq -u      # only show truly unique lines
green
$ sort -f names.txt | uniq -i    # case-insensitive dedup
Alice
Bob
carol
$ # Count unique IP addresses in an access log
$ awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -5
    523 192.168.1.10
    412 10.0.0.5
    198 172.16.0.22
     87 192.168.1.55
     45 10.0.0.100
$ # Find duplicate lines in a file
$ sort data.txt | uniq -d
repeated_line_1
repeated_line_2
$ # Count unique words in a file
$ tr ' ' '\n' < story.txt | sort | uniq | wc -l
148

Common Mistakes

Wrong
$ uniq unsorted.txt     # misses non-adjacent duplicates!
apple
banana
apple               <-- still here because not adjacent
Right
$ sort unsorted.txt | uniq   # sort first!
apple
banana
Always sort before uniq

uniq only compares adjacent lines. If your data is not sorted, uniq will miss duplicates that are separated by other lines. The pattern sort | uniq is so common it is practically one command. (You can also use sort -u as a shortcut for simple deduplication.)

11. cut — Extract Columns from Text

cut extracts specific columns (fields) or character ranges from each line of input. It is perfect for pulling data out of CSV files, log files, or any structured text.

Syntax

cut [OPTIONS] [FILE...]

Common Flags

FlagDescription
-d CHARUse CHAR as the field delimiter (default is tab)
-f LISTSelect fields (columns) by number. E.g., -f1, -f1,3, -f2-5
-c LISTSelect characters by position. E.g., -c1-10
-b LISTSelect bytes by position
--complementShow everything except the selected fields
-sOnly print lines that contain the delimiter
--output-delimiter=STRUse STR as the output delimiter

Examples

$ cat data.csv
name,age,city
Alice,30,London
Bob,25,Paris
Carol,35,Tokyo

$ cut -d',' -f1 data.csv        # first field (name)
name
Alice
Bob
Carol
$ cut -d',' -f1,3 data.csv      # fields 1 and 3
name,city
Alice,London
Bob,Paris
Carol,Tokyo
$ cut -d',' -f2-3 data.csv      # fields 2 through 3
age,city
30,London
25,Paris
35,Tokyo
$ cut -d: -f1 /etc/passwd        # extract usernames
root
daemon
bin
sys
...
$ cut -d: -f1,3 /etc/passwd     # username and UID
root:0
daemon:1
bin:2
...
$ cut -c1-8 /etc/passwd          # first 8 characters of each line
root:x:0
daemon:x
bin:x:2:
...
$ cut -d',' -f2 data.csv --complement   # everything except field 2
name,city
Alice,London
Bob,Paris
Carol,Tokyo
$ cut -d',' -f1,3 --output-delimiter=' | ' data.csv
name | city
Alice | London
Bob | Paris
Carol | Tokyo
$ # Extract IP addresses from access log (space-delimited, field 1)
$ cut -d' ' -f1 access.log | sort | uniq -c | sort -rn | head
    523 192.168.1.10
    412 10.0.0.5
    198 172.16.0.22
$ echo "Hello, World" | cut -c1-5
Hello
$ # Extract the shell from /etc/passwd
$ cut -d: -f1,7 /etc/passwd | head -3
root:/bin/bash
daemon:/usr/sbin/nologin
bin:/usr/sbin/nologin

Common Mistakes

Wrong
$ cut -f1 data.csv          # forgets delimiter, default is TAB
name,age,city              # entire line (no tabs found)
Right
$ cut -d',' -f1 data.csv    # specify the comma delimiter
name
Alice
Bob
Carol
Tip

Remember: cut defaults to tab as the delimiter. If your data uses commas, colons, spaces, or anything else, you must specify -d.

12. paste — Merge Files Line by Line

paste joins lines from multiple files side by side. Where cat concatenates files vertically (one after another), paste merges them horizontally (column by column). It is the opposite of cut.

Syntax

paste [OPTIONS] [FILE...]

Common Flags

FlagDescription
-d CHARSUse CHARS as delimiters (default is tab). Can be a list of delimiters used in rotation.
-sPaste serial: merge all lines of each file into one line
-zUse NUL as line delimiter instead of newline

Examples

$ cat names.txt
Alice
Bob
Carol

$ cat ages.txt
30
25
35

$ paste names.txt ages.txt
Alice	30
Bob	25
Carol	35
$ paste -d',' names.txt ages.txt
Alice,30
Bob,25
Carol,35
$ cat cities.txt
London
Paris
Tokyo

$ paste -d',' names.txt ages.txt cities.txt
Alice,30,London
Bob,25,Paris
Carol,35,Tokyo
$ paste -s names.txt            # serial: all lines joined into one
Alice	Bob	Carol
$ paste -s -d',' names.txt      # serial with comma delimiter
Alice,Bob,Carol
$ paste -d'\n' names.txt ages.txt   # interleave lines
Alice
30

35
$ # Use - (stdin) to reshape a single column into multiple columns
$ seq 1 8 | paste - - - -       # four columns
1	2	3	4
5	6	7	8
$ seq 1 6 | paste -d',' - -     # two columns, comma-separated

$ # Combine cut and paste: swap columns
$ cut -d',' -f2 data.csv > /tmp/col2
$ cut -d',' -f1 data.csv > /tmp/col1

$ # Number lines from two sources side by side
$ paste -d': ' /dev/null names.txt ages.txt
 Alice 30
 Bob 25
 Carol 35
The - trick

When you use - as a filename, paste reads from standard input. Multiple dashes split stdin into columns. seq 1 8 | paste - - - - turns 8 lines into 2 rows of 4.

13. tr — Translate or Delete Characters

tr (translate) replaces, deletes, or squeezes characters. It reads from standard input only (no filename argument), so you must pipe or redirect into it. It works on individual characters, not words or patterns.

Syntax

tr [OPTIONS] SET1 [SET2]

Common Flags

FlagDescription
-dDelete characters in SET1
-sSqueeze: replace consecutive repeated characters with one
-cComplement: use the complement of SET1 (all chars NOT in SET1)

Character Classes

ClassMeaning
[:lower:]Lowercase letters (a-z)
[:upper:]Uppercase letters (A-Z)
[:alpha:]All letters
[:digit:]Digits (0-9)
[:alnum:]Letters and digits
[:space:]Whitespace characters
[:punct:]Punctuation characters

Examples

$ echo "hello world" | tr 'a-z' 'A-Z'
HELLO WORLD
$ echo "HELLO WORLD" | tr '[:upper:]' '[:lower:]'
hello world
$ echo "hello world" | tr ' ' '_'
hello_world
$ echo "hello 123 world" | tr -d '[:digit:]'
hello  world
$ echo "hello 123 world" | tr -d ' '
hello123world
$ echo "aabbccdd" | tr -s 'a-z'
abcd
$ echo "hello     world" | tr -s ' '
hello world
$ echo "Hello, World! 123" | tr -cd '[:alpha:]'
HelloWorld
$ echo "Hello, World! 123" | tr -cd '[:alnum:] \n'
Hello World 123
$ # Replace newlines with spaces (join all lines)
$ cat names.txt | tr '\n' ' '
Alice Bob Carol 
$ # Split words to lines (replace spaces with newlines)
$ echo "one two three" | tr ' ' '\n'
one
two
three
$ # ROT13 encoding
$ echo "Hello" | tr 'A-Za-z' 'N-ZA-Mn-za-m'
Uryyb
$ # Replace tabs with spaces
$ cat Makefile | tr '\t' '    '
(tabs replaced with spaces)
$ # Remove carriage returns from Windows files
$ tr -d '\r' < windows_file.txt > unix_file.txt
$ # Count unique words (split + sort + uniq + count)
$ tr ' ' '\n' < story.txt | sort | uniq -c | sort -rn | head -5
     42 the
     31 and
     28 of
     19 to
     15 a

Common Mistakes

Wrong
$ tr 'a-z' 'A-Z' myfile.txt    # tr does NOT take filenames!
tr: extra operand 'myfile.txt'
Right
$ tr 'a-z' 'A-Z' < myfile.txt  # redirect from file
CONTENTS OF MYFILE IN UPPERCASE
tr reads only from stdin

tr never takes a filename argument. You must use < file (redirection) or pipe into it. This trips up almost every beginner.

Exercise 1: File Inspection Pipeline

Create a file called animals.txt with these lines (one per line): dog, cat, bird, cat, fish, dog, bird, bird, cat. Then:

  1. Count how many lines the file has.
  2. Sort the file and remove duplicates. How many unique animals are there?
  3. Find which animal appears most often and how many times.
Show Solution 
$ printf "dog\ncat\nbird\ncat\nfish\ndog\nbird\nbird\ncat\n" > animals.txt

$ wc -l animals.txt
9 animals.txt

$ sort animals.txt | uniq
bird

$ sort animals.txt | uniq | wc -l

$ sort animals.txt | uniq -c | sort -rn | head -1
      3 bird
      3 cat

The file has 9 lines. There are 4 unique animals. "bird" and "cat" are tied at 3 each.

Exercise 3: Log Analysis

Imagine you have a web server log at /var/log/access.log where each line starts with an IP address followed by a space. Write a one-liner pipeline that:

  1. Extracts the IP addresses.
  2. Sorts them.
  3. Counts unique occurrences.
  4. Shows the top 5 most frequent visitors.
Show Solution 
$ cut -d' ' -f1 /var/log/access.log | sort | uniq -c | sort -rn | head -5
    523 192.168.1.10
    412 10.0.0.5
    198 172.16.0.22
     87 192.168.1.55
     45 10.0.0.100

This pipeline: cut extracts field 1 (IP), sort puts identical IPs together, uniq -c counts them, sort -rn sorts by count descending, and head -5 limits to the top 5.

Exercise 4: Merge and Transform

Create two files:

first_names.txt:    last_names.txt:
Alice               Smith
Bob                 Jones
Carol               Williams

Merge them into a single file with the format "LASTNAME, Firstname" (last name uppercase, first name as-is, comma separated).

Show Solution 
$ paste -d',' last_names.txt first_names.txt | \
    while IFS=',' read last first; do
      echo "$(echo "$last" | tr '[:lower:]' '[:upper:]'), $first"
    done
SMITH, Alice
JONES, Bob
WILLIAMS, Carol

Or a simpler approach using awk:

$ paste last_names.txt first_names.txt | awk '{printf "%s, %s\n", toupper($1), $2}'
SMITH, Alice
JONES, Bob
WILLIAMS, Carol

Quizzes

Quiz 1: You have a file called data.txt with 500 lines. Which command shows lines 20 through 30? 
$ head -n 30 data.txt | tail -n 11

head -n 30 gets lines 1-30, then tail -n 11 gets the last 11 of those (lines 20-30). Another approach: sed -n '20,30p' data.txt.

Quiz 2: What is wrong with this command: uniq names.txt? When will it fail to remove all duplicates?

uniq only removes adjacent duplicate lines. If the file contains:

alice
bob
alice

The two "alice" lines are not adjacent, so uniq keeps both. You must sort first: sort names.txt | uniq.

Quiz 3: You are stuck in vim and you have made changes you do NOT want to keep. How do you exit without saving?

Press Esc (to ensure you are in Normal mode), then type :q! and press Enter. The ! forces vim to quit without saving. Without !, vim will refuse to quit if there are unsaved changes.

Quiz 4: What does this pipeline do: tr ' ' '\n' < essay.txt | sort | uniq -c | sort -rn | head -10?

It finds the 10 most frequently used words in essay.txt. Step by step:

  1. tr ' ' '\n' — splits words onto separate lines (replaces spaces with newlines)
  2. sort — puts identical words next to each other
  3. uniq -c — counts each word's occurrences
  4. sort -rn — sorts by count, highest first
  5. head -10 — shows only the top 10

Key takeaway

The real power of these commands is not in using them alone — it is in combining them with pipes. A pipeline like cut -d',' -f3 data.csv | sort | uniq -c | sort -rn | head -5 can answer complex questions about your data in seconds. Practice building pipelines and these commands will become second nature.
