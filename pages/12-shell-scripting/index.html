Chapter 12: Shell & Scripting Basics

Everything you have typed in the terminal so far has been interpreted by a shell. This chapter teaches you how the shell works, how to customize it, and how to start writing your own scripts to automate tasks.

1. What is Bash?

A shell is a program that takes the commands you type and translates them into instructions for the operating system. There are several shells available on Linux:

ShellPathNotes
bash/bin/bashBourne Again Shell. The default on most Linux systems.
sh/bin/shThe original Bourne Shell (or a symlink to bash/dash).
zsh/bin/zshZ Shell. Default on macOS. Popular with plugins (Oh My Zsh).
fish/usr/bin/fishFriendly Interactive Shell. Great autocompletion, not POSIX.
dash/bin/dashDebian Almquist Shell. Fast, minimal, used for system scripts.
# Check your current shell
$ echo $SHELL
/bin/bash

# See all available shells on the system
$ cat /etc/shells
/bin/sh
/bin/bash
/usr/bin/bash
/bin/zsh
/usr/bin/zsh

# Check the bash version
$ bash --version
GNU bash, version 5.1.16(1)-release (x86_64-pc-linux-gnu)

This chapter focuses on bash because it is the most common shell you will encounter on Linux servers and desktops.

2. .bashrc and .profile

When bash starts, it reads configuration files to set up your environment. Which files it reads depends on how the shell was started:

Shell TypeHow It StartsFiles Read
Login shellSSH login, su - user, console login~/.profile (or ~/.bash_profile)
Non-login interactiveOpening a new terminal window~/.bashrc
Non-interactiveRunning a scriptNone by default (uses $BASH_ENV if set)
Practical tip

Most people put their customizations in ~/.bashrc and then add this to ~/.profile:
if [ -f ~/.bashrc ]; then source ~/.bashrc; fi
This way, your settings load in both login and non-login shells.

Common things to put in .bashrc

# Custom prompt (shows user@host and current directory in color)
PS1='\[\033[01;32m\]\u@\h\[\033[00m\]:\[\033[01;34m\]\w\[\033[00m\]\$ '

# Aliases
alias ll='ls -alF'
alias la='ls -A'
alias gs='git status'

# Environment variables
export EDITOR=vim
export PATH="$HOME/bin:$PATH"

# History settings
HISTSIZE=10000
HISTFILESIZE=20000
HISTCONTROL=ignoredups:erasedups
# After editing .bashrc, reload it without logging out:
$ source ~/.bashrc
# or equivalently:
$ . ~/.bashrc

3. Aliases

An alias is a custom shortcut for a longer command. It saves typing and reduces mistakes.

Creating aliases

# Temporary alias (lasts until you close the terminal)
$ alias ll='ls -alF'
$ alias gs='git status'
$ alias update='sudo apt update && sudo apt upgrade -y'

# View all current aliases
$ alias
alias ll='ls -alF'
alias gs='git status'
alias update='sudo apt update && sudo apt upgrade -y'

# Remove an alias
$ unalias ll

Useful aliases to add to .bashrc

# Navigation
alias ..='cd ..'
alias ...='cd ../..'
alias ~='cd ~'

# Listing
alias ll='ls -alF --color=auto'
alias la='ls -A --color=auto'
alias l='ls -CF --color=auto'

# Safety nets
alias rm='rm -i'          # ask before deleting
alias cp='cp -i'          # ask before overwriting
alias mv='mv -i'          # ask before overwriting

# Grep with color
alias grep='grep --color=auto'

# Disk usage (human readable)
alias df='df -h'
alias du='du -h'

# Git shortcuts
alias gs='git status'
alias ga='git add'
alias gc='git commit'
alias gp='git push'
alias gl='git log --oneline -10'
Making aliases permanent

Aliases set at the command line disappear when you close the terminal. To make them permanent, add them to ~/.bashrc and run source ~/.bashrc.

4. Pipes

Mental Model: Pipes

Imagine water flowing through a series of connected pipes. Each pipe section does one thing to the water (filters it, heats it, adds color). In Linux, the | (pipe) character connects commands the same way. The output of one command flows into the input of the next.

Command A ------> Command B ------> Command C ------> Result (output) | (output) | (output) | | pipe ( | ) pipe ( | ) Example: cat log.txt | grep "ERROR" | wc -l Step 1: cat outputs the entire file Step 2: grep filters to only lines containing "ERROR" Step 3: wc -l counts how many lines remain

Pipe examples

# Count how many files are in a directory
$ ls | wc -l
42

# Find lines containing "error" in a log, case-insensitive
$ cat /var/log/syslog | grep -i error

# Sort a file and remove duplicates
$ cat names.txt | sort | uniq

# Show the 5 largest files in current directory
$ ls -lS | head -6               # head -6: header line + 5 files

# List all users on the system, sorted
$ cut -d: -f1 /etc/passwd | sort

# Count unique IP addresses in an access log
$ awk '{print $1}' access.log | sort | uniq | wc -l

# Find the 10 most common words in a file
$ cat book.txt | tr ' ' '\n' | sort | uniq -c | sort -rn | head -10

# Show disk usage sorted by size
$ du -sh /var/* 2>/dev/null | sort -hr | head -10

# List running processes and search for nginx
$ ps aux | grep nginx

# Chain 4 commands: find .log files, count lines, sort by count
$ find /var/log -name "*.log" | xargs wc -l | sort -n | tail -5

# Show unique shells used by users
$ cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn

# Get HTTP status codes from an access log and count them
$ awk '{print $9}' access.log | sort | uniq -c | sort -rn
The Unix philosophy

Each command does one thing well. Pipes let you combine simple tools into powerful workflows. This is the core of the Unix philosophy.

5. Redirection

Mental Model: Redirection

Normally, command output goes to your screen (stdout) and errors go to your screen (stderr). Redirection changes where these streams go — you can send output to a file, or pull input from a file, instead of the keyboard/screen.

+-------------------+ | Command | +-------------------+ Input -->| stdin (fd 0) <--|-- Keyboard (default) or < file | | | stdout (fd 1) -->|-- Screen (default) or > file | | | stderr (fd 2) -->|-- Screen (default) or 2> file +-------------------+

Output redirection

# Write output to a file (overwrites if file exists!)
$ echo "Hello" > greeting.txt
$ ls -la > filelist.txt

# Append output to a file (does NOT overwrite)
$ echo "World" >> greeting.txt
$ date >> log.txt                     # add timestamp to log

# Redirect stderr to a file
$ find / -name "*.conf" 2> errors.txt # only errors go to file, output to screen

# Redirect both stdout and stderr to the same file
$ command > output.txt 2>&1           # traditional syntax
$ command &> output.txt               # bash shorthand (same result)

# Redirect stdout to one file and stderr to another
$ command > output.txt 2> errors.txt

# Discard output completely (send to /dev/null)
$ command > /dev/null                  # discard stdout
$ command 2> /dev/null                 # discard stderr
$ command &> /dev/null                 # discard everything

Input redirection

# Feed a file as input to a command
$ sort < unsorted.txt                  # sort reads from the file
$ wc -l < myfile.txt                   # count lines in the file

# Here-document: pass multiple lines of input
$ cat <<EOF
This is line 1
This is line 2
EOF

# Here-string: pass a single string as input
$ wc -w <<< "count the words in this string"
7

Wrong vs correct examples

Wrong
# Trying to read and write the same file
$ sort < names.txt > names.txt
# This EMPTIES the file! The shell
# truncates names.txt before sort
# can read it.
Correct
# Use a temporary file instead
$ sort < names.txt > names_sorted.txt
$ mv names_sorted.txt names.txt

# Or use sponge (from moreutils)
$ sort names.txt | sponge names.txt
Wrong
# Accidentally overwriting a file
$ echo "new data" > important.log
# Oops! Used > instead of >>
# The old data is gone forever.
Correct
# Use >> to append
$ echo "new data" >> important.log

# Or protect yourself with noclobber
$ set -o noclobber
# Now > on existing files gives an error

6. stdin, stdout, and stderr

The Three Standard Streams

Every Linux process has three default communication channels, called file descriptors:

  • stdin (fd 0) — Standard Input. Where the command reads data from. Default: your keyboard.
  • stdout (fd 1) — Standard Output. Where the command sends its normal results. Default: your screen.
  • stderr (fd 2) — Standard Error. Where the command sends error messages. Default: your screen (same as stdout, but a separate stream).
+---------------------+ Keyboard -------->| stdin (fd 0) | | | | YOUR COMMAND | | | | stdout (fd 1) ----|------> Screen (normal output) | | | stderr (fd 2) ----|------> Screen (error messages) +---------------------+

Even though both stdout and stderr appear on your screen, they are separate streams. This is why you can redirect them independently:

# This command produces both stdout and stderr
$ find / -name "*.conf" > found.txt 2> errors.txt
# found.txt gets the file paths (stdout)
# errors.txt gets "Permission denied" messages (stderr)

# Prove they are separate: only redirect stderr
$ ls /real-dir /fake-dir 2> /dev/null
/real-dir:
file1.txt  file2.txt
# The error about /fake-dir was silenced, but stdout still shows

# Only redirect stdout
$ ls /real-dir /fake-dir > /dev/null
ls: cannot access '/fake-dir': No such file or directory
# stdout was silenced, but the error still shows

7. Command Substitution

Command substitution lets you use the output of one command as part of another command. The shell runs the inner command first, captures its output, and inserts it in place.

Syntax: $( ) vs backticks

# Modern syntax (recommended) — use $(...)
$ echo "Today is $(date +%A)"
Today is Wednesday

# Old syntax (avoid) — backticks `...`
$ echo "Today is `date +%A`"
Today is Wednesday
Always use $( ) instead of backticks

Backticks work but are harder to read, cannot be nested, and are considered outdated. Use $(command) in all new scripts.

Practical examples

# Create a file with today's date in the name
$ touch "backup-$(date +%Y-%m-%d).tar.gz"
$ ls
backup-2026-03-31.tar.gz

# Store the result in a variable
$ CURRENT_USER=$(whoami)
$ echo "Logged in as: $CURRENT_USER"
Logged in as: alice

# Use command output as an argument
$ echo "There are $(ls | wc -l) files here"
There are 42 files here

# Create a directory named with the hostname
$ mkdir "logs-$(hostname)"

# Kill all processes matching a name
$ kill $(pgrep firefox)

# Nested command substitution (only works with $(), not backticks)
$ echo "Kernel: $(uname -r) on $(uname -s)"
Kernel: 5.15.0-56-generic on Linux

# Use in a for loop
$ for file in $(find . -name "*.log"); do echo "Found: $file"; done

# Get the parent directory name
$ echo "Project: $(basename $(pwd))"
Project: my-project

8. Variables

Variables let you store and reuse values. In bash, there are no spaces around the = sign when setting a variable.

Setting and using variables

# Set a variable (NO spaces around =)
$ NAME="Alice"
$ AGE=30
$ GREETING="Hello, $NAME"

# Use a variable with $
$ echo $NAME
Alice
$ echo "My name is $NAME and I am $AGE"
My name is Alice and I am 30

# Use ${VAR} when variable is next to other text
$ echo "${NAME}'s age is $AGE"
Alice's age is 30
$ echo "File: ${NAME}_report.txt"
File: Alice_report.txt
Wrong
# Spaces around = cause errors!
$ NAME = "Alice"
bash: NAME: command not found

$ NAME ="Alice"
bash: NAME: command not found

$ NAME= "Alice"
bash: Alice: command not found
Correct
# No spaces around =
$ NAME="Alice"

# Numbers work the same way
$ COUNT=42

# Command output in a variable
$ TODAY=$(date +%Y-%m-%d)

export and readonly

# Regular variables are only available in the current shell
$ FRUIT="apple"
$ bash -c 'echo $FRUIT'            # empty! child shell cannot see it


# export makes a variable available to child processes
$ export FRUIT="apple"
$ bash -c 'echo $FRUIT'
apple

# readonly makes a variable unchangeable
$ readonly PI=3.14159
$ PI=3.0
bash: PI: readonly variable

Common environment variables

$ echo $HOME                          # your home directory
/home/alice
$ echo $USER                          # current username
alice
$ echo $PATH                          # directories searched for commands
/usr/local/bin:/usr/bin:/bin
$ echo $PWD                           # current working directory
/home/alice/projects
$ echo $SHELL                         # your default shell
/bin/bash
$ echo $?                             # exit code of the last command
0

9. Simple Bash Scripts

A bash script is a text file containing a series of commands. Instead of typing each command one at a time, you write them in a file and run them all at once.

Your first script

# Step 1: Create the script file
$ nano hello.sh
#!/bin/bash
# This is my first script

echo "Hello, $(whoami)!"
echo "Today is $(date +%A), $(date +%B) $(date +%d), $(date +%Y)"
echo "You are in: $(pwd)"
echo "Your system has been up for: $(uptime -p)"
# Step 2: Make it executable
$ chmod +x hello.sh

# Step 3: Run it
$ ./hello.sh
Hello, alice!
Today is Tuesday, March 31, 2026
You are in: /home/alice
Your system has been up for: up 3 days, 7 hours, 12 minutes

# Alternative: run with bash explicitly (no chmod needed)
$ bash hello.sh
The shebang line: #!/bin/bash

The first line #!/bin/bash is called the shebang. It tells the system which interpreter to use when you run the script with ./script.sh. Without it, the system may use a different shell. Always include it.

Script 2: if / else

#!/bin/bash
# Check if a file exists

FILE="$1"       # $1 = first argument passed to the script

if [ -z "$FILE" ]; then
    echo "Usage: ./check_file.sh <filename>"
    exit 1
fi

if [ -f "$FILE" ]; then
    echo "'$FILE' exists and is a regular file."
    echo "Size: $(wc -c < "$FILE") bytes"
    echo "Lines: $(wc -l < "$FILE")"
elif [ -d "$FILE" ]; then
    echo "'$FILE' exists and is a directory."
    echo "Contains: $(ls "$FILE" | wc -l) items"
else
    echo "'$FILE' does not exist."
    exit 1
fi
$ chmod +x check_file.sh
$ ./check_file.sh /etc/passwd
'/etc/passwd' exists and is a regular file.
Size: 2775 bytes
Lines: 48

$ ./check_file.sh /tmp
'/tmp' exists and is a directory.
Contains: 12 items

$ ./check_file.sh nonexistent
'nonexistent' does not exist.

Common test conditions

TestMeaning
-f FILEFILE exists and is a regular file
-d FILEFILE exists and is a directory
-e FILEFILE exists (any type)
-r FILEFILE is readable
-w FILEFILE is writable
-x FILEFILE is executable
-z STRINGSTRING is empty (zero length)
-n STRINGSTRING is not empty
STR1 = STR2Strings are equal
NUM1 -eq NUM2Numbers are equal
NUM1 -lt NUM2NUM1 is less than NUM2
NUM1 -gt NUM2NUM1 is greater than NUM2

Script 3: for loop

#!/bin/bash
# Rename all .txt files to .bak

for file in *.txt; do
    if [ -f "$file" ]; then
        newname="${file%.txt}.bak"
        mv "$file" "$newname"
        echo "Renamed: $file -> $newname"
    fi
done
$ ls
notes.txt  report.txt  data.txt
$ ./rename_bak.sh
Renamed: data.txt -> data.bak
Renamed: notes.txt -> notes.bak
Renamed: report.txt -> report.bak

Script 4: while loop with read

#!/bin/bash
# Simple number guessing game

SECRET=42
GUESS=0

echo "Guess a number between 1 and 100:"

while [ "$GUESS" -ne "$SECRET" ]; do
    read -p "> " GUESS

    if [ "$GUESS" -lt "$SECRET" ]; then
        echo "Too low! Try again."
    elif [ "$GUESS" -gt "$SECRET" ]; then
        echo "Too high! Try again."
    fi
done

echo "Correct! The number was $SECRET."

Script 5: System info report

#!/bin/bash
# Generate a system information report

REPORT="system_report_$(date +%Y%m%d).txt"

{
    echo "===== System Report ====="
    echo "Date: $(date)"
    echo "Hostname: $(hostname)"
    echo "User: $(whoami)"
    echo ""
    echo "--- OS Info ---"
    uname -a
    echo ""
    echo "--- Uptime ---"
    uptime
    echo ""
    echo "--- Memory ---"
    free -h
    echo ""
    echo "--- Disk Usage ---"
    df -h /
    echo ""
    echo "--- Top 5 Processes by Memory ---"
    ps aux --sort=-%mem | head -6
    echo ""
    echo "===== End of Report ====="
} > "$REPORT"

echo "Report saved to $REPORT"
echo "Size: $(wc -c < "$REPORT") bytes"
$ chmod +x sysreport.sh
$ ./sysreport.sh
Report saved to system_report_20260331.txt
Size: 1247 bytes

Exit codes

# Every command returns an exit code: 0 = success, non-zero = failure
$ ls /etc/passwd
$ echo $?
0              # success

$ ls /nonexistent
ls: cannot access '/nonexistent': No such file or directory
$ echo $?
2              # failure

# Use exit codes in your scripts
#!/bin/bash
if [ $# -eq 0 ]; then
    echo "Error: no arguments provided" >&2
    exit 1          # exit with error code 1
fi
echo "Processing: $1"
exit 0              # exit with success code 0

Exercise 3: Write a script

Write a bash script called greet.sh that:

  1. Accepts a name as the first argument ($1).
  2. If no name is given, prints "Usage: ./greet.sh <name>" and exits with code 1.
  3. If a name is given, prints "Good morning, <name>! Today is <day of week>."
Show Solution 
#!/bin/bash

if [ -z "$1" ]; then
    echo "Usage: ./greet.sh <name>"
    exit 1
fi

echo "Good morning, $1! Today is $(date +%A)."
exit 0
$ chmod +x greet.sh
$ ./greet.sh Alice
Good morning, Alice! Today is Tuesday.
$ ./greet.sh
Usage: ./greet.sh <name>

Knowledge Check

1. What does the command ls | wc -l do?
Answer: b) The pipe (|) sends the output of ls into wc -l, which counts the number of lines. Each item ls prints appears on its own line, so this counts the number of files and directories.
2. What is wrong with this variable assignment? NAME = "Bob"
Answer: c) In bash, variable assignment must have no spaces around the =. The correct form is NAME="Bob". With spaces, bash interprets NAME as a command name and = and "Bob" as arguments to it.
