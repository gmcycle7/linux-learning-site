Chapter 2: Terminal Basics

The terminal is the gateway to everything in Linux. In this chapter you will learn the foundational commands that every Linux user types every single day. Master these and you will never feel lost in a terminal again.

Mental Model: What Happens When You Type a Command

  +-------------+       +------------------+       +-----------------+       +----------------+
  |  You type   | ----> |  Shell reads &   | ----> |  Kernel finds   | ----> |  Output sent   |
  |  a command  |       |  interprets the  |       |  the program &  |       |  back to your  |
  |  (e.g. ls)  |       |  input string    |       |  executes it    |       |  terminal      |
  +-------------+       +------------------+       +-----------------+       +----------------+
        |                       |                         |                         |
   Keyboard input       Parses command,             Loads binary from           stdout / stderr
   goes to the          expands variables,          disk into memory,           streams are
   terminal emulator    resolves aliases,           allocates CPU time,         printed line
                        finds the binary            runs the process            by line

Key insight: The shell is just a program itself. It sits between you and the kernel, translating your human-readable commands into system calls. When you type ls, the shell searches the directories listed in your $PATH variable, finds /usr/bin/ls, and asks the kernel to run it. The kernel creates a new process, executes the binary, and the output flows back through the shell to your screen.

1. pwd — Print Working Directory

What It Does

pwd prints the absolute path of the directory you are currently inside. Think of it as a "You Are Here" sign on a map. Every time you open a terminal, you start somewhere in the filesystem — pwd tells you exactly where.

Why It Matters

When you navigate deep into nested folders, it is easy to lose track of your location. Running pwd instantly grounds you. Many scripts also use pwd to build file paths dynamically.

Syntax

pwd [OPTION]

Options

OptionDescription
-LPrint the logical path (follows symlinks; this is the default)
-PPrint the physical path (resolves all symlinks)

Practical Examples

$ pwd
/home/alice
$ cd /var/log
$ pwd
/var/log
$ cd /tmp
$ pwd
/tmp
# If /home/alice/mylink is a symlink to /opt/data
$ cd /home/alice/mylink
$ pwd -L
/home/alice/mylink
$ pwd -P
/opt/data
# Use pwd in a script to reference the current directory
$ echo "I am in: $(pwd)"
I am in: /home/alice
# Store current directory in a variable
$ MYDIR=$(pwd)
$ echo $MYDIR
/home/alice
# After multiple cd commands, check where you ended up
$ cd /etc
$ cd ../var
$ cd log
$ pwd
/var/log
# pwd always shows the full (absolute) path, never relative
$ cd ~
$ pwd
/home/alice
Tip: Most terminal prompts already show your current directory (or an abbreviated version like ~). But when in doubt, pwd gives you the unambiguous, full path.

Common Mistakes

Wrong: Assuming pwd shows the directory name only. 
$ pwd
/var/log   # Not just "log"
Right: pwd always returns the full absolute path from the root /.

2. ls — List Directory Contents

What It Does

ls shows you the files and directories inside a given location. Without arguments, it lists the contents of your current directory. It is almost certainly the command you will type the most in your Linux career.

Why It Matters

You cannot work with files if you do not know what files exist. ls is your eyes inside the terminal. Combine it with different flags and you can see hidden files, file sizes, permissions, modification dates, and more.

Syntax

ls [OPTIONS] [FILE_OR_DIR...]

Common Options

OptionDescription
-lLong format — shows permissions, owner, size, date
-aShow all files, including hidden ones (names starting with .)
-hHuman-readable sizes (KB, MB, GB instead of raw bytes). Use with -l
-RRecursive — list contents of all subdirectories too
-tSort by modification time (newest first)
-SSort by file size (largest first)
-rReverse sort order
-dList directory entries themselves, not their contents
-1One entry per line
--colorColorize output (often enabled by default via alias)

Practical Examples

# Basic listing of current directory
$ ls
Desktop  Documents  Downloads  Music  Pictures  Videos
# Long format: permissions, owner, group, size, date, name
$ ls -l
total 24
drwxr-xr-x 2 alice alice 4096 Mar 15 09:00 Desktop
drwxr-xr-x 3 alice alice 4096 Mar 20 14:22 Documents
drwxr-xr-x 2 alice alice 4096 Mar 18 11:30 Downloads
drwxr-xr-x 2 alice alice 4096 Feb 10 08:00 Music
drwxr-xr-x 2 alice alice 4096 Mar 01 16:45 Pictures
drwxr-xr-x 2 alice alice 4096 Jan 22 12:00 Videos
# Show hidden files (dotfiles)
$ ls -a
.  ..  .bashrc  .profile  .ssh  Desktop  Documents  Downloads
# Combine long format + hidden + human-readable sizes
$ ls -lah
total 48K
drwxr-xr-x 8 alice alice 4.0K Mar 20 14:22 .
drwxr-xr-x 3 root  root  4.0K Jan 01 00:00 ..
-rw-r--r-- 1 alice alice  220 Jan 01 00:00 .bash_logout
-rw-r--r-- 1 alice alice 3.5K Jan 01 00:00 .bashrc
-rw-r--r-- 1 alice alice  807 Jan 01 00:00 .profile
drwx------ 2 alice alice 4.0K Mar 10 09:15 .ssh
drwxr-xr-x 2 alice alice 4.0K Mar 15 09:00 Desktop
drwxr-xr-x 3 alice alice 4.0K Mar 20 14:22 Documents
drwxr-xr-x 2 alice alice 4.0K Mar 18 11:30 Downloads
# Sort by modification time (newest first)
$ ls -lt
total 24
drwxr-xr-x 3 alice alice 4096 Mar 20 14:22 Documents
drwxr-xr-x 2 alice alice 4096 Mar 18 11:30 Downloads

$ ls -lSh /var/log

$ ls /etc/ssh

# List only directories

# List files matching a pattern (glob)
$ ls *.txt

Common Mistakes

Wrong: Forgetting that hidden files start with a dot and are invisible by default. 
$ ls
Desktop  Documents   # Where is .bashrc?
Right: Use ls -a to see hidden (dot) files. 
$ ls -a
.  ..  .bashrc  .profile  Desktop  Documents
Wrong: Using -h without -l. The -h flag has no visible effect without long format. 
$ ls -h
Desktop  Documents  Downloads   # No sizes shown!
Right: Combine -lh to see human-readable sizes. 
$ ls -lh
-rw-r--r-- 1 alice alice 3.5K Mar 20 notes.txt
Tip: Many distributions alias ls to ls --color=auto so you see colors by default. You can check with alias ls.

3. cd — Change Directory

What It Does

cd changes your current working directory. It is how you move around the filesystem. After running cd, your prompt updates and any relative commands (like ls) now operate from the new location.

Why It Matters

Everything in Linux revolves around your current directory. When you run ls, it lists files here. When you create a file, it appears here. cd is your ability to walk through the filesystem.

Syntax

cd [DIRECTORY]

Special Shortcuts

ShortcutDescription
~Home directory (e.g., /home/alice)
..Parent directory (go up one level)
.Current directory (rarely useful with cd, but important conceptually)
-Previous directory (toggle back and forth)
/Root of the entire filesystem

Practical Examples

# Go to your home directory (three equivalent ways)
$ cd
$ cd ~
$ cd $HOME
$ pwd
/home/alice
# Go to an absolute path
$ cd /var/log
$ pwd
/var/log
# Go to a relative path (from current directory)
$ cd Documents
$ pwd
/home/alice/Documents
# Go up one level
$ pwd
/home/alice/Documents/projects
$ cd ..
$ pwd
/home/alice/Documents
# Go up two levels
$ pwd
/home/alice/Documents/projects
$ cd ../..
$ pwd
/home/alice
# Toggle to previous directory with -
$ cd /etc
$ cd /tmp
$ cd -
/etc
$ cd -
/tmp
# Go to root directory
$ cd /
$ pwd
/
$ ls
bin  boot  dev  etc  home  lib  media  mnt  opt  proc  root  sbin  srv  sys  tmp  usr  var
# Navigate to another user's home directory
$ cd /home/bob
$ pwd
/home/bob
# Combine .. with a directory name
$ pwd
/home/alice/Documents
$ cd ../Downloads
$ pwd
/home/alice/Downloads
# Using . (current directory) - stays in place
$ pwd
/home/alice
$ cd .
$ pwd
/home/alice
# Tab completion: type partial names and press Tab
$ cd Doc<TAB>
$ cd Documents/    # Shell auto-completes!

Absolute vs. Relative Paths

Absolute path starts from root / and gives the full location: /home/alice/Documents

Relative path starts from your current directory: Documents or ../Downloads

  /                         (root - absolute paths start here)
  +-- home/
  |   +-- alice/            (you are here: /home/alice)
  |   |   +-- Documents/    relative: Documents     absolute: /home/alice/Documents
  |   |   +-- Downloads/    relative: Downloads     absolute: /home/alice/Downloads
  |   +-- bob/              relative: ../bob        absolute: /home/bob
  +-- etc/                  relative: ../../etc     absolute: /etc
  +-- var/
      +-- log/              relative: ../../var/log absolute: /var/log

Common Mistakes

Wrong: Typing a path with spaces without quoting it. 
$ cd My Documents
bash: cd: My: No such file or directory
Right: Quote the path or escape the space. 
$ cd "My Documents"
$ cd My\ Documents
Wrong: Confusing cd with no argument (goes home) versus cd / (goes to root).
Right: cd alone = home. cd / = filesystem root. Very different places!
Note: cd is a shell built-in, not an external program. You will not find a binary for it in /usr/bin/. The shell handles it directly because changing the working directory is a property of the shell process itself.

4. clear — Clear the Terminal Screen

What It Does

clear wipes the visible terminal screen, giving you a fresh, empty view. Your command history and any running processes are not affected — it only clears the display.

Why It Matters

After running many commands, your screen fills with output. Clearing it helps you focus and reduces visual clutter. It is a quality-of-life command you will use constantly.

Syntax

clear

Practical Examples

# Clear the screen
$ clear
# Keyboard shortcut (faster than typing "clear")
# Press: Ctrl + L
# This works in most shells and is identical to running clear
# Clear and run a command on the same line
$ clear && ls -la
# Reset the terminal completely (fixes garbled display)
$ reset
# Clear screen in a script for cleaner output
$ clear; echo "=== System Report ==="; uname -a
# You can scroll up after clear to see previous output
# (in most terminal emulators, use Shift+PageUp)
# Difference: clear vs reset
# clear: just clears the visible screen
# reset: reinitializes the terminal (fixes broken display after cat-ing a binary file)
# Use tput to clear (alternative method)
$ tput clear
Tip: Ctrl+L is the fastest way to clear your screen. Your fingers never leave the keyboard. Make it a habit!
Note: If your terminal ever looks garbled (strange characters everywhere, usually from accidentally running cat on a binary file), type reset and press Enter. Even if you cannot see what you are typing, it will fix the display.

5. history — Command History

What It Does

history displays a numbered list of commands you have previously typed. The shell remembers your past commands, and you can recall, search, and re-execute them. This saves enormous amounts of retyping.

Why It Matters

Experienced Linux users rarely retype long commands. They use history to recall them. The history mechanism also serves as a log of your actions, which is invaluable for debugging ("What did I do 10 minutes ago that broke things?").

Syntax

history [N]         # Show last N commands
history -c          # Clear history
history -d N        # Delete entry number N
history -w          # Write history to file

History Shortcuts

ShortcutDescription
!!Re-run the last command
!NRe-run command number N from history
!stringRe-run the most recent command starting with string
!$The last argument of the previous command
Ctrl+RReverse-search through history (interactive)
Up ArrowScroll through previous commands one by one
HISTSIZEEnvironment variable: number of commands to remember in memory
HISTFILESIZEEnvironment variable: number of commands to store in the history file

Practical Examples

# Show full command history
$ history
    1  pwd
    2  ls -la
    3  cd /var/log
    4  cat syslog
    5  cd ~
    6  mkdir projects
    7  cd projects
    8  touch app.py
# Show only the last 5 commands
$ history 5
    4  cat syslog
    5  cd ~
    6  mkdir projects
    7  cd projects
    8  touch app.py
# Re-run the last command with !!
$ echo "hello"
hello
$ !!
echo "hello"
hello
# Classic use: forgot sudo? Use sudo !!
$ apt update
E: Could not open lock file - open (13: Permission denied)
$ sudo !!
sudo apt update
[sudo] password for alice:
Hit:1 http://archive.ubuntu.com/ubuntu jammy InRelease
...
# Re-run command number 6
$ !6
mkdir projects
mkdir: cannot create directory 'projects': File exists
# Re-run the most recent command starting with "cd"
$ !cd
cd projects
# Use the last argument of the previous command
$ mkdir /home/alice/newproject
$ cd !$
cd /home/alice/newproject
# Interactive reverse search with Ctrl+R
# Press Ctrl+R, then type part of a command:
(reverse-i-search)`apt': sudo apt update
# Press Enter to run it, or Ctrl+R again to find an older match
# Press Ctrl+C or Ctrl+G to cancel the search
# Check your history size settings
$ echo $HISTSIZE
1000
$ echo $HISTFILESIZE
2000
# Increase history size (add to ~/.bashrc for persistence)
$ export HISTSIZE=5000
$ export HISTFILESIZE=10000
# Clear all history (be careful!)
$ history -c
# Delete a specific entry (e.g., if you typed a password)
$ history -d 42
# Prevent a command from being saved: start with a space
$  secret-command    # Note the leading space
# (Requires HISTCONTROL=ignorespace or ignoreboth)
Warning: Your history file (~/.bash_history) may contain sensitive information such as passwords accidentally typed on the command line. Avoid typing passwords directly in commands. Use history -d to remove sensitive entries.
Tip: Ctrl+R is by far the most efficient way to find a previous command. Start using it today and you will wonder how you ever lived without it.

6. man — Manual Pages

What It Does

man displays the manual page (documentation) for a command. Virtually every command installed on a Linux system comes with a man page explaining its options, syntax, and usage. Think of man as the built-in reference library.

Why It Matters

You do not need to memorize every flag of every command. When you forget how something works, man is right there on your system — no internet required. Learning to read man pages is a superpower.

Syntax

man [SECTION] COMMAND

Man Page Sections

SectionContents
1User commands (most common)
2System calls (kernel functions)
3Library functions (C library)
4Special files (/dev)
5File formats (e.g., /etc/passwd)
6Games
7Miscellaneous (conventions, protocols)
8System administration commands

Navigation Inside man

KeyAction
Space / fScroll forward one page
bScroll backward one page
j / DownScroll down one line
k / UpScroll up one line
/patternSearch forward for "pattern"
?patternSearch backward for "pattern"
nNext search result
NPrevious search result
qQuit the man page
gGo to the top
GGo to the bottom

Practical Examples

# Read the manual for the ls command
$ man ls
LS(1)                     User Commands                     LS(1)

NAME
       ls - list directory contents

SYNOPSIS
       ls [OPTION]... [FILE]...

DESCRIPTION
       List information about the FILEs (the current directory by default).
       ...
# Read the manual for a specific section
# (e.g., passwd the command vs passwd the file format)
$ man 1 passwd      # The passwd command
$ man 5 passwd      # The /etc/passwd file format
# Search for man pages by keyword
$ man -k "copy files"
cp (1)               - copy files and directories
install (1)          - copy files and set attributes
scp (1)              - OpenSSH secure file copy
# Alternative: apropos does the same as man -k
$ apropos "list directory"
dir (1)              - list directory contents
ls (1)               - list directory contents
vdir (1)             - list directory contents
# Inside man, search for a specific option:
# 1. Open the man page: man ls
# 2. Type /-h and press Enter
# 3. Press n to jump to the next match
# This finds the -h flag description quickly
# Show a one-line description of a command
$ whatis ls
ls (1)               - list directory contents
$ whatis cat
cat (1)              - concatenate files and print on the standard output
# Read the man page for man itself
$ man man
# Quick help: many commands support --help for a short summary
$ ls --help
Usage: ls [OPTION]... [FILE]...
List information about the FILEs ...
  -a, --all                  do not ignore entries starting with .
  -l                         use a long listing format
  ...
# Some commands use info pages (GNU-style extended docs)
$ info coreutils
Tip: When a man page is too long, jump straight to the section you need. Type /EXAMPLES inside the man viewer to go to the examples section (if one exists). Many man pages have an EXAMPLES section near the bottom.
Note: The --help flag provides a quick summary. Use man for the full documentation. When you need to search for a command but do not know its name, use man -k keyword or apropos keyword.

7. which and whereis — Locate Commands

What They Do

which tells you the exact file path of a command — the binary that runs when you type the command name. whereis goes further, also showing the location of man pages and source code if available.

Why They Matter

When you have multiple versions of a program installed (e.g., Python 2 and Python 3), which tells you which one runs by default. When something is not working, which helps you confirm the right binary is being used.

Syntax

which COMMAND
which -a COMMAND      # Show ALL matching binaries in PATH

whereis COMMAND
whereis -b COMMAND    # Show only binary locations
whereis -m COMMAND    # Show only man page locations
whereis -s COMMAND    # Show only source locations

Options

CommandOptionDescription
which-aShow all matches in PATH, not just the first
whereis-bOnly search for binaries
whereis-mOnly search for manual pages
whereis-sOnly search for source code

Practical Examples

# Where is the ls binary?
$ which ls
/usr/bin/ls
# Where is python?
$ which python3
/usr/bin/python3
# Show ALL locations for python (if multiple installed)
$ which -a python3
/usr/bin/python3
/usr/local/bin/python3
# Check if a command exists (useful in scripts)
$ which git
/usr/bin/git
$ which nonexistent
                              # No output = not found
$ echo $?
1                              # Exit code 1 = failure
# whereis: find binary, man page, and source
$ whereis ls
ls: /usr/bin/ls /usr/share/man/man1/ls.1.gz
# whereis: only binaries
$ whereis -b bash
bash: /usr/bin/bash /bin/bash
# whereis: only man pages
$ whereis -m grep
grep: /usr/share/man/man1/grep.1.gz
# which does NOT find shell built-ins; type does
$ which cd
                              # No output - cd is a built-in
$ type cd
cd is a shell builtin
# type can also show aliases and functions
$ type ls
ls is aliased to 'ls --color=auto'
$ type -a ls
ls is aliased to 'ls --color=auto'
ls is /usr/bin/ls
ls is /bin/ls
# Useful debugging: is the right version running?
$ which node
/usr/local/bin/node
$ /usr/local/bin/node --version
v20.11.0
Tip: Use type as a more comprehensive alternative to which. It finds built-ins, aliases, functions, and external binaries. type -a command shows everything.

Common Mistakes

Wrong: Using which to find shell built-ins like cd, echo, or history.
Right: Use type command to find built-ins. which only searches $PATH for external binaries.

8. echo — Print Text to the Terminal

What It Does

echo prints text (or the value of variables) to the standard output. It is the simplest way to display a message, show the value of a variable, or write text to a file from the command line.

Why It Matters

echo is foundational for shell scripting and daily debugging. You will use it to inspect variable values, write quick messages, generate file contents, and build output strings. It appears in nearly every shell script.

Syntax

echo [OPTIONS] [STRING...]

Options

OptionDescription
-nDo not add a trailing newline
-eEnable interpretation of escape characters (\n, \t, etc.)
-EDisable escape interpretation (default in Bash)

Common Escape Characters (with -e)

EscapeMeaning
\nNewline
\tTab
\\Literal backslash
\aAlert (bell)
\033[...]ANSI color codes

Practical Examples

# Print a simple message
$ echo "Hello, World!"
Hello, World!
# Print the value of a variable
$ echo $HOME
/home/alice
$ echo $USER
alice
$ echo $PATH
/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
# Print without a trailing newline (-n)
$ echo -n "Loading..."
Loading...$    # No newline, prompt appears on same line
# Use escape characters with -e
$ echo -e "Line 1\nLine 2\nLine 3"
Line 1
Line 2
Line 3
# Tabs for aligned output
$ echo -e "Name\tAge\tCity"
Name    Age     City
$ echo -e "Alice\t30\tNew York"
Alice   30      New York
# Write text to a file (overwrite)
$ echo "Hello" > greeting.txt
$ cat greeting.txt
Hello
# Append text to a file
$ echo "World" >> greeting.txt
$ cat greeting.txt
Hello
World
# Single quotes: everything is literal (no variable expansion)
$ echo 'My home is $HOME'
My home is $HOME

# Double quotes: variables ARE expanded
$ echo "My home is $HOME"
My home is /home/alice
# Show all environment variables (combine echo with env)
$ echo $SHELL
/bin/bash
$ echo $LANG
en_US.UTF-8
# Command substitution with echo
$ echo "Today is $(date +%A)"
Today is Tuesday
$ echo "There are $(ls | wc -l) items here"
There are 6 items here
# Use echo to create a quick multi-line file
$ echo -e "#!/bin/bash\necho 'Hello from script'" > hello.sh
$ cat hello.sh
#!/bin/bash
echo 'Hello from script'
# Print colored text using ANSI codes
$ echo -e "\033[31mRed text\033[0m and normal text"
Red text and normal text
$ echo -e "\033[32mGreen\033[0m \033[34mBlue\033[0m \033[33mYellow\033[0m"
Green Blue Yellow
# Echo with wildcard expansion (the shell expands *, not echo)
$ echo *.txt
greeting.txt notes.txt todo.txt

Common Mistakes

Wrong: Forgetting the difference between single and double quotes. 
$ echo 'User: $USER'
User: $USER    # Literal, not expanded!
Right: Use double quotes when you want variable expansion. 
$ echo "User: $USER"
User: alice
Wrong: Using > when you meant >> (overwrites the file!). 
$ echo "new line" > important.txt    # ERASES old content!
Right: Use >> to append safely. 
$ echo "new line" >> important.txt   # Adds to end of file
Danger: echo "text" > file overwrites the file without warning. There is no undo. Double-check before using > with important files.

9. uname — System Information

What It Does

uname prints information about your system: the kernel name, version, architecture, hostname, and more. It answers the question "What system am I running on?"

Why It Matters

When troubleshooting, installing software, or writing scripts that need to work across different systems, you need to know your kernel version, architecture (32-bit vs 64-bit), and OS name. uname gives you all of that.

Syntax

uname [OPTIONS]

Options

OptionDescription
-aPrint all information
-sKernel name (e.g., Linux)
-nNetwork hostname
-rKernel release version
-vKernel version (build date)
-mMachine hardware architecture (e.g., x86_64)
-pProcessor type
-oOperating system name

Practical Examples

# Print all system information at once
$ uname -a
Linux myserver 5.15.0-91-generic #101-Ubuntu SMP Tue Nov 14 13:30:08 UTC 2023 x86_64 x86_64 x86_64 GNU/Linux
# Kernel name only
$ uname -s
Linux
# Kernel release version
$ uname -r
5.15.0-91-generic
# Machine architecture (is it 64-bit?)
$ uname -m
x86_64
# Operating system
$ uname -o
GNU/Linux
# Hostname
$ uname -n
myserver
# Combine specific flags
$ uname -sr
Linux 5.15.0-91-generic
# Use in a script to detect architecture

10. hostname — Show or Set the System Hostname

What It Does

hostname displays the name of your computer on the network. Every Linux machine has a hostname — it is how the system identifies itself. You can also use it to show IP addresses and domain information.

Why It Matters

When you SSH into multiple servers, the hostname in your prompt is often the only way to tell which machine you are on. In networked environments, the hostname is critical for DNS resolution, logging, and service discovery.

Syntax

hostname [OPTIONS]

Options

OptionDescription
-f / --fqdnShow the fully qualified domain name (FQDN)
-IShow all IP addresses of the host
-iShow the IP address associated with the hostname
-sShow the short hostname (before the first dot)
-dShow the DNS domain name

Practical Examples

# Show the current hostname
$ hostname
myserver
# Show the fully qualified domain name
$ hostname -f
myserver.example.com
# Show all IP addresses
$ hostname -I
192.168.1.100 10.0.0.5
# Show the short hostname
$ hostname -s
myserver
# Show the DNS domain
$ hostname -d
example.com
# The hostname is also stored in an environment variable
$ echo $HOSTNAME
myserver
# Temporarily change hostname (requires root, resets on reboot)
$ sudo hostname newname
$ hostname
newname
# Permanently change hostname on systemd-based systems
$ sudo hostnamectl set-hostname myserver
$ hostnamectl
   Static hostname: myserver
         Icon name: computer-vm
           Chassis: vm
        Machine ID: abc123...
           Boot ID: def456...
    Virtualization: kvm
  Operating System: Ubuntu 22.04.3 LTS
            Kernel: Linux 5.15.0-91-generic
      Architecture: x86-64
# Check hostname in the hosts file
$ cat /etc/hostname
myserver
# hostnamectl shows detailed system identity (systemd)
$ hostnamectl status
   Static hostname: myserver
   Pretty hostname: My Development Server
         ...
Warning: Changing the hostname on a running server can break services that depend on the hostname (databases, web servers, monitoring agents). Always plan hostname changes carefully and update /etc/hosts accordingly.

Common Mistakes

Wrong: Using sudo hostname newname and thinking it persists across reboots.
Right: Use sudo hostnamectl set-hostname newname for a permanent change on systemd systems. Also update /etc/hosts.

Quizzes

Quiz 1: Command Knowledge Check

  1. What does cd - do?

    1. Goes to the root directory
    2. Goes to the home directory
    3. Goes to the previous directory you were in
    4. Goes up one directory level
    Answer

    c) cd - toggles to the previous directory. cd / goes to root, cd or cd ~ goes home, and cd .. goes up one level.

  2. Which command shows hidden files?

    1. ls -l
    2. ls -h
    3. ls -a
    4. ls -R
    Answer

    c) ls -a shows all files including hidden ones (those starting with a dot). -l is long format, -h is human-readable sizes, -R is recursive.

  3. What happens when you type echo 'The value is $HOME'?

    1. It prints The value is /home/alice
    2. It prints The value is $HOME
    3. It gives an error
    4. It prints nothing
    Answer

    b) Single quotes prevent variable expansion. The literal string $HOME is printed. To expand the variable, use double quotes: echo "The value is $HOME".

  4. You run apt update and get a permission error. What is the fastest fix?

    1. sudo apt update (retype the whole thing)
    2. sudo !!
    3. su root
    4. history | grep apt
    Answer

    b) sudo !! re-runs the previous command with sudo prepended. It is the fastest way to fix a forgotten sudo.

  5. What does uname -m output on a 64-bit Intel/AMD system?

    1. Linux
    2. x86_64
    3. amd64
    4. 64bit
    Answer

    b) uname -m shows the machine hardware name. On 64-bit x86 systems, this is x86_64. On ARM it might be aarch64.

Quiz 2: Scenario-Based Questions

  1. You are in /home/alice/Documents/projects/webapp and need to get to /home/alice/Downloads. Which of these works?

    1. cd ../../../Downloads
    2. cd ~/Downloads
    3. cd /home/alice/Downloads
    4. All of the above
    Answer

    d) All three work. Option (a) uses relative paths going up three levels then into Downloads. Option (b) uses the ~ shortcut for home. Option (c) uses an absolute path. In practice, (b) is the quickest to type.

  2. You accidentally ran cat /bin/ls and your terminal shows garbled characters. How do you fix it?

    1. Close the terminal and open a new one
    2. Type reset and press Enter (even if you cannot see what you type)
    3. Press Ctrl+L
    4. Both (a) and (b) work, but (b) is faster
    Answer

    d) Both work, but reset reinitializes the terminal without losing your session. Ctrl+L only clears the screen and will not fix garbled encoding.

  3. You need to find out if git is installed and where it lives. What is the best command?

    1. find / -name git
    2. which git
    3. ls /usr/bin/git
    4. man git
    Answer

    b) which git quickly tells you if git is in your PATH and shows its location. find is slow and overkill. ls assumes you know the path. man shows documentation but does not confirm the binary location.

  4. What does the number 1 in man 1 passwd refer to?

    1. Show page 1 of the manual
    2. The first version of the command
    3. Section 1 (user commands) of the manual
    4. Show only 1 line of output
    Answer

    c) Man pages are organized into sections. Section 1 covers user commands. Section 5 covers file formats. So man 1 passwd shows the passwd command, while man 5 passwd shows the /etc/passwd file format.
