Chapter 10: Archives & Compression

Archives and compression are fundamental to working with Linux. You will encounter .tar.gz files when downloading software, use zip files when sharing with non-Linux users, and create backups using tar. This chapter teaches you to create, inspect, and extract archives in every common format.

What You Will Learn

How to create and extract archives with tar, compress files with gzip/bzip2/xz, work with zip files, and choose the right format for each situation.

Archive vs Compression

Mental Model: Archive vs Compression

These are two separate concepts that are often combined:

Archiving = bundling multiple files and directories into a single file. Think of it like putting documents into a folder. The size does not change. Tool: tar

Compression = making a file smaller by encoding data more efficiently. Think of it like vacuum-sealing a bag. The number of items does not change, but the size shrinks. Tools: gzip, bzip2, xz

Archive + Compression = bundling files together AND making the bundle smaller. This is what .tar.gz does — first tar creates the archive, then gzip compresses it.

file1.txt (10 KB)  ─┐
file2.txt (20 KB)   ├── tar ──→ archive.tar (30 KB) ──→ gzip ──→ archive.tar.gz (8 KB)
file3.txt ( 5 KB)  ─┘          (same size, one file)            (smaller, one file)

     Multiple files          Archive (no compression)      Archive + Compression

The exception is zip, which archives and compresses in one step. It is the standard on Windows but less common in the Linux world.

tar — Tape Archive

What it does: tar creates, extracts, and lists archive files. Despite the name ("tape archive"), it is used everywhere — not just tapes. It is the most important archiving tool on Linux.

Why it matters: Almost every piece of Linux software is distributed as a .tar.gz or .tar.xz file. Backups, deployments, and file transfers all use tar.

Modern tar auto-detects compression

On modern systems, tar -xf archive.tar.gz works without specifying -z. Tar will auto-detect the compression format. However, when creating archives, you must specify the compression flag.

Examples: Creating Archives

$ tar -cf backup.tar documents/
# Create an uncompressed tar archive
$ tar -cvf backup.tar documents/
# Create with verbose output (lists each file)
documents/
documents/report.txt
documents/notes.md
documents/images/
documents/images/photo.jpg
$ tar -czf backup.tar.gz documents/
# Create a gzip-compressed archive (.tar.gz)
$ tar -cjf backup.tar.bz2 documents/
# Create a bzip2-compressed archive (.tar.bz2)
$ tar -cJf backup.tar.xz documents/
# Create an xz-compressed archive (.tar.xz) — best compression
$ tar -czf project-backup.tar.gz --exclude='.git' --exclude='node_modules' project/
# Exclude .git and node_modules directories
$ tar -czf backup-$(date +%Y%m%d).tar.gz /home/alice/
# Create a dated backup: backup-20260331.tar.gz

Examples: Listing Contents

$ tar -tf archive.tar
# List all files in an uncompressed archive
documents/
documents/report.txt
documents/notes.md
documents/images/
documents/images/photo.jpg
$ tar -tzf archive.tar.gz
# List files in a gzip archive
$ tar -tvf archive.tar.gz
# List with details (permissions, size, date)

-rw-r--r-- alice/alice  2456 2026-03-30 10:15 documents/report.txt

$ tar -tzf archive.tar.gz | head -10
# Peek at the first 10 entries
$ tar -tzf archive.tar.gz | wc -l
127
# Count how many files are in the archive

Examples: Extracting Archives

$ tar -xf archive.tar
# Extract to current directory
$ tar -xzf archive.tar.gz
# Extract gzip archive
$ tar -xvzf archive.tar.gz
# Extract with verbose output
$ tar -xzf archive.tar.gz -C /opt/
# Extract to a specific directory
$ tar -xzf archive.tar.gz documents/report.txt
# Extract only a specific file from the archive
$ tar -xzf archive.tar.gz --wildcards '*.txt'
# Extract only .txt files
Security Warning: Do Not Extract Untrusted Archives Blindly

A malicious tar archive can contain files with absolute paths (like /etc/passwd) or relative paths with ../../ that overwrite files outside the extraction directory. Always inspect first:

# ALWAYS list contents before extracting an untrusted archive:
$ tar -tzf suspicious.tar.gz | head -20
# Look for paths starting with / or containing ../
# If you see those, DO NOT extract or use --one-top-level:
$ tar -xzf suspicious.tar.gz --one-top-level=safe-dir/

The --one-top-level flag forces everything into a single directory, preventing path traversal attacks.

More tar Examples

$ tar -czf - documents/ | ssh alice@server "cat > /backup/docs.tar.gz"
# Create archive and pipe directly to remote server via SSH
$ tar -czf backup.tar.gz -T filelist.txt
# Create archive from a list of files
$ tar -uf archive.tar newfile.txt
# Append a file to an existing (uncompressed) archive
$ tar --diff -f archive.tar
# Compare archive contents with the filesystem
Common Mistake
$ tar -czf *.tar.gz project/
# Glob expands *.tar.gz before tar sees it!
# If old archives exist, this will NOT work as expected.
Correct
$ tar -czf project-backup.tar.gz project/
# Always specify the exact filename for the archive.

gzip / gunzip — Compress & Decompress .gz Files

What it does: gzip compresses a single file, replacing it with a .gz version. gunzip (or gzip -d) decompresses it back.

Why it matters: gzip is the most common compression format on Linux. It is fast and offers a good balance of speed and compression ratio. The .tar.gz format uses gzip for compression.

Flags Reference

FlagMeaning
-dDecompress (same as gunzip)
-kKeep the original file (do not delete it)
-vVerbose (show compression ratio)
-lList compression info for a .gz file
-rRecursively compress files in a directory
-1 to -9Compression level (1=fastest/least, 9=slowest/most). Default is 6.
-cWrite to stdout (useful for piping)

Examples

$ gzip file.txt
# Compresses file.txt → file.txt.gz (original is deleted!)
$ gzip -k file.txt
# Compress but keep the original file
$ gunzip file.txt.gz
# Decompress file.txt.gz → file.txt (gz file is deleted)
$ gzip -d file.txt.gz
# Same as gunzip
$ gzip -dk file.txt.gz
# Decompress and keep the .gz file
$ gzip -v file.txt
file.txt:	 72.3% -- replaced with file.txt.gz
$ gzip -l file.txt.gz
  compressed  uncompressed  ratio  uncompressed_name
       12345         45678  73.0%  file.txt
$ gzip -9 largefile.log
# Maximum compression (slower but smaller)
$ gzip -1 largefile.log
# Fastest compression (larger but quicker)
$ zcat file.txt.gz
# View compressed file contents without decompressing
$ zgrep "error" logfile.gz
# Search inside a compressed file without decompressing
$ cat file.txt | gzip -c > file.txt.gz
# Compress from stdin to a file
gzip Deletes the Original

By default, gzip file.txt replaces file.txt with file.txt.gz — the original is gone. Use -k (keep) to preserve the original.

gzip Only Compresses Single Files

gzip compresses one file at a time. It cannot compress a directory. That is why we combine it with tar: tar bundles the directory into one file, then gzip compresses that file. The result is .tar.gz.

zip / unzip — Create & Extract .zip Files

What it does: zip creates .zip archives (combining archiving and compression in one step). unzip extracts them. The .zip format is universal — supported on Windows, macOS, and Linux.

Why it matters: When sharing files with non-Linux users, .zip is the most compatible format. Every operating system can open zip files without additional software.

Examples

$ zip archive.zip file1.txt file2.txt file3.txt
# Zip multiple files
  adding: file1.txt (deflated 62%)
  adding: file2.txt (deflated 58%)
  adding: file3.txt (deflated 71%)
$ zip -r project.zip project/
# Zip a directory recursively (-r is required for directories!)
$ unzip archive.zip
# Extract to current directory
Archive:  archive.zip
  inflating: file1.txt
  inflating: file2.txt
  inflating: file3.txt
$ unzip archive.zip -d /opt/extracted/
# Extract to a specific directory
$ unzip -l archive.zip
# List contents without extracting
Archive:  archive.zip
  Length      Date    Time    Name
---------  ---------- -----   ----
     2456  2026-03-31 14:00   file1.txt
     1893  2026-03-31 14:00   file2.txt
     4521  2026-03-31 14:00   file3.txt
---------                     -------
     8870                     3 files
$ unzip archive.zip file1.txt
# Extract only a specific file
$ zip -e secure.zip sensitive-data.txt
# Create a password-protected zip file
Enter password:
Verify password:
$ zip -u archive.zip newfile.txt
# Update: add new file or replace modified file in existing zip
$ zip -r project.zip project/ -x "project/.git/*" "project/node_modules/*"
# Zip directory excluding certain paths
$ unzip -o archive.zip
# Overwrite existing files without prompting
$ unzip -t archive.zip
# Test archive integrity (do not extract)
    testing: file1.txt                OK
    testing: file2.txt                OK
    testing: file3.txt                OK
No errors detected in compressed data of archive.zip.
$ zip -9 -r archive.zip project/
# Maximum compression
Common Mistake
$ zip archive.zip project/
# Without -r, only the empty directory is zipped!
Correct
$ zip -r archive.zip project/
# -r includes all files and subdirectories

xz — High Compression

What it does: xz provides the highest compression ratios of the common Linux compression tools. It produces .xz files and is used for .tar.xz archives.

Why it matters: Many Linux distributions use .tar.xz for their software packages because it achieves significantly smaller files than gzip. The tradeoff is that compression (not decompression) is slower and uses more memory.

Examples

$ xz file.txt
# Compress file.txt → file.txt.xz (original is deleted)
$ xz -k file.txt
# Compress and keep original
$ xz -d file.txt.xz
# Decompress (or use unxz)
$ unxz file.txt.xz
# Same as xz -d
$ xz -dk file.txt.xz
# Decompress and keep the .xz file
$ xz -v file.txt
file.txt (1/1)
  100 %        2,345 B / 12,678 B = 0.185   1.2 MiB/s     0:00
$ xz -l file.txt.xz
# Show compression info
Strms  Blocks   Compressed Uncompressed  Ratio  Check   Filename
    1       1      2,345 B     12,678 B  0.185  CRC64   file.txt.xz
$ xz -9 largefile.log
# Maximum compression (very slow but smallest output)
$ xz -0 largefile.log
# Fastest compression (still better than gzip at same speed)
$ xzcat file.txt.xz
# View contents without decompressing
$ xz -T 4 largefile.log
# Use 4 threads for faster compression
$ xz -T 0 largefile.log
# Use all available CPU threads

Compression Format Comparison

Format Extension Compression Speed Decompression Speed Compression Ratio CPU/Memory Usage Compatibility
gzip .tar.gz / .tgz Fast Fast Good Low Universal (everywhere on Linux)
bzip2 .tar.bz2 / .tbz2 Slow Moderate Better than gzip Moderate Common on Linux, less elsewhere
xz .tar.xz / .txz Very Slow Fast Best High (compression) Standard for distro packages
zip .zip Fast Fast Good (similar to gzip) Low Best (Windows, macOS, Linux)
zstd .tar.zst Very Fast Very Fast Very Good Low to Moderate Growing (newer tool)
Which Format Should You Use?
  • General purpose / speed matters: .tar.gz — the safe default
  • Smallest file size: .tar.xz — when you compress once and distribute many times (like software releases)
  • Sharing with Windows/macOS users: .zip — the universal format
  • Modern fast compression: .tar.zst — if all recipients have zstd installed
  • Avoid bzip2 for new projects — xz is better in almost every way

Real-World Scenarios

$ # Backup a project, excluding build artifacts
tar -czf ~/backups/myproject-$(date +%Y%m%d).tar.gz \
  --exclude='.git' \
  --exclude='node_modules' \
  --exclude='__pycache__' \
  --exclude='*.pyc' \
  ~/projects/myproject/

Knowledge Check

You receive a file called data.tar.bz2. Which command extracts it?
B. tar -xjf data.tar.bz2 is correct. The -j flag specifies bzip2 decompression. Option A uses -z which is for gzip. On modern systems, tar -xf data.tar.bz2 (without any compression flag) also works because tar auto-detects the format.

More Practical tar Examples

1. Archive Excluding Certain Files

$ tar -czf project.tar.gz project/ --exclude='*.log' --exclude='*.tmp'
# Exclude all .log and .tmp files from the archive
$ tar -czf project.tar.gz project/ \
  --exclude='.git' \
  --exclude='node_modules' \
  --exclude='__pycache__' \
  --exclude='*.pyc' \
  --exclude='.env'
# Exclude common development clutter
# This keeps the archive small and avoids bundling secrets (.env)
$ tar -czf website.tar.gz /var/www/html/ --exclude='uploads/cache/*'
# Exclude only the cache subdirectory inside uploads
Exclude patterns use relative paths

Patterns in --exclude are matched against the path as stored in the archive, not the full filesystem path. Use tar -tzf to check what paths look like inside the archive if you are unsure.

2. Archive with Date in Filename

$ tar -czf backup-$(date +%Y%m%d).tar.gz /home/alice/documents/
# Creates: backup-20260331.tar.gz
$ tar -czf backup-$(date +%Y%m%d-%H%M%S).tar.gz /home/alice/documents/
# Creates: backup-20260331-143025.tar.gz (with time for multiple daily backups)
$ tar -czf "project-$(date +%F).tar.gz" project/
# Creates: project-2026-03-31.tar.gz  (%F = %Y-%m-%d)
$ BACKUP_NAME="myapp-$(date +%Y%m%d-%H%M).tar.gz"
$ tar -czf "$BACKUP_NAME" /opt/myapp/
$ echo "Backup saved as $BACKUP_NAME"
Backup saved as myapp-20260331-1430.tar.gz

3. Archive and Split into Parts

Large archives can be split into smaller parts for easier transfer (e.g., when a file sharing service has a size limit).

$ tar -czf - largedir/ | split -b 100M - largedir-backup.tar.gz.part-
# Creates 100 MB chunks:
#   largedir-backup.tar.gz.part-aa
#   largedir-backup.tar.gz.part-ab
#   largedir-backup.tar.gz.part-ac
#   ...
$ # To reassemble and extract:
cat largedir-backup.tar.gz.part-* | tar -xzf -
# Concatenates all parts back together and extracts
$ # Split into a specific number of files instead of by size:
tar -czf - bigproject/ | split -n 5 - bigproject.tar.gz.part-
# Splits into exactly 5 equal parts

4. List Contents Before Extracting

Always inspect an archive before extracting, especially if you did not create it yourself.

$ tar -tzf download.tar.gz | head -20
# Preview the first 20 entries
myapp-2.0/
myapp-2.0/README.md
myapp-2.0/src/
myapp-2.0/src/main.c
myapp-2.0/Makefile
$ tar -tzf download.tar.gz | grep -c "/"
47
# Count how many entries are in the archive
$ # Check if archive has a single top-level directory (well-behaved):
tar -tzf download.tar.gz | head -1
myapp-2.0/
# Good — everything is inside myapp-2.0/
$ # Check for dangerous paths (absolute or path traversal):
tar -tzf suspicious.tar.gz | grep -E "^/|\.\./"
# If this produces output, the archive may overwrite system files!

5. Extract Specific Files from Archive

$ tar -xzf project.tar.gz project/README.md
# Extract only README.md (must use the exact path shown by -t)
$ tar -xzf project.tar.gz --wildcards '*.conf'
# Extract all .conf files from anywhere in the archive
$ tar -xzf project.tar.gz --wildcards 'project/src/*.c' -C /tmp/review/
# Extract only C source files into /tmp/review/
$ tar -xzf backup.tar.gz --wildcards '*/config/*'
# Extract only files inside any config/ directory

6. Incremental Backups with tar

Incremental backups save only the files that changed since the last backup. This is much faster and uses less space than full backups every time.

$ # First backup (full/level-0) — creates a snapshot file
tar --listed-incremental=/home/alice/backup.snar \
    -czf /backups/full-$(date +%Y%m%d).tar.gz \
    /home/alice/documents/
# backup.snar stores metadata about what was backed up
$ # Second backup (incremental/level-1) — only changed files
tar --listed-incremental=/home/alice/backup.snar \
    -czf /backups/incr-$(date +%Y%m%d).tar.gz \
    /home/alice/documents/
# Only files modified since the full backup are included
# The .snar file is updated automatically
$ # To restore: apply full backup first, then each incremental in order
tar --listed-incremental=/dev/null -xzf /backups/full-20260331.tar.gz -C /restore/
tar --listed-incremental=/dev/null -xzf /backups/incr-20260401.tar.gz -C /restore/
tar --listed-incremental=/dev/null -xzf /backups/incr-20260402.tar.gz -C /restore/
Keep the snapshot file safe

The .snar file is essential for incremental backups. If you lose it, tar cannot determine what changed, and you will need to start a new full backup. Store it alongside your backup archives.

7. Compressing with Different Levels

You can control the compression level by passing environment variables or by compressing in a separate step.

$ GZIP=-9 tar -czf max-compressed.tar.gz largedir/
# Maximum gzip compression (slowest but smallest)
$ GZIP=-1 tar -czf fast-compressed.tar.gz largedir/
# Fastest gzip compression (largest but quickest)
$ XZ_OPT=-9 tar -cJf max-compressed.tar.xz largedir/
# Maximum xz compression
$ XZ_OPT='-T4 -6' tar -cJf threaded.tar.xz largedir/
# xz with 4 threads at compression level 6
$ # Or compress in a separate step for more control:
tar -cf archive.tar largedir/
gzip -9 archive.tar
# Result: archive.tar.gz with maximum compression

8. Using tar with Pipes (Remote Backup via SSH)

One of the most powerful tar features is piping to/from other commands. This lets you transfer files between machines without creating a local archive first.

$ # Send a directory to a remote server:
tar -czf - /home/alice/project/ | ssh alice@server "cat > /backups/project.tar.gz"
# The "-" means "write to stdout" instead of a file
# The archive streams directly over SSH to the remote machine
$ # Copy a directory to a remote server and extract it there:
tar -czf - /home/alice/project/ | ssh alice@server "tar -xzf - -C /opt/"
# Archives locally, streams over SSH, extracts remotely
# No intermediate file is created on either machine
$ # Pull a directory FROM a remote server:
ssh alice@server "tar -czf - /var/www/html/" | tar -xzf - -C /tmp/
# Remote server archives and sends, local machine receives and extracts
$ # Copy between two remote servers (using local machine as a bridge):
ssh alice@server1 "tar -czf - /data/" | ssh alice@server2 "tar -xzf - -C /data/"
# Data flows: server1 → your machine → server2
Why pipes are powerful

When you use tar -czf -, the archive is never saved to disk. It streams directly through the pipe. This means you do not need free disk space for a temporary archive, and the transfer starts immediately without waiting for compression to finish.

Exercise 3: Exclude and Split

Practice creating archives with exclusions and splitting them:

  1. Create a project directory with subdirectories: src/, build/, logs/, node_modules/.
  2. Put a few files in each subdirectory.
  3. Create a .tar.gz archive of the project, excluding build/, logs/, and node_modules/.
  4. List the contents of the archive to verify the excluded directories are not present.
  5. Now create an archive of the full project and split it into 1 MB chunks.
  6. Reassemble the chunks and extract to /tmp/reassembled/.
Show Solution 
# 1-2. Create project structure with files
$ mkdir -p ~/testproject/{src,build,logs,node_modules}
$ echo "main code" > ~/testproject/src/main.c
$ echo "build artifact" > ~/testproject/build/output.o
$ echo "log entry" > ~/testproject/logs/app.log
$ echo "module data" > ~/testproject/node_modules/dep.js
$ echo "readme" > ~/testproject/README.md

# 3. Archive with exclusions
$ tar -czf ~/testproject-clean.tar.gz \
    --exclude='build' --exclude='logs' --exclude='node_modules' \
    -C ~/ testproject/

# 4. Verify exclusions
$ tar -tzf ~/testproject-clean.tar.gz
testproject/
testproject/src/
testproject/src/main.c
testproject/README.md

# 5. Create full archive and split into 1 MB parts
$ tar -czf - -C ~/ testproject/ | split -b 1M - ~/testproject-split.tar.gz.part-

# 6. Reassemble and extract
$ mkdir -p /tmp/reassembled
$ cat ~/testproject-split.tar.gz.part-* | tar -xzf - -C /tmp/reassembled/
$ ls /tmp/reassembled/testproject/
Exercise 4: Remote Backup Simulation

Practice using tar with pipes (you can simulate this locally):

  1. Create a directory ~/important-data/ with several files.
  2. Use tar -czf - to pipe the archive into another tar -xzf - that extracts to /tmp/mirror/.
  3. Compare the contents of both directories with diff -r.
  4. Now use tar -czf - piped to split to create 512K chunks, then reassemble and extract.
Show Solution 
# 1. Create source data
$ mkdir -p ~/important-data
$ echo "financial report Q1" > ~/important-data/report.txt
$ echo '{"db":"prod","port":5432}' > ~/important-data/config.json
$ dd if=/dev/urandom of=~/important-data/data.bin bs=1K count=500 2>/dev/null

# 2. Pipe tar to tar (simulates network transfer)
$ mkdir -p /tmp/mirror
$ tar -czf - -C ~/ important-data/ | tar -xzf - -C /tmp/mirror/

# 3. Verify the copy is identical
$ diff -r ~/important-data/ /tmp/mirror/important-data/
# No output = directories are identical

# 4. Split into chunks, reassemble, extract
$ tar -czf - -C ~/ important-data/ | split -b 512K - /tmp/data-part-
$ ls -lh /tmp/data-part-*
$ mkdir -p /tmp/from-chunks
$ cat /tmp/data-part-* | tar -xzf - -C /tmp/from-chunks/
$ diff -r ~/important-data/ /tmp/from-chunks/important-data/
Exercise 5: Incremental Backup Practice

Practice incremental backups with tar:

  1. Create a directory ~/incr-test/ with 3 files.
  2. Create a full (level-0) backup using --listed-incremental.
  3. Add 2 new files and modify 1 existing file.
  4. Create an incremental (level-1) backup.
  5. List the contents of both archives. The incremental should be smaller.
  6. Restore from both backups into /tmp/restored/ and verify all 5 files are present.
Show Solution 
# 1. Create initial files
$ mkdir -p ~/incr-test
$ echo "file one" > ~/incr-test/one.txt
$ echo "file two" > ~/incr-test/two.txt
$ echo "file three" > ~/incr-test/three.txt

# 2. Full backup
$ tar --listed-incremental=~/incr-test.snar \
    -czf ~/full-backup.tar.gz -C ~/ incr-test/

# 3. Modify data
$ echo "file four" > ~/incr-test/four.txt
$ echo "file five" > ~/incr-test/five.txt
$ echo "modified file one" > ~/incr-test/one.txt

# 4. Incremental backup
$ tar --listed-incremental=~/incr-test.snar \
    -czf ~/incr-backup.tar.gz -C ~/ incr-test/

# 5. Compare archive contents
$ echo "--- Full backup ---" && tar -tzf ~/full-backup.tar.gz
$ echo "--- Incremental ---" && tar -tzf ~/incr-backup.tar.gz
$ ls -lh ~/full-backup.tar.gz ~/incr-backup.tar.gz
# Incremental archive should be smaller

# 6. Restore (full first, then incremental)
$ mkdir -p /tmp/restored
$ tar --listed-incremental=/dev/null -xzf ~/full-backup.tar.gz -C /tmp/restored/
$ tar --listed-incremental=/dev/null -xzf ~/incr-backup.tar.gz -C /tmp/restored/
$ ls /tmp/restored/incr-test/
five.txt  four.txt  one.txt  three.txt  two.txt
$ cat /tmp/restored/incr-test/one.txt
modified file one

Wrong vs Correct: Common tar Mistakes

These are mistakes that almost everyone makes at least once. Learn from them here instead of in production.

Wrong: Forgetting the -f flag
$ tar -cz backup.tar.gz mydir/
# Without -f, tar does not know "backup.tar.gz" is the filename.
# It treats "backup.tar.gz" as a file to archive!
# Result: an archive written to stdout (garbage on screen).
Correct: Always include -f
$ tar -czf backup.tar.gz mydir/
# -f tells tar the next argument is the archive filename.
Wrong: Putting -f before compression flag
$ tar -cfz backup.tar.gz mydir/
# -f grabs the NEXT argument as the filename.
# Here -f sees "z" as the filename, not "backup.tar.gz"!
# Creates a file literally named "z".
Correct: Put -f last (before the filename)
$ tar -czf backup.tar.gz mydir/
# -f is last among the grouped flags, so "backup.tar.gz" is correctly
# interpreted as the filename.
Wrong: Extracting without checking directory
$ cd /
$ tar -xzf /tmp/backup.tar.gz
# Extracts into / (root!) — files could scatter everywhere
# or overwrite system files if the archive has absolute paths.
Correct: Always specify or verify the target directory
$ mkdir -p /tmp/extracted
$ tar -xzf /tmp/backup.tar.gz -C /tmp/extracted/
# -C ensures files are extracted to a safe, known location.
Wrong: Overwriting the source with the archive
$ tar -czf mydir/backup.tar.gz mydir/
# The archive is INSIDE the directory being archived!
# tar will try to archive its own output file — this causes
# errors or a corrupted archive.
Correct: Save the archive outside the source directory
$ tar -czf /tmp/backup.tar.gz mydir/
# Archive is stored outside of mydir/, avoiding the loop.
Wrong: Using the wrong compression flag
$ tar -czf backup.tar.xz mydir/
# The filename says .xz but -z means gzip compression!
# The file is actually gzip-compressed despite the .xz extension.
# Anyone trying to open it with xz will get errors.
Correct: Match the flag to the extension
$ tar -cJf backup.tar.xz mydir/
# -J = xz compression, matching the .tar.xz extension.
# -z = gzip (.tar.gz), -j = bzip2 (.tar.bz2), -J = xz (.tar.xz)
