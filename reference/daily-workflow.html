Linux Daily Workflow for Beginners

This page walks you through a typical day using Linux as a developer or junior sysadmin. Each section covers a real task you will do regularly, with exact commands and expected output. Follow along in your own terminal to build muscle memory.

How to use this page

Read through each section in order. Open a terminal and type the commands yourself. Over time, this sequence will become second nature. Bookmark this page and revisit it during your first weeks with Linux.

1. Morning: Check the System

The first thing to do when you sit down at a Linux machine (especially a server) is check that everything is healthy. These quick checks take under a minute and tell you if anything needs attention.

How long has the system been running?

$ uptime
 09:01:23 up 45 days,  3:22,  2 users,  load average: 0.15, 0.20, 0.18

This tells you:

  • Current time: 09:01:23
  • Uptime: 45 days, 3 hours, 22 minutes since last reboot
  • Users: 2 users currently logged in
  • Load average: CPU load over the last 1, 5, and 15 minutes. Values below the number of CPU cores are healthy.

How much disk space is left?

$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       500G  120G  355G  26% /
tmpfs           7.8G   24M  7.8G   1% /dev/shm
/dev/sdb1       1.0T  450G  550G  45% /data
Watch the Use% column

If any filesystem is above 80%, investigate. At 90% or above, take action immediately. Full disks cause applications to crash, databases to corrupt, and logs to stop writing.

How much memory is available?

$ free -h
              total        used        free      shared  buff/cache   available
Mem:           15Gi       4.2Gi       8.1Gi       256Mi       3.1Gi        10Gi
Swap:         2.0Gi          0B       2.0Gi

Focus on the available column, not "free." Linux uses spare memory for caching, which is normal and healthy. If "available" is low and "swap" is being used heavily, you may have a memory problem.

Check recent logs for errors

# Check the last 20 lines of the system log
$ sudo tail -20 /var/log/syslog
Mar 31 09:00:01 server CRON[12345]: (root) CMD (test -x /usr/sbin/anacron ...)
Mar 31 09:01:00 server systemd[1]: Started Session 45 of user admin.
...

# Search for errors in the last hour
$ sudo journalctl --since "1 hour ago" -p err
-- No entries --
# Good news - no errors in the last hour
Make it a one-liner

Create an alias to run all morning checks at once:

# Add to ~/.bashrc
morning() {
    echo "=== Uptime ==="
    uptime
    echo ""
    echo "=== Disk Usage ==="
    df -h | grep -E '^/dev'
    echo ""
    echo "=== Memory ==="
    free -h | head -2
    echo ""
    echo "=== Recent Errors ==="
    sudo journalctl --since "1 hour ago" -p err --no-pager 2>/dev/null || echo "No errors"
}

$ morning
=== Uptime ===
 09:01:23 up 45 days,  3:22,  2 users,  load average: 0.15, 0.20, 0.18

=== Disk Usage ===
/dev/sda1       500G  120G  355G  26% /
/dev/sdb1       1.0T  450G  550G  45% /data

=== Memory ===
              total        used        free      shared  buff/cache   available
Mem:           15Gi       4.2Gi       8.1Gi       256Mi       3.1Gi        10Gi

=== Recent Errors ===
No errors

2. Navigate Your Project

Once you know the system is healthy, navigate to your working directory and orient yourself.

# Go to your project directory
$ cd ~/projects/my-web-app
$ pwd
/home/user/projects/my-web-app

# See what is here
$ ls -la

Navigation shortcuts

Use cd - to go back to the previous directory. Use cd ~ to go home. Use pushd/popd to manage a stack of directories. Tab completion saves typing.

3. Work with Files

Throughout the day, you will create, edit, and manage files constantly. Here is a typical sequence.

Create a new file

# Create a new source file
$ touch src/routes/profile.js

# Or create it with initial content
$ cat <<'EOF' > src/routes/profile.js
// Profile routes
const express = require('express');
const router = express.Router();

router.get('/profile', (req, res) => {
    res.json({ user: req.user });
});

module.exports = router;
EOF

Edit a file with nano

$ nano src/routes/profile.js

# Inside nano:
# - Type to add text
# - Ctrl+O then Enter to save
# - Ctrl+X to exit
# - Ctrl+K to cut a line
# - Ctrl+U to paste a line
# - Ctrl+W to search

Copy and back up files

# Make a backup before a risky edit
$ cp src/routes/auth.js src/routes/auth.js.bak

# Copy a file to another directory
$ cp src/utils/helpers.js tests/fixtures/

# Copy an entire directory
$ cp -r src/routes/ src/routes-backup/

Move and rename files

# Rename a file
$ mv src/routes/profile.js src/routes/user-profile.js

# Move a file to a different directory
$ mv old-notes.txt ~/Documents/archive/

Delete files you no longer need

# Delete a backup you no longer need
$ rm src/routes/auth.js.bak

# Delete a directory and its contents (be careful!)
$ rm -ri src/routes-backup/
rm: descend into 'src/routes-backup/'? y
rm: remove regular file 'src/routes-backup/auth.js'? y
rm: remove directory 'src/routes-backup/'? y

4. Search for Things

You will constantly need to find files and search for text. These are the commands you will use most.

Search for text inside files

# Find all files containing "TODO" in your project
$ grep -rn "TODO" src/
src/routes/auth.js:15:    // TODO: Add rate limiting
src/utils/helpers.js:42:  // TODO: Handle edge case for empty input

# Search for a function definition
$ grep -rn "function validateUser" src/
src/utils/helpers.js:10:function validateUser(data) {

# Case-insensitive search
$ grep -rni "error" /var/log/syslog | tail -5

Find files by name

# Find all JavaScript files in the project
$ find . -name "*.js" -type f
./src/index.js
./src/routes/auth.js
./src/routes/user-profile.js
./src/utils/helpers.js
./tests/test_routes.js
./tests/test_utils.js

# Find files modified today
$ find . -name "*.js" -mtime 0
./src/routes/auth.js
./src/routes/user-profile.js

# Find large files (over 10 MB)
$ find ~ -type f -size +10M -exec ls -lh {} \; 2>/dev/null | head -5

Search your command history

# Search history for a previous command
$ history | grep "docker"
 1042  docker ps
 1043  docker build -t myapp .
 1055  docker-compose up -d

# Interactive reverse search: press Ctrl+R and start typing
(reverse-i-search)`dock': docker-compose up -d
# Press Enter to run it, or Ctrl+R again to see older matches
Faster searching with grep

grep -rn is your best friend. -r = recursive (search all subdirectories), -n = show line numbers. Add -i for case-insensitive and -l to show only matching filenames.

Throughout the day, you will need to check on running processes, especially when something seems slow or unresponsive.

Quick process check

# See all your running processes
$ ps aux --sort=-%mem | head -10
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
user     15234  2.1  8.5 1234567 130000 ?      Sl   08:30   1:23 node server.js

mysql    12345  1.2  2.8  654321  43000 ?       Ssl  Mar30   5:42 /usr/sbin/mysqld

# Find a specific process
$ ps aux | grep "node"

# Or use pgrep for just PIDs
$ pgrep -a node
15234 node server.js

6. Install or Update Software

On Debian/Ubuntu systems (the most common for beginners), you use apt to manage software.

Update package lists and upgrade

# Update the list of available packages
$ sudo apt update
Hit:1 http://archive.ubuntu.com/ubuntu jammy InRelease
Get:2 http://security.ubuntu.com/ubuntu jammy-security InRelease [110 kB]
...
Reading package lists... Done
12 packages can be upgraded. Run 'apt list --upgradable' to see them.

# See what can be upgraded
$ apt list --upgradable
Listing...
libssl3/jammy-security 3.0.2-0ubuntu1.16 amd64 [upgradable from: 3.0.2-0ubuntu1.15]
nginx/jammy-security 1.18.0-6ubuntu14.5 amd64 [upgradable from: 1.18.0-6ubuntu14.4]
...

# Upgrade all packages
$ sudo apt upgrade -y

Install new software

# Search for a package
$ apt search tree
tree/jammy 2.0.2-1 amd64
  list contents of directories in a tree-like format

# Install it
$ sudo apt install tree
Reading package lists... Done
The following NEW packages will be installed:
  tree
Do you want to continue? [Y/n] y

# Verify installation
$ which tree
/usr/bin/tree
$ tree --version
tree v2.0.2
Always update before installing

Run sudo apt update before installing new packages. This ensures you get the latest version available.

7. Transfer Files

Moving files between machines is a daily task, whether deploying code, pulling data, or sharing files.

Copy files to/from a remote server with scp

# Copy a local file to a remote server
$ scp report.pdf user@server:/home/user/Documents/
report.pdf                     100%  2.3MB  10.5MB/s   00:00

# Copy a file from a remote server to local
$ scp user@server:/var/log/app.log ./logs/
app.log                        100%  15MB   12.0MB/s   00:01

# Copy an entire directory
$ scp -r user@server:/home/user/project/ ./project-copy/

Sync directories with rsync

# Sync a local directory to a remote server
$ rsync -avz ~/projects/my-app/ user@server:/var/www/my-app/
sending incremental file list
./
src/routes/auth.js
src/routes/user-profile.js
sent 4,567 bytes  received 123 bytes  3,126.67 bytes/sec
total size is 45,678  speedup is 9.74

# Dry run first to see what would be transferred
$ rsync -avz --dry-run ~/projects/my-app/ user@server:/var/www/my-app/

# Sync and delete files on remote that no longer exist locally
$ rsync -avz --delete ~/projects/my-app/ user@server:/var/www/my-app/
rsync vs scp

Use scp for simple, one-time copies. Use rsync for syncing directories, especially large ones, because rsync only transfers files that have changed. Always use --dry-run first with rsync.

8. End of Day: Clean Up

Before wrapping up for the day, check that things are tidy and your work is saved.

Check disk usage again

# Quick disk check
$ df -h /
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       500G  122G  353G  26% /

# Find what is using the most space in your home directory
$ du -h --max-depth=1 ~ 2>/dev/null | sort -rh | head -10
2.3G    /home/user
850M    /home/user/.cache
420M    /home/user/Downloads
310M    /home/user/projects
180M    /home/user/Documents

Remove temporary files

# Clean up your Downloads folder
$ ls ~/Downloads/
report-v1.pdf  report-v2.pdf  report-final.pdf  temp.zip  old-installer.deb

$ rm ~/Downloads/temp.zip ~/Downloads/old-installer.deb

# Clean the apt cache (can recover significant space)
$ sudo apt clean
$ sudo apt autoremove -y
Removing linux-headers-5.15.0-90 ...
0 upgraded, 0 newly installed, 3 to remove and 0 not upgraded.

# Clear old journal logs (keep last 7 days)
$ sudo journalctl --vacuum-time=7d
Vacuuming done, freed 120.0M of archived journals.

Commit and push your work

$ cd ~/projects/my-web-app
$ git status
On branch feature/user-auth
Changes not staged for commit:
  modified:   src/routes/auth.js
Untracked files:
  src/routes/user-profile.js

$ git add -A
$ git commit -m "Add user profile endpoint"
[feature/user-auth d4e5f6g] Add user profile endpoint
 2 files changed, 45 insertions(+), 3 deletions(-)
 create mode 100644 src/routes/user-profile.js

$ git push origin feature/user-auth

Back up important work

# Create a quick backup of today's work
$ tar -czf ~/backups/my-web-app-$(date +%Y%m%d).tar.gz -C ~/projects my-web-app/
$ ls -lh ~/backups/
-rw-r--r-- 1 user user 2.3M Mar 31 17:30 my-web-app-20260331.tar.gz
-rw-r--r-- 1 user user 2.1M Mar 30 17:30 my-web-app-20260330.tar.gz

9. Essential Keyboard Shortcuts

These keyboard shortcuts will save you hundreds of keystrokes every day. Learn them and use them constantly.

Terminal Control Shortcuts

Shortcut What It Does When to Use It
Ctrl+C Cancel / interrupt the running command A command is taking too long or you typed it wrong
Ctrl+D Exit the current shell / send EOF Log out of SSH, exit a sub-shell, close the terminal
Ctrl+Z Suspend the current process Pause a running program to do something else (resume with fg or bg)
Ctrl+L Clear the terminal screen The screen is cluttered and you want a fresh view (same as typing clear)
Ctrl+R Reverse history search Find and rerun a previous command by typing part of it
Tab Auto-complete file names and commands Always. Press Tab after typing the first few characters of any filename or command
Tab Tab Show all possible completions When Tab does not complete uniquely, press it again to see all options
Up Arrow Previous command from history Rerun or modify the last command
Down Arrow Next command from history Navigate forward through history after pressing Up

Command Line Editing Shortcuts

Shortcut What It Does
Ctrl+A Move cursor to the beginning of the line
Ctrl+E Move cursor to the end of the line
Ctrl+W Delete the word before the cursor
Ctrl+U Delete from cursor to the beginning of the line
Ctrl+K Delete from cursor to the end of the line
Alt+B Move cursor back one word
Alt+F Move cursor forward one word
!! Repeat the last command (type as two exclamation marks)
!$ Reuse the last argument of the previous command

Shortcuts in action

# You forgot sudo:
$ apt update
E: Could not open lock file - open (13: Permission denied)

# Rerun with sudo using !!:
$ sudo !!
sudo apt update
Hit:1 http://archive.ubuntu.com/ubuntu ...

# Reuse the last argument with !$:
$ mkdir /tmp/my-new-directory
$ cd !$
cd /tmp/my-new-directory

# Tab completion example:
$ cat /etc/ho[Tab]
cat /etc/hostname
# Bash completed "ho" to "hostname" because it is the only match
The #1 time saver: Tab completion

If you learn only one shortcut, let it be Tab. It autocompletes file paths, command names, and arguments. It prevents typos, saves typing, and works everywhere. Press it constantly.

Putting It All Together

A Complete Daily Routine

# === MORNING ===
$ uptime                        # Check system health
$ df -h                         # Check disk space
$ free -h                       # Check memory

# === START WORKING ===
$ cd ~/projects/my-app          # Navigate to project
$ git pull                      # Get latest changes
$ git status                    # See where you left off

# === DURING THE DAY ===
$ nano src/feature.js           # Edit files
$ grep -rn "TODO" src/          # Find todos
$ find . -name "*.log" -delete  # Clean up logs
$ ps aux | grep node            # Check processes
$ sudo systemctl restart nginx  # Restart services

# === END OF DAY ===
$ git add -A                    # Stage changes
$ git commit -m "Feature done"  # Commit work
$ git push                      # Push to remote
$ du -h --max-depth=1 ~         # Check home dir size
$ sudo apt clean                # Clean package cache
Practice makes it natural

Your first week using Linux will feel slow. That is normal. By the end of your first month, these commands will become automatic. The key is to use the terminal every day, even for simple tasks. Resist the urge to use a GUI file manager. The terminal is faster once you build the habit.

Daily Challenge

Try this for one week: every morning when you open your terminal, run the morning checks (uptime, df, free). Throughout the day, use Ctrl+R instead of retyping commands. At the end of the day, commit your work and clean up temp files. After seven days, these steps will feel natural.
