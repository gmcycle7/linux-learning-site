Practice Exercises

The best way to learn Linux is to practice. These exercises are organized by difficulty and cover the most important topics from this guide. Each exercise has clear instructions, the expected outcome, and a collapsible answer you can check after trying on your own.

How to use these exercises

Open a terminal and try each exercise before looking at the answer. If you get stuck, re-read the relevant chapter linked in each exercise. Typing the commands yourself (not copy-pasting) builds muscle memory.

Practice safely

Use a test directory (e.g., ~/linux-practice/) for all exercises. Do not run commands against system files or directories unless the exercise specifically instructs it (e.g., reading /etc/passwd). Never use sudo unless the exercise requires it.

Beginner Exercises

These exercises cover basic navigation, file management, and fundamental commands. You should be comfortable with Chapters 1 through 4 before attempting these.

Exercise B1: Navigate and List Files

Task: Navigate to your home directory, print the current working directory, and list all files including hidden ones in long format.

Expected outcome: You should see your home directory path and a detailed listing showing hidden files (starting with .), permissions, owner, size, and modification dates.

Show Answer 
$ cd ~
$ pwd
/home/yourusername

$ ls -la
total 48
drwxr-xr-x 6 user user 4096 Mar 31 09:00 .
drwxr-xr-x 3 root root 4096 Jan 15 08:00 ..
-rw------- 1 user user 1234 Mar 30 22:00 .bash_history
-rw-r--r-- 1 user user  220 Jan 15 08:00 .bashrc
drwxr-xr-x 2 user user 4096 Mar 28 14:00 Documents
drwxr-xr-x 2 user user 4096 Mar 25 10:00 Downloads
...

Key points: cd ~ takes you home. ls -la combines -l (long format) and -a (show all, including hidden). Entries starting with . are hidden files.

Exercise B2: Create a Directory Structure

Task: Create the following directory structure in one command:

project/
├── src/
├── docs/
└── tests/

Then verify the structure exists using ls.

Expected outcome: A project directory containing three subdirectories: src, docs, and tests.

Show Answer 
$ mkdir -p project/{src,docs,tests}
$ ls project/
docs  src  tests

# Or verify with tree if installed:
$ tree project/
project/
├── docs
├── src
└── tests

Key points: mkdir -p creates parent directories as needed. Brace expansion {src,docs,tests} creates multiple directories at once. No spaces after commas inside braces.

Exercise B3: Create, Copy, Move, and Delete Files

Task: Create 5 files named file1.txt through file5.txt. Copy file1.txt and file2.txt to a new directory called backup/. Move file3.txt to backup/. Delete file4.txt. List the contents of both directories.

Expected outcome: The current directory has file1.txt, file2.txt, file5.txt. The backup/ directory has file1.txt, file2.txt, file3.txt.

Show Answer 
$ touch file1.txt file2.txt file3.txt file4.txt file5.txt
$ mkdir backup
$ cp file1.txt file2.txt backup/
$ mv file3.txt backup/
$ rm file4.txt

$ ls
backup  file1.txt  file2.txt  file5.txt

$ ls backup/
file1.txt  file2.txt  file3.txt

Key points: touch creates empty files. cp copies (original remains). mv moves (original is gone from the source). rm permanently deletes.

Task: Display the first 5 lines and the last 5 lines of the /etc/passwd file.

Exercise B5: Find Your User Information

Task: Find your username, your user ID (UID), your primary group ID (GID), and all the groups you belong to.

Expected outcome: Your username, a numeric UID (typically 1000 for the first user), and a list of groups.

Exercise B7: Create and View a File with Content

Task: Create a file called notes.txt containing three lines: "Line 1: Hello", "Line 2: World", "Line 3: Done". Display its contents and count the number of lines, words, and characters.

Expected outcome: The file contents displayed, followed by line/word/character counts.

Show Answer 
# Method 1: Using echo with -e for newlines
$ echo -e "Line 1: Hello\nLine 2: World\nLine 3: Done" > notes.txt

# Method 2: Using a here document
$ cat <<EOF > notes.txt

Line 2: World

$ cat notes.txt

Line 2: World
Line 3: Done

Key points: echo -e interprets escape sequences like \n. Here documents (<<EOF) allow multi-line input. wc shows lines, words, and bytes by default.

Exercise B9: Use Man Pages

Task: Use the man page for the cp command to find out what the -p flag does. Then use cp -p to copy a file while preserving its timestamps.

Expected outcome: You should find that -p preserves mode, ownership, and timestamps. The copied file should have the same modification time as the original.

Show Answer 
$ man cp
# Search for -p by pressing / then typing -p then Enter
# You'll find: -p  same as --preserve=mode,ownership,timestamps
# Press q to quit man

$ touch -t 202301150900 original.txt   # Create file with specific timestamp
$ ls -l original.txt
-rw-r--r-- 1 user user 0 Jan 15  2023 original.txt

$ cp -p original.txt copy_preserved.txt
$ cp original.txt copy_normal.txt

$ ls -l original.txt copy_preserved.txt copy_normal.txt
-rw-r--r-- 1 user user 0 Mar 31 10:00 copy_normal.txt
-rw-r--r-- 1 user user 0 Jan 15  2023 copy_preserved.txt
-rw-r--r-- 1 user user 0 Jan 15  2023 original.txt

Key points: In man, press / to search, n for next match, q to quit. cp -p preserves timestamps. Without -p, the copy gets the current time.

Exercise B10: Understand File Permissions

Task: Create a file and a directory. Check their default permissions. Change the file to be readable by everyone but writable only by the owner. Make the directory accessible only to the owner.

Expected outcome: The file has -rw-r--r-- (644) permissions. The directory has drwx------ (700) permissions.

Show Answer 
$ touch myfile.txt
$ mkdir mydir

# Check default permissions
$ ls -la myfile.txt mydir
-rw-rw-r-- 1 user user 0 Mar 31 10:00 myfile.txt
drwxrwxr-x 2 user user 4096 Mar 31 10:00 mydir

# Set file: owner rw, group r, others r (644)
$ chmod 644 myfile.txt

# Set directory: owner only (700)
$ chmod 700 mydir

$ ls -la myfile.txt mydir
-rw-r--r-- 1 user user 0 Mar 31 10:00 myfile.txt
drwx------ 2 user user 4096 Mar 31 10:00 mydir

Key points: 6 = rw (4+2), 4 = r (read only), 0 = no access. 7 = rwx (4+2+1). First digit = owner, second = group, third = others.

Intermediate Exercises

These exercises combine multiple commands and concepts. You should be comfortable with Chapters 5 through 10 before attempting these.

Exercise I1: Find Large Log Files

Task: Find all .log files in /var/log that are larger than 1 MB. Sort them by size, largest first.

Expected outcome: A list of log files larger than 1 MB with their sizes, sorted from largest to smallest.

Show Answer 
# Method 1: Using find with -size
$ sudo find /var/log -name "*.log" -size +1M -exec ls -lh {} \; | sort -k5 -hr
-rw-r----- 1 syslog adm 25M Mar 31 09:00 /var/log/syslog
-rw-r----- 1 syslog adm 12M Mar 30 23:59 /var/log/kern.log
-rw-r--r-- 1 root   root 3.5M Mar 31 08:00 /var/log/dpkg.log

# Method 2: Using find with -printf for cleaner output
$ sudo find /var/log -name "*.log" -size +1M -printf "%s %p\n" | sort -nr | \
  awk '{printf "%.1fM %s\n", $1/1048576, $2}'
25.0M /var/log/syslog
12.0M /var/log/kern.log
3.5M /var/log/dpkg.log

Key points: find -size +1M matches files larger than 1 megabyte. -exec runs a command on each result. sort -hr sorts human-readable sizes in reverse.

Task: Create a test directory with 5 .txt files containing varying numbers of lines. Count the number of lines in each file and display the total across all files.

Expected outcome: Line counts for each file and a grand total.

Show Answer 
# Setup: create test files
$ mkdir -p ~/practice/textfiles && cd ~/practice/textfiles
$ seq 10 > a.txt
$ seq 25 > b.txt
$ seq 50 > c.txt
$ seq 100 > d.txt
$ seq 5 > e.txt

# Count lines in all .txt files
$ wc -l *.txt
  10 a.txt
  25 b.txt
  50 c.txt
 100 d.txt

Exercise I3: Create a Compressed Backup

Task: Create a directory called my-project with several files in it. Create a compressed .tar.gz archive of the entire directory. Then list the archive contents without extracting. Finally, extract it to a different location.

Expected outcome: A .tar.gz file, a listing of its contents, and a successful extraction to a new location.

Show Answer 
# Setup
$ mkdir -p ~/practice/my-project
$ echo "readme content" > ~/practice/my-project/README.md
$ echo "main code" > ~/practice/my-project/main.py
$ echo "config here" > ~/practice/my-project/config.yaml

# Create the archive
$ cd ~/practice
$ tar -czvf my-project-backup.tar.gz my-project/
my-project/
my-project/README.md
my-project/main.py
my-project/config.yaml

# List contents without extracting
$ tar -tzvf my-project-backup.tar.gz
drwxr-xr-x user/user   0 2026-03-31 10:00 my-project/
-rw-r--r-- user/user  15 2026-03-31 10:00 my-project/README.md
-rw-r--r-- user/user  10 2026-03-31 10:00 my-project/main.py
-rw-r--r-- user/user  12 2026-03-31 10:00 my-project/config.yaml

# Extract to a different location
$ mkdir ~/practice/restored
$ tar -xzvf my-project-backup.tar.gz -C ~/practice/restored/
$ ls ~/practice/restored/my-project/
config.yaml  main.py  README.md

Key points: -c = create, -x = extract, -t = list, -z = gzip compression, -v = verbose, -f = filename. -C specifies the extraction directory.

Exercise I4: Find Recently Modified Files

Task: Find all files in your home directory (not subdirectories) that were modified in the last 24 hours. Show them with their modification times.

Expected outcome: A list of recently modified files with timestamps.

Show Answer 
# Find files modified in last 24 hours (maxdepth 1 = no subdirectories)
$ find ~ -maxdepth 1 -type f -mtime -1 -exec ls -lh {} \;
-rw------- 1 user user 12K Mar 31 09:45 /home/user/.bash_history
-rw-r--r-- 1 user user  55 Mar 31 08:30 /home/user/.lesshst

# Alternative: using -mmin for minutes (last 60 minutes)
$ find ~ -maxdepth 1 -type f -mmin -60

# Using -newer to find files modified after a reference file
$ touch -t 202603310000 /tmp/reference    # midnight today
$ find ~ -maxdepth 1 -type f -newer /tmp/reference

Key points: -mtime -1 means modified less than 1 day ago. -mmin -60 means modified less than 60 minutes ago. -maxdepth 1 prevents descending into subdirectories. -type f matches only regular files.

Exercise I5: Find the Five Most Common Words in a File

Task: Create a text file with at least 20 words (some repeated). Write a single pipe chain that finds the 5 most common words and displays them with their counts.

Expected outcome: A ranked list of the top 5 words with occurrence counts.

Show Answer 
# Create a test file
$ cat <<EOF > words.txt
the quick brown fox jumps over the lazy dog
the dog chased the fox around the yard
the fox was quick but the dog was quicker
quick fox quick dog the end
EOF

# Find top 5 most common words
$ cat words.txt | tr -s ' ' '\n' | tr '[:upper:]' '[:lower:]' | sort | uniq -c | sort -rn | head -5
      8 the
      4 quick
      4 fox
      3 dog
      2 was

Pipeline explained:

  1. tr -s ' ' '\n' — replace spaces with newlines (one word per line)
  2. tr '[:upper:]' '[:lower:]' — convert to lowercase
  3. sort — sort alphabetically (required for uniq)
  4. uniq -c — count consecutive identical lines
  5. sort -rn — sort numerically in reverse (highest first)
  6. head -5 — take the top 5

Exercise I7: Process Management

Task: Start a long-running command in the background. Check that it is running. Bring it to the foreground. Suspend it. Resume it in the background. Then stop it.

Expected outcome: You should demonstrate the full lifecycle of a background process.

Show Answer 
# Start a long-running process in the background
$ sleep 300 &
[1] 12345

# Check it is running
$ jobs
[1]+  Running                 sleep 300 &

$ ps aux | grep "sleep 300"
user     12345  0.0  0.0   8076   580 pts/0    S    10:00   0:00 sleep 300

# Bring it to the foreground
$ fg %1
sleep 300

# Suspend it with Ctrl+Z
^Z
[1]+  Stopped                 sleep 300

# Resume it in the background
$ bg %1
[1]+ sleep 300 &

# Stop it
$ kill %1
[1]+  Terminated              sleep 300

# Verify it is gone
$ jobs
# (no output - no running jobs)

Key points: & starts in background. jobs lists background jobs. fg brings to foreground. Ctrl+Z suspends. bg resumes in background. kill terminates.

Advanced Exercises

These exercises require combining multiple skills and writing scripts. You should be comfortable with Chapters 11 and 12 before attempting these.

Take your time

Advanced exercises may take 15 to 30 minutes each. It is normal to need multiple attempts. Read the hints before looking at the answer.

Exercise A1: Disk Usage Monitor Script

Task: Write a bash script called disk-check.sh that:

  1. Checks the disk usage percentage of the root filesystem (/).
  2. If usage is above 80%, prints a warning message with the current usage.
  3. If usage is above 90%, prints a critical alert.
  4. If usage is below 80%, prints an "all clear" message.

Hint: Use df to get the usage percentage, awk to extract it, and if statements to check thresholds.

Expected outcome: A working script that displays appropriate messages based on disk usage.

Show Answer 
#!/bin/bash
# disk-check.sh - Monitor disk usage and warn if high

# Get the usage percentage of the root filesystem (remove the % sign)
usage=$(df / | awk 'NR==2 {print $5}' | tr -d '%')

echo "Current disk usage: ${usage}%"

if [ "$usage" -ge 90 ]; then
    echo "CRITICAL: Disk usage is at ${usage}%! Immediate action required!"
    echo "Top 10 largest directories:"
    du -h --max-depth=1 / 2>/dev/null | sort -rh | head -10
elif [ "$usage" -ge 80 ]; then
    echo "WARNING: Disk usage is at ${usage}%. Consider cleaning up."
    echo "Suggestions:"
    echo "  - Clear package cache: sudo apt clean"
    echo "  - Remove old kernels: sudo apt autoremove"
    echo "  - Check /tmp: du -sh /tmp"
    echo "  - Check logs: du -sh /var/log"
else
    echo "OK: Disk usage is healthy at ${usage}%."
fi
$ chmod +x disk-check.sh
$ ./disk-check.sh
Current disk usage: 26%
OK: Disk usage is healthy at 26%.

Key points: df / gets root filesystem info. awk 'NR==2' gets the second line (data, not header). tr -d '%' removes the percent sign for numeric comparison. -ge means "greater than or equal to" in bash.

Exercise A2: Find and Kill Processes by User

Task: Write a command (or short script) that lists all processes owned by a specific user, shows their PID, CPU usage, memory usage, and command. Then demonstrate how to kill all processes by that user (use a test user, not root).

Hint: Use ps with user filtering, and pkill or killall for termination.

Expected outcome: A process listing filtered by user, and a safe method to terminate those processes.

Show Answer 
# List all processes by a specific user
$ ps -u username -o pid,pcpu,pmem,cmd --sort=-pcpu
    PID %CPU %MEM CMD
  12345  2.3  1.5 /usr/bin/python3 app.py
  12346  0.5  0.8 /usr/bin/node server.js
  12347  0.1  0.3 bash

# Count processes by user
$ ps -u username --no-headers | wc -l
3

# Kill all processes by user (CAREFUL - do not use on your own account!)
# Method 1: pkill (sends SIGTERM by default)
$ sudo pkill -u username

# Method 2: Force kill if SIGTERM does not work
$ sudo pkill -9 -u username

# Method 3: Using killall with a specific command
$ sudo killall -u username python3

# Safe approach: list first, then kill specific PIDs
$ ps -u username -o pid --no-headers
12345
12346
$ kill 12345 12346

Key points: Always list processes first before killing. pkill -u kills by username. kill sends SIGTERM (graceful). kill -9 sends SIGKILL (force). Never kill processes for root or your own session carelessly.

Exercise A3: Set Up SSH Key-Based Authentication

Task: Generate an SSH key pair, explain the purpose of each file created, and describe the steps to set up passwordless SSH login to a remote server.

Hint: Use ssh-keygen and ssh-copy-id.

Expected outcome: A key pair generated, understanding of public vs. private keys, and a working passwordless login procedure.

Show Answer 
# Step 1: Generate an SSH key pair
$ ssh-keygen -t ed25519 -C "your_email@example.com"
Generating public/private ed25519 key pair.
Enter file in which to save the key (/home/user/.ssh/id_ed25519): [Enter]
Enter passphrase (empty for no passphrase): [Enter or set a passphrase]
Your identification has been saved in /home/user/.ssh/id_ed25519
Your public key has been saved in /home/user/.ssh/id_ed25519.pub

# Step 2: Understand the files
$ ls -la ~/.ssh/
-rw-------  1 user user  411 Mar 31 10:00 id_ed25519       # PRIVATE key (NEVER share)
-rw-r--r--  1 user user   97 Mar 31 10:00 id_ed25519.pub   # PUBLIC key (safe to share)

# Step 3: Copy the public key to the remote server
$ ssh-copy-id user@remote-server.com
Number of key(s) added: 1

# Step 4: Test passwordless login
$ ssh user@remote-server.com
# You should connect without being asked for a password

# Manual method (if ssh-copy-id is not available):
$ cat ~/.ssh/id_ed25519.pub | ssh user@remote-server.com "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys && chmod 700 ~/.ssh"

Key concepts:

  • Private key (id_ed25519): stays on your machine. Permissions must be 600. Never share it.
  • Public key (id_ed25519.pub): placed on remote servers in ~/.ssh/authorized_keys.
  • ed25519 is the recommended algorithm (faster and more secure than RSA).
  • A passphrase adds an extra layer of security to your private key.

Exercise A5: Log File Analyzer Script

Task: Write a bash script that analyzes a log file and produces a summary report including:

  1. Total number of lines
  2. Number of ERROR, WARNING, and INFO entries
  3. The 5 most frequent error messages
  4. The hour of the day with the most log entries

Hint: Use grep -c, awk, sort, uniq -c, and head.

Expected outcome: A working script that produces a formatted log analysis report.

Show Answer 
#!/bin/bash
# log-analyzer.sh - Analyze a log file and produce a summary

if [ -z "$1" ]; then
    echo "Usage: $0 <logfile>"
    exit 1
fi

LOGFILE="$1"

if [ ! -f "$LOGFILE" ]; then
    echo "Error: File '$LOGFILE' not found."
    exit 1
fi

echo "========================================"
echo "  Log Analysis Report"
echo "  File: $LOGFILE"
echo "  Date: $(date)"
echo "========================================"
echo ""

# Total lines
total=$(wc -l < "$LOGFILE")
echo "Total log entries: $total"
echo ""

# Count by severity
errors=$(grep -c "ERROR" "$LOGFILE")
warnings=$(grep -c "WARN" "$LOGFILE")
infos=$(grep -c "INFO" "$LOGFILE")
echo "Severity Breakdown:"
echo "  ERROR:   $errors"
echo "  WARNING: $warnings"
echo "  INFO:    $infos"
echo ""

# Top 5 error messages
echo "Top 5 Most Frequent Error Messages:"
grep "ERROR" "$LOGFILE" | sed 's/.*ERROR[: ]*//' | sort | uniq -c | sort -rn | head -5 | \
    while read count msg; do
        printf "  %4d  %s\n" "$count" "$msg"
    done
echo ""

# Busiest hour
echo "Busiest Hours (top 5):"
awk '{print substr($0, 1, 13)}' "$LOGFILE" | grep -oE '[0-9]{2}:' | sort | uniq -c | sort -rn | head -5 | \
    while read count hour; do
        printf "  %4d entries at %s00\n" "$count" "$hour"
    done
echo ""
echo "========================================"
# Create a test log file
$ for i in $(seq 1 100); do
  hour=$(printf "%02d" $((RANDOM % 24)))
  level=$(shuf -e INFO INFO INFO WARN ERROR -n1)
  msg=$(shuf -e "disk full" "timeout" "connected" "retry" "success" -n1)
  echo "2026-03-31 ${hour}:$((RANDOM%60)):00 ${level}: ${msg}"
done > test.log

$ chmod +x log-analyzer.sh
$ ./log-analyzer.sh test.log

Exercise A6: Automated Backup Script with Rotation

Task: Write a script that creates a timestamped backup of a given directory, compresses it, and keeps only the 5 most recent backups (deleting older ones).

Expected outcome: A working backup script with automatic rotation.

Show Answer 
#!/bin/bash
# backup.sh - Create compressed backup with rotation

SOURCE_DIR="${1:-.}"            # Directory to backup (default: current)
BACKUP_DIR="${2:-$HOME/backups}" # Where to store backups
KEEP=5                          # Number of backups to keep

# Validate source directory
if [ ! -d "$SOURCE_DIR" ]; then
    echo "Error: Source directory '$SOURCE_DIR' does not exist."
    exit 1
fi

# Create backup directory if needed
mkdir -p "$BACKUP_DIR"

# Create backup filename with timestamp
DIRNAME=$(basename "$(realpath "$SOURCE_DIR")")
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
BACKUP_FILE="${BACKUP_DIR}/${DIRNAME}_${TIMESTAMP}.tar.gz"

# Create the backup
echo "Backing up '$SOURCE_DIR' to '$BACKUP_FILE'..."
tar -czf "$BACKUP_FILE" -C "$(dirname "$SOURCE_DIR")" "$DIRNAME"

if [ $? -eq 0 ]; then
    SIZE=$(du -h "$BACKUP_FILE" | cut -f1)
    echo "Backup created successfully ($SIZE)"
else
    echo "Error: Backup failed!"
    exit 1
fi

# Rotation: keep only the most recent backups
BACKUP_COUNT=$(ls -1 "${BACKUP_DIR}/${DIRNAME}_"*.tar.gz 2>/dev/null | wc -l)
if [ "$BACKUP_COUNT" -gt "$KEEP" ]; then
    DELETE_COUNT=$((BACKUP_COUNT - KEEP))
    echo "Rotating: removing $DELETE_COUNT old backup(s)..."
    ls -1t "${BACKUP_DIR}/${DIRNAME}_"*.tar.gz | tail -n "$DELETE_COUNT" | xargs rm -f
fi

echo "Current backups ($BACKUP_COUNT, keeping $KEEP):"
ls -lh "${BACKUP_DIR}/${DIRNAME}_"*.tar.gz

Exercise A7: Cron Job for Scheduled Tasks

Task: Set up a cron job that runs the disk check script (from Exercise A1) every day at 8:00 AM and appends the output to a log file. List your cron jobs to verify.

Expected outcome: A working crontab entry and understanding of cron syntax.

Show Answer 
# Edit your crontab
$ crontab -e

# Add this line (runs at 8:00 AM every day):
0 8 * * * /home/user/scripts/disk-check.sh >> /home/user/logs/disk-check.log 2>&1

# Cron syntax explained:
# ┌───────────── minute (0-59)
# │ ┌───────────── hour (0-23)
# │ │ ┌───────────── day of month (1-31)
# │ │ │ ┌───────────── month (1-12)
# │ │ │ │ ┌───────────── day of week (0-7, 0 and 7 = Sunday)
# │ │ │ │ │
# 0 8 * * * command

# Verify your crontab
$ crontab -l
0 8 * * * /home/user/scripts/disk-check.sh >> /home/user/logs/disk-check.log 2>&1

# Other useful cron schedules:
# Every 30 minutes:      */30 * * * *
# Every Monday at 9 AM:  0 9 * * 1
# First of every month:  0 0 1 * *
# Every weekday at 6 PM: 0 18 * * 1-5

Key points: Use crontab -e to edit, crontab -l to list. Always use full paths in cron jobs. Redirect output to a log file for debugging. 2>&1 captures both stdout and stderr.
