Common Linux Interview & Workplace Commands

This page covers the Linux commands and knowledge that come up most frequently in job interviews and daily workplace tasks. Whether you are preparing for a DevOps, sysadmin, or developer interview, or you just started a job that involves Linux servers, this is what you need to know.

How to use this page

Each section covers a topic area. For interview questions, read the question, try to answer it yourself, then check the provided answer. For workplace commands, practice them on a test system. The commands here are practical, not theoretical — these are what people actually type every day.

System Administration

Check System Resources (CPU, Memory, Disk)

One of the most common tasks: figuring out why a system is slow or a service is down.

# Quick system overview: uptime, users, load average
$ uptime
 14:30:00 up 90 days, 12:15,  3 users,  load average: 2.15, 1.80, 1.45

# CPU information
$ nproc
4
$ lscpu | grep "Model name"
Model name:   Intel(R) Xeon(R) CPU E5-2686 v4 @ 2.30GHz

# Memory usage
$ free -h
              total        used        free      shared  buff/cache   available
Mem:           15Gi       12Gi       512Mi       256Mi       3.1Gi       2.8Gi
Swap:         2.0Gi       1.2Gi       820Mi

# Disk usage
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       500G  420G   55G  89% /

# All three in one glance with vmstat
$ vmstat 1 5
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
 1  0 1228800 524288 131072 3276800  0    0    12    45  150  250 15  3 80  2  0
Interview tip: Load average

Load average shows the number of processes waiting for CPU time. A load average of 2.0 on a 4-core machine means 50% utilization (healthy). A load average of 8.0 on a 4-core machine means the system is overloaded. The three numbers show 1-minute, 5-minute, and 15-minute averages.

Check Open Ports

# Show all listening ports with process names
$ sudo ss -tulnp
Netid  State   Recv-Q  Send-Q  Local Address:Port  Peer Address:Port  Process
tcp    LISTEN  0       128     0.0.0.0:22           0.0.0.0:*          users:(("sshd",pid=1100))
tcp    LISTEN  0       511     0.0.0.0:80           0.0.0.0:*          users:(("nginx",pid=2200))
tcp    LISTEN  0       511     0.0.0.0:443          0.0.0.0:*          users:(("nginx",pid=2200))
tcp    LISTEN  0       151     127.0.0.1:3306       0.0.0.0:*          users:(("mysqld",pid=12345))

# Find which process is using a specific port
$ sudo ss -tulnp | grep :80
tcp    LISTEN  0  511  0.0.0.0:80  0.0.0.0:*  users:(("nginx",pid=2200,fd=6))

# Alternative with lsof
$ sudo lsof -i :80
COMMAND  PID     USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
nginx   2200     root    6u  IPv4  12345      0t0  TCP *:http (LISTEN)

# Check if a specific port is open from outside
$ nc -zv server.example.com 443
Connection to server.example.com 443 port [tcp/https] succeeded!
ss flags explained

-t = TCP, -u = UDP, -l = listening only, -n = show port numbers (not service names), -p = show process using the port. The old command was netstat -tulnp, but ss is the modern replacement.

View and Manage Services/Daemons

# Check status of a service
$ systemctl status nginx
● nginx.service - A high performance web server and a reverse proxy server
     Loaded: loaded (/lib/systemd/system/nginx.service; enabled; vendor preset: enabled)

$ sudo systemctl stop nginx

# List failed services
$ systemctl list-units --type=service --state=failed

Check System Logs

# View recent system logs
$ sudo journalctl -n 50             # Last 50 entries
$ sudo journalctl --since "1 hour ago"

# View logs for a specific service
$ sudo journalctl -u nginx -n 20
Mar 31 09:05:00 server systemd[1]: Starting A high performance web server...
Mar 31 09:05:00 server systemd[1]: Started A high performance web server.

# Follow logs in real time (like tail -f)
$ sudo journalctl -u nginx -f

# View only errors and above
$ sudo journalctl -p err -n 20

# Traditional log files
$ sudo tail -f /var/log/syslog         # System log
$ sudo tail -f /var/log/auth.log        # Authentication log
$ sudo tail -f /var/log/nginx/error.log # Nginx error log

# Search logs for a pattern
$ sudo journalctl | grep "Failed password"
Mar 31 03:15:00 server sshd[4567]: Failed password for invalid user admin from 203.0.113.50

File Management

Find Files by Various Criteria

# Find by name
$ find /etc -name "*.conf" -type f
/etc/nginx/nginx.conf
/etc/ssh/sshd_config
/etc/mysql/mysql.conf.d/mysqld.cnf

# Find by size (files larger than 100 MB)
$ find / -type f -size +100M 2>/dev/null
/var/lib/mysql/ibdata1
/var/log/syslog.1

# Find by modification time (modified in last 7 days)
$ find /var/log -type f -mtime -7

# Find by permissions (world-writable files, security concern)
$ find / -type f -perm -o+w 2>/dev/null

# Find by owner
$ find /home -user john -type f

# Find and execute a command on results
$ find /tmp -name "*.tmp" -mtime +30 -exec rm {} \;
# Deletes .tmp files in /tmp older than 30 days

# Find empty files and directories
$ find /var/log -empty -type f

Disk Usage Analysis

# Filesystem-level overview
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       500G  420G   55G  89% /

# Where is the space being used?
$ sudo du -h --max-depth=1 / 2>/dev/null | sort -rh | head -15
420G    /
180G    /var
120G    /home
85G     /opt
25G     /usr

# Drill down into /var
$ sudo du -h --max-depth=1 /var | sort -rh | head -10
180G    /var
150G    /var/lib
20G     /var/log
8G      /var/cache

# Find the single largest files on the system
$ sudo find / -type f -exec du -h {} + 2>/dev/null | sort -rh | head -10

# Check inode usage (can run out even with free disk space)
$ df -i
Filesystem       Inodes  IUsed    IFree IUse% Mounted on
/dev/sda1      32768000 245000 32523000    1% /
Inodes matter too

A filesystem can run out of inodes (file entries) even if there is free disk space. This happens when there are millions of tiny files. Check with df -i. Common culprit: mail queue directories or session files.

Permission Troubleshooting

# Check file permissions and ownership
$ ls -la /var/www/html/
total 12
drwxr-xr-x 2 root     root     4096 Mar 31 09:00 .
drwxr-xr-x 3 root     root     4096 Mar 01 06:00 ..
-rw-r--r-- 1 root     root      612 Mar 31 09:00 index.html
-rw-r----- 1 root     root      450 Mar 31 09:00 config.php

# Problem: web server (www-data) cannot read config.php
# Solution: change ownership
$ sudo chown www-data:www-data /var/www/html/config.php
$ sudo chmod 640 /var/www/html/config.php

# Check effective permissions for a user
$ sudo -u www-data test -r /var/www/html/config.php && echo "Readable" || echo "Not readable"
Readable

# Find files with SUID bit set (security audit)
$ find / -perm -4000 -type f 2>/dev/null
/usr/bin/sudo
/usr/bin/passwd
/usr/bin/su

Scripting & Automation

Common One-Liners

These one-liners come up in interviews and are genuinely useful in daily work.

# Count lines in a file
$ wc -l /var/log/syslog
125430 /var/log/syslog

# Find and replace text in a file
$ sed -i 's/old_string/new_string/g' config.txt

# Extract a specific column from output
$ awk '{print $1}' /var/log/access.log | sort | uniq -c | sort -rn | head -10
# Shows top 10 IP addresses in an access log

# Find duplicate files by checksum
$ find . -type f -exec md5sum {} + | sort | uniq -w32 -dD

# Watch a command run repeatedly (every 2 seconds)
$ watch -n 2 'df -h /'

# Run a command on multiple files
$ for f in *.log; do echo "Processing $f"; gzip "$f"; done

# Get the nth line of a file
$ sed -n '42p' largefile.txt       # Get line 42

# Remove blank lines from a file
$ sed -i '/^$/d' file.txt

# Sort a CSV by the 3rd column
$ sort -t',' -k3 -n data.csv

# Sum a column of numbers
$ awk '{sum += $1} END {print sum}' numbers.txt

Cron Job Basics

# View your cron jobs
$ crontab -l

# Edit your cron jobs
$ crontab -e

# Cron syntax:
# ┌───── minute (0-59)
# │ ┌───── hour (0-23)
# │ │ ┌───── day of month (1-31)
# │ │ │ ┌───── month (1-12)
# │ │ │ │ ┌───── day of week (0-7, 0 and 7 = Sunday)
# │ │ │ │ │
# * * * * * command

# Examples:
0 2 * * *   /usr/local/bin/backup.sh       # Every day at 2:00 AM
*/15 * * * * /usr/local/bin/health-check.sh # Every 15 minutes
0 9 * * 1   /usr/local/bin/weekly-report.sh # Every Monday at 9:00 AM
0 0 1 * *   /usr/local/bin/monthly-cleanup  # First of each month at midnight
30 6 * * 1-5 /usr/local/bin/morning.sh      # Weekdays at 6:30 AM

# View system-wide cron jobs
$ ls /etc/cron.d/
$ ls /etc/cron.daily/
$ ls /etc/cron.weekly/
Common cron pitfalls

Always use full paths in cron jobs (e.g., /usr/bin/python3 not just python3). Cron runs with a minimal environment. Redirect output to a log file for debugging: command >> /var/log/myjob.log 2>&1.

Common Interview Questions

How to answer interview questions

For each question, explain your approach first, then give the specific command. Interviewers want to see that you understand the problem, not just that you memorized a command.

Q1: "How would you find all files larger than 100 MB?"

Why they ask: Tests knowledge of find, file sizes, and practical disk management.

Show Answer 
# Find all files larger than 100 MB on the entire system
$ sudo find / -type f -size +100M 2>/dev/null

# With human-readable sizes, sorted largest first
$ sudo find / -type f -size +100M -exec ls -lh {} \; 2>/dev/null | sort -k5 -hr

# In a specific directory
$ find /var -type f -size +100M -exec du -h {} \; | sort -rh

Explanation: find with -type f matches only files. -size +100M means larger than 100 megabytes. 2>/dev/null suppresses permission denied errors. The -exec flag runs ls -lh on each result to show human-readable sizes.

Q2: "How would you check which port a service is running on?"

Why they ask: Tests knowledge of network tools, service management, and troubleshooting.

Show Answer 
# Method 1: ss (modern, preferred)
$ sudo ss -tulnp | grep nginx
tcp  LISTEN 0 511 0.0.0.0:80  0.0.0.0:* users:(("nginx",pid=2200,fd=6))
tcp  LISTEN 0 511 0.0.0.0:443 0.0.0.0:* users:(("nginx",pid=2200,fd=7))

# Method 2: lsof
$ sudo lsof -i -P -n | grep nginx
nginx  2200 root  6u IPv4 12345 0t0 TCP *:80 (LISTEN)
nginx  2200 root  7u IPv4 12346 0t0 TCP *:443 (LISTEN)

# Method 3: Check the service configuration
$ grep -r "listen" /etc/nginx/
/etc/nginx/sites-enabled/default:    listen 80;
/etc/nginx/sites-enabled/default:    listen 443 ssl;

Explanation: ss -tulnp shows all listening TCP/UDP ports with process names. lsof -i lists open network files. You can also check the service configuration files directly.

Q3: "How would you find which process is consuming the most memory?"

Why they ask: Tests process management and troubleshooting slow systems.

Show Answer 
# Method 1: ps sorted by memory
$ ps aux --sort=-%mem | head -10
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
mysql    12345 15.2 25.5 4096000 392000 ?      Ssl  Mar01  480:00 /usr/sbin/mysqld
...

# Method 2: top (interactive, press M to sort by memory)
$ top -o %MEM

# Method 3: One-liner showing top 5 memory consumers
$ ps -eo pid,user,%mem,%cpu,cmd --sort=-%mem | head -6

Explanation: ps aux --sort=-%mem lists all processes sorted by memory usage (highest first). The %MEM column shows the percentage of total RAM used. RSS (Resident Set Size) shows the actual memory in kilobytes.

Q4: "Explain the difference between hard and soft links."

Why they ask: Tests understanding of the Linux filesystem, inodes, and how files are stored.

Show Answer 
# Create a test file
$ echo "Hello" > original.txt

# Create a hard link
$ ln original.txt hard_link.txt

# Create a soft (symbolic) link
$ ln -s original.txt soft_link.txt

# Check inodes
$ ls -li original.txt hard_link.txt soft_link.txt
131074 -rw-r--r-- 2 user user 6 Mar 31 10:00 original.txt
131074 -rw-r--r-- 2 user user 6 Mar 31 10:00 hard_link.txt
131075 lrwxrwxrwx 1 user user 12 Mar 31 10:00 soft_link.txt -> original.txt

Key differences:

Feature Hard Link Soft (Symbolic) Link
Inode Same inode as original Different inode
If original deleted Data still accessible Link is broken (dangling)
Cross filesystem No Yes
Link to directories No (usually) Yes
File size Same as original Size of the path string

Q5: "What does chmod 755 mean?"

Why they ask: Tests understanding of the Linux permission system.

Show Answer 
# chmod 755 means:
# 7 = owner:  rwx (read + write + execute) = 4+2+1
# 5 = group:  r-x (read + execute)         = 4+0+1
# 5 = others: r-x (read + execute)         = 4+0+1

$ chmod 755 script.sh
$ ls -l script.sh
-rwxr-xr-x 1 user user 1234 Mar 31 10:00 script.sh

Permission values:

  • 4 = read (r)
  • 2 = write (w)
  • 1 = execute (x)
  • 0 = no permission (-)

Common combinations:

  • 755 = directories, executables (owner full, others read/execute)
  • 644 = regular files (owner read/write, others read only)
  • 600 = private files like SSH keys (owner read/write only)
  • 700 = private directories (owner only)
  • 777 = everyone can do everything (almost never appropriate)

Q6: "How would you search for a string across all files in a directory?"

Why they ask: Tests grep knowledge, which is essential for log analysis and code searching.

Show Answer 
# Recursive grep with line numbers
$ grep -rn "database_password" /etc/
/etc/myapp/config.yaml:15:  database_password: s3cret

# Case-insensitive search
$ grep -rni "error" /var/log/

# Only show filenames (not content)
$ grep -rl "TODO" src/
src/routes/auth.js
src/utils/helpers.js

# Search for a pattern (regex)
$ grep -rn "password.*=.*['\"]" /etc/ 2>/dev/null

# Exclude certain directories (e.g., node_modules, .git)
$ grep -rn "function" --exclude-dir={node_modules,.git} src/

# Search only specific file types
$ grep -rn "import" --include="*.py" src/

Explanation: grep -rn is the most commonly used form: -r for recursive, -n for line numbers. Add -i for case-insensitive, -l for filenames only, --include/--exclude for filtering file types.

Q7: "How would you find which user has the most running processes?"

Why they ask: Tests process management and text processing pipeline skills.

Show Answer 
$ ps -eo user --no-headers | sort | uniq -c | sort -rn | head -10
     85 root
     23 www-data
     12 mysql
      8 user
      3 syslog

Pipeline explained:

  1. ps -eo user --no-headers — list only the user column for every process
  2. sort — sort alphabetically (required for uniq)
  3. uniq -c — count consecutive identical lines
  4. sort -rn — sort numerically, highest first
  5. head -10 — show top 10

Q8: "How would you check if a remote server is reachable and which ports are open?"

Why they ask: Tests networking and connectivity troubleshooting skills.

Show Answer 
# Step 1: Check basic connectivity
$ ping -c 3 server.example.com
PING server.example.com (198.51.100.50) 56(84) bytes of data.
64 bytes from 198.51.100.50: icmp_seq=1 ttl=64 time=0.5 ms

# Step 2: Check specific ports
$ nc -zv server.example.com 22      # SSH
Connection to server.example.com 22 port [tcp/ssh] succeeded!

$ nc -zv server.example.com 80      # HTTP
Connection to server.example.com 80 port [tcp/http] succeeded!

$ nc -zv server.example.com 3306    # MySQL
nc: connect to server.example.com port 3306 (tcp) failed: Connection refused

# Step 3: Scan a range of ports (if nmap is available)
$ nmap -p 1-1024 server.example.com
PORT    STATE SERVICE
22/tcp  open  ssh
80/tcp  open  http
443/tcp open  https

# Step 4: Check DNS resolution
$ dig server.example.com +short
198.51.100.50

# Step 5: Trace the route
$ traceroute server.example.com

Approach: Start with ping (is it reachable?), then test specific ports with nc, optionally scan with nmap, and check DNS if name resolution fails.

Q9: "How would you troubleshoot a full disk?"

Why they ask: Tests real-world incident response and systematic troubleshooting.

Show Answer 
# Step 1: Confirm the problem
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       500G  495G  0    100% /

# Step 2: Find the biggest directories
$ sudo du -h --max-depth=1 / 2>/dev/null | sort -rh | head -10
495G    /
300G    /var
100G    /home
50G     /opt

# Step 3: Drill down into the culprit
$ sudo du -h --max-depth=1 /var | sort -rh | head -10
300G    /var
280G    /var/log

# Step 4: Find the specific large files
$ sudo find /var/log -type f -size +1G -exec ls -lh {} \;
-rw-r--r-- 1 root root 250G Mar 31 14:00 /var/log/app-debug.log

# Step 5: Quick fixes
$ sudo truncate -s 0 /var/log/app-debug.log   # Empty the log file
$ sudo apt clean                                # Clear package cache
$ sudo journalctl --vacuum-size=500M            # Trim journal logs
$ sudo find /tmp -mtime +7 -delete              # Clear old temp files

# Step 6: Check for deleted files still held open
$ sudo lsof +L1
# Shows files that are deleted but still open by a process
# Restarting that process will free the space

Key insight for interviews: Mention lsof +L1. This shows deleted files still held open by processes. The disk space is not freed until the process releases the file handle. This is a common gotcha that impresses interviewers.

Q10: "What is the difference between a process and a thread?"

Why they ask: Tests fundamental operating system knowledge.

Show Answer

Process:

  • An independent program in execution with its own memory space, file descriptors, and PID.
  • Processes are isolated from each other. One crashing process does not affect another.
  • Communication between processes requires IPC (Inter-Process Communication): pipes, sockets, shared memory.
  • Creating a process (fork) is relatively expensive.

Thread:

  • A lightweight unit of execution within a process. Threads share the same memory space and file descriptors.
  • Threads can communicate by reading/writing shared memory directly (but need synchronization).
  • One thread crashing can bring down the entire process.
  • Creating a thread is cheaper than creating a process.
# View threads for a specific process
$ ps -T -p $(pidof mysqld) | head -10

Interview Preparation Tips

How to stand out in a Linux interview

Follow these tips to make a strong impression:

  1. Explain your thought process. Do not just give the command. Say "First I would check X because... then I would look at Y to narrow it down..."
  2. Know multiple methods. For most tasks, there are 2-3 ways to do it. Showing alternatives demonstrates deeper knowledge.
  3. Mention safety precautions. When asked about deleting or modifying, mention backups, dry runs, and double-checking first.
  4. Know the modern tools. Use ss instead of netstat, ip instead of ifconfig, journalctl instead of just /var/log.
  5. Practice on a real system. Spin up a virtual machine or use a cloud instance. Type the commands yourself. Reading about them is not enough.
  6. Know troubleshooting patterns. Most problems follow: check symptoms, identify the resource (CPU, memory, disk, network), find the root cause, fix it, verify the fix.

Troubleshooting Framework

When asked "How would you troubleshoot X?", follow this systematic approach:

  1. Reproduce / confirm the problem: "Can you describe the symptoms? When did it start?"
  2. Check system resources: uptime, free -h, df -h, top
  3. Check logs: journalctl -u service -n 50, tail /var/log/syslog
  4. Check the service: systemctl status service
  5. Check the network: ss -tulnp, ping, nc -zv
  6. Identify the root cause and fix it
  7. Verify the fix and document what happened
