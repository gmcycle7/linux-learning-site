Glossary of Linux Terms

An alphabetical reference of Linux terminology, jargon, and abbreviations. If you encounter an unfamiliar term anywhere in this guide, look it up here.

Tip

Use your browser's find feature (Ctrl+F) to quickly jump to any term on this page.

A

Alias

A custom shortcut for a command or series of commands, defined with the alias built-in. For example, alias ll='ls -la' lets you type ll instead of the full command. Aliases are typically defined in ~/.bashrc or ~/.zshrc to make them permanent.

Argument

A value passed to a command that tells it what to act on. In cp file.txt backup/, the arguments are file.txt and backup/. Arguments are different from flags/options, which modify the command's behavior.

Absolute Path

A file path that starts from the root directory / and specifies the complete location of a file, such as /home/alex/documents/notes.txt. Absolute paths work regardless of your current working directory. Compare with Relative Path.

B

Bash (Bourne Again SHell)

The most common shell on Linux systems. Bash interprets your commands, supports scripting with variables, loops, and conditionals, and reads configuration from files like ~/.bashrc. It is the default shell on most Linux distributions.

Binary

An executable file compiled from source code into machine-readable format. Binaries are stored in directories like /usr/bin and /usr/local/bin. The term is also used to distinguish compiled programs from human-readable text files and scripts.

Boot

The process of starting up a computer. During boot, the BIOS/UEFI loads the bootloader (like GRUB), which loads the Linux kernel, which then starts the init system (systemd), which starts all configured services and presents you with a login prompt.

Built-in (Shell Built-in)

A command that is part of the shell itself rather than a separate program on disk. Examples include cd, echo, export, alias, and source. Built-ins execute faster because the shell does not need to create a new process. Check whether a command is a built-in with type command.

C

CLI (Command-Line Interface)

A text-based interface where you interact with the computer by typing commands. The opposite of a GUI. The Linux CLI is accessed through a terminal emulator and uses a shell (like Bash) to interpret commands.

Command

An instruction given to the shell to perform a task. A command can be a built-in shell feature (like cd), an external program (like ls), or a script. Commands can take flags and arguments to modify their behavior.

Configuration File (Config File)

A text file that stores settings for a program or the system. On Linux, config files are often plain text and found in /etc/ (system-wide) or ~/ as dotfiles (per-user). Examples include /etc/ssh/sshd_config and ~/.bashrc.

Cron

A time-based job scheduler that runs commands or scripts at specified intervals (every minute, every day, etc.). Cron jobs are configured using crontab -e. The cron daemon runs in the background and checks the schedule every minute.

Current Working Directory (CWD)

The directory you are currently "in" within the shell. Commands like ls operate on the CWD by default. Check it with pwd and change it with cd. Represented by . (a single dot) in paths.

D

Dotfile

A file or directory whose name starts with a dot (.), making it hidden from normal ls output. Dotfiles are used for user configuration: .bashrc, .ssh/, .gitconfig, etc. Use ls -a to see them.

Daemon

A background process that runs continuously, providing services to other programs or the system. Daemons typically start at boot and have names ending in d (like sshd, httpd, crond). They have no direct user interface.

Directory

The Linux equivalent of a folder. Directories contain files and other directories, forming the filesystem hierarchy. The root directory is /, and every path on the system starts from there.

Distribution (Distro)

A complete operating system built around the Linux kernel, packaged with a specific set of software, package manager, and configuration. Examples include Ubuntu, Fedora, Debian, Arch Linux, and CentOS. Each distro targets different use cases and user preferences.

E

Environment Variable

A named value stored in the shell's environment that affects how processes behave. Important examples include PATH (where to find commands), HOME (your home directory), and USER (your username). Set with export VAR=value and view with echo $VAR or env.

Executable

A file that can be run as a program. On Linux, a file is executable if it has the execute permission bit set (chmod +x). Executables can be compiled binaries or text scripts with a shebang line.

Exit Code (Return Code)

A numeric value returned by a command when it finishes. An exit code of 0 means success; any non-zero value indicates an error. Check the most recent exit code with echo $?. Exit codes are used in scripts for conditional logic (if command; then ...).

F

File Descriptor

A number that the kernel assigns to an open file, socket, or pipe within a process. The three standard file descriptors are: 0 (stdin), 1 (stdout), and 2 (stderr). Redirection uses these numbers: 2>/dev/null sends stderr to nowhere.

Filesystem

The method and structure used to organize files on a storage device. Common Linux filesystems include ext4, XFS, and Btrfs. The term also refers to the overall directory hierarchy starting from / (the Filesystem Hierarchy Standard).

Flag (Option)

A modifier passed to a command that changes its behavior, usually prefixed with - (short form) or -- (long form). For example, ls -l uses the -l flag for long format. Flags can often be combined: ls -la is the same as ls -l -a.

Fork

When a running process creates an exact copy of itself. The original is the parent process and the copy is the child. Forking is the standard way Linux creates new processes. The child can then replace itself with a different program using exec.

G

Glob (Globbing)

A pattern-matching syntax used by the shell to expand filenames. Common glob characters: * matches any number of characters, ? matches exactly one character, [abc] matches any one of the listed characters. For example, *.txt matches all files ending in .txt.

GNU

A recursive acronym for "GNU's Not Unix." The GNU project, started by Richard Stallman in 1983, created free replacements for Unix tools (gcc, coreutils, bash, etc.). Most "Linux" systems are technically GNU/Linux: the Linux kernel combined with GNU userland tools.

grep

A command that searches for text patterns in files or input. The name comes from the ed editor command g/re/p (globally search for a regular expression and print). It is one of the most frequently used Linux commands.

GUI (Graphical User Interface)

A visual interface with windows, buttons, icons, and a mouse pointer. Linux desktop environments like GNOME, KDE, and XFCE provide GUIs. Servers typically run without a GUI to save resources.

GID (Group ID)

A unique numeric identifier for a group. Every file and process is associated with a GID in addition to a UID. Users can belong to multiple groups, gaining the file permissions of each. Check your groups with id or groups.

H

Home Directory

Each user's personal directory, typically located at /home/username. Represented by the tilde ~ shortcut. Your home directory contains your personal files, configuration files (dotfiles), and is where your shell session starts by default.

Hard Link

A directory entry that points directly to a file's inode (its actual data on disk). Multiple hard links to the same file share the same data; deleting one link does not delete the data until all links are removed. Created with ln file link (without -s). Hard links cannot cross filesystem boundaries or link to directories.

I

Inode

A data structure on the filesystem that stores metadata about a file: permissions, owner, size, timestamps, and pointers to the actual data blocks. Every file has an inode, identified by an inode number. The filename is just a human-readable label pointing to an inode.

Init System

The first process started by the Linux kernel after booting (PID 1). It is responsible for starting all other system services and processes. Modern Linux systems use systemd as their init system. Older systems used SysVinit or Upstart.

J

Job

A process or group of processes started from the shell. Jobs can be in the foreground (receiving your keyboard input) or background (running while you type other commands). Manage jobs with jobs, bg, fg, and Ctrl+Z.

K

Kernel

The core of the operating system that manages hardware, memory, processes, and system calls. The Linux kernel was created by Linus Torvalds in 1991. It sits between the hardware and user-space applications, handling all low-level operations. Check your kernel version with uname -r.

L

Library

A collection of pre-compiled code that programs can use to perform common tasks without rewriting the code themselves. Shared libraries (files ending in .so) are loaded at runtime and shared between programs to save memory and disk space.

Link

A filesystem entry that points to another file or directory. Linux supports two types: hard links (direct pointers to an inode) and symbolic links (symlinks) (pointers to a file path). See Hard Link and Symlink.

Log

A file that records events, errors, and activity. System logs are typically stored in /var/log/. Important log files include syslog (general system messages), auth.log (authentication events), and kern.log (kernel messages). View logs with less, tail -f, or journalctl.

Loop Device

A pseudo-device that makes a file accessible as a block device (like a disk). This lets you mount disk images (like ISO files) as if they were physical drives: mount -o loop image.iso /mnt.

M

Mount

To attach a filesystem (from a disk, partition, USB drive, or network share) to a directory in the filesystem tree, making its contents accessible. The mount command performs this operation. The directory where a filesystem is attached is called the mount point.

Man Page (Manual Page)

Built-in documentation for commands, system calls, and configuration files. Access with man command. Man pages are organized into sections (1 for user commands, 5 for file formats, 8 for admin commands). Navigate like less: / to search, q to quit.

N

Namespace

A kernel feature that isolates system resources for groups of processes, making each group think it has its own instance of that resource. Namespaces are the foundation of container technologies like Docker. Types include PID, network, mount, and user namespaces.

O

Option

See Flag. The terms "option" and "flag" are used interchangeably in Linux documentation. Options modify how a command behaves.

P

Pager

A program that displays text one screenful at a time. The most common pager is less. Pagers are automatically used by commands like man and git log. The default pager is set by the PAGER environment variable.

Package

A bundle of software files (binaries, libraries, configuration, documentation) that can be installed, updated, and removed as a unit. Packages are managed by package managers like apt (Debian/Ubuntu), dnf (Fedora), or pacman (Arch). Package formats include .deb and .rpm.

Partition

A logical division of a physical disk. Each partition acts like a separate disk and can hold its own filesystem. Common partitions on a Linux system include / (root), /boot, /home, and swap. View partitions with lsblk or fdisk -l.

PATH

An environment variable that contains a colon-separated list of directories where the shell searches for executable commands. When you type ls, the shell checks each directory in PATH until it finds an executable named ls. View with echo $PATH.

PID (Process ID)

A unique numeric identifier assigned to every running process by the kernel. PID 1 is always the init system. Use ps or top to see PIDs. You need a process's PID to send it signals with kill.

Pipe

A mechanism that connects the output (stdout) of one command to the input (stdin) of another, using the | symbol. Pipes let you chain commands together: cat file | grep error | wc -l counts lines containing "error".

Port

A numbered endpoint for network communication. Ports range from 0 to 65535. Well-known ports include 22 (SSH), 80 (HTTP), 443 (HTTPS), and 3306 (MySQL). Use ss -tulnp to see which ports are in use on your system.

Process

A running instance of a program. Each process has a PID, its own memory space, and a state (running, sleeping, stopped, zombie). The kernel manages all processes and allocates CPU time. View processes with ps or top.

Prompt

The text displayed by the shell to indicate it is ready for your input, typically showing the username, hostname, and current directory. A common format is alex@server:~$. The $ indicates a normal user; # indicates root. Customized via the PS1 variable.

R

Redirect (Redirection)

Changing where a command's input comes from or output goes to. > sends stdout to a file (overwrites), >> appends, < reads input from a file, 2> redirects stderr. Example: ls > files.txt saves the file list to a file instead of showing it on screen.

Relative Path

A file path specified relative to the current working directory, without starting from /. Examples: ./script.sh, ../config/, documents/notes.txt. The path depends on where you currently are. Compare with Absolute Path.

Regex (Regular Expression)

A pattern language for matching text. Used by grep, sed, awk, and many other tools. Common elements: . matches any character, * matches zero or more of the previous character, ^ matches start of line, $ matches end of line, [abc] matches a character class.

Repository (Repo)

A remote server (or collection of servers) that hosts software packages. When you run apt update, you are downloading the latest package list from your configured repositories. You can also add third-party repositories for additional software.

Root (User)

The superuser account with UID 0 that has unrestricted access to the entire system. Root can read, write, and execute any file, kill any process, and modify any setting. Use sudo to run individual commands as root instead of logging in as root directly.

Root Directory

The top-level directory in the Linux filesystem hierarchy, represented by /. Every file and directory on the system is contained under /. Not to be confused with the root user's home directory, which is /root.

S

Script

A text file containing a sequence of commands that the shell executes in order. Shell scripts typically start with a shebang line (#!/bin/bash) and have the execute permission set. Scripts automate repetitive tasks and can include variables, loops, conditionals, and functions.

Shell

A program that interprets commands typed by the user and communicates with the kernel. The shell reads your input, executes commands, and displays output. Common shells include Bash, Zsh, Fish, and Dash. Check your current shell with echo $SHELL.

Shebang

The character sequence #! at the very beginning of a script file, followed by the path to the interpreter that should run it. For example, #!/bin/bash tells the system to use Bash, and #!/usr/bin/env python3 tells it to use Python 3.

Signal

A software notification sent to a process. Common signals include SIGTERM (15, polite shutdown request), SIGKILL (9, forced termination), SIGINT (2, interrupt from Ctrl+C), and SIGHUP (1, terminal hangup). Send signals with kill.

Socket

An endpoint for network communication between two processes, either on the same machine (Unix socket) or across a network (TCP/UDP socket). Sockets are identified by an IP address and port number. View active sockets with ss.

SSH (Secure Shell)

A cryptographic network protocol for secure remote login, command execution, and file transfer. SSH encrypts all traffic between client and server. The ssh command connects to remote machines; scp and sftp transfer files over SSH.

stdin (Standard Input)

The default input stream for a process, file descriptor 0. By default, stdin comes from the keyboard. It can be redirected from a file with < or piped from another command with |.

stdout (Standard Output)

The default output stream for a process, file descriptor 1. By default, stdout goes to the terminal screen. It can be redirected to a file with > or piped to another command with |.

stderr (Standard Error)

The output stream for error messages, file descriptor 2. Stderr is separate from stdout so that error messages are not mixed into normal output. Redirect stderr with 2> or combine it with stdout using 2>&1.

sudo

A command that lets permitted users run commands as the superuser (root) or another user. Instead of logging in as root, you prefix commands with sudo: sudo apt update. Configuration is in /etc/sudoers.

Superuser

See Root (User). The superuser has unlimited privileges on the system. The superuser account has UID 0.

Swap

A portion of disk space used as an extension of RAM. When physical memory is full, the kernel moves less-used data to swap space. Swap can be a dedicated partition or a swap file. Check swap usage with free -h or swapon --show.

Symlink (Symbolic Link / Soft Link)

A special file that points to another file or directory by its path name. Created with ln -s target linkname. Unlike hard links, symlinks can point across filesystems and to directories. If the target is deleted, the symlink becomes a "dangling" (broken) link.

T

Terminal (Terminal Emulator)

A program that provides a text-based interface to the shell. Modern terminal emulators (like GNOME Terminal, Konsole, Alacritty, or Windows Terminal for WSL) emulate the behavior of old hardware terminals. The terminal displays the shell prompt and renders command output.

TTY (Teletypewriter)

Originally a physical terminal device. In modern Linux, TTY refers to virtual consoles accessible with Ctrl+Alt+F1 through F6. The term is also used generically for any terminal session. Check your current TTY with tty or who.

Tarball

A colloquial name for a .tar archive file, often compressed (e.g., .tar.gz, .tar.xz). Tarballs are the standard way to distribute source code and bundle files on Linux. Created and extracted with the tar command.

U

UID (User ID)

A unique numeric identifier assigned to each user account. Root always has UID 0. Regular users typically start at UID 1000. The system uses UIDs (not usernames) internally for permission checks. Check yours with id.

umask

A value that determines the default permissions for newly created files and directories. The umask is subtracted from the maximum permissions (666 for files, 777 for directories). A common umask of 022 results in files with 644 and directories with 755. Check with the umask command.

V

Variable

A named container that stores a value in the shell. Shell variables are set with NAME=value (no spaces around =) and accessed with $NAME. Variables can store strings, numbers, or command output. Environment variables (set with export) are passed to child processes.

W

Wildcard

Special characters used in file name patterns that the shell expands before running a command. The main wildcards are * (match any number of characters), ? (match exactly one character), and [...] (match one character from a set). See also Glob.

Working Directory

See Current Working Directory. The directory you are currently "in" within the shell session.

Z

Zombie Process

A process that has finished executing but still has an entry in the process table because its parent has not yet read its exit status. Zombies consume no resources except a PID slot. They appear in ps output with a state of Z. They are cleaned up when the parent reads the exit code or when the parent process ends.

Zsh (Z Shell)

An advanced shell that is compatible with Bash but adds features like better autocompletion, spelling correction, themeable prompts, and plugin support (via frameworks like Oh My Zsh). Zsh is the default shell on macOS and is increasingly popular on Linux.

Missing a term?

This glossary covers the terms used throughout this guide. As you learn more about Linux, you will encounter additional concepts. The man command and online resources like the Arch Wiki and Linux man-pages project are excellent references for deeper exploration.
